# v1.1.0

## 修了三个会让「更新」这件事出错的毛病

这一版没有新功能，全部是可靠性修复。

### 1. 更新失败时，回滚可能根本没发生（Windows）

覆盖安装区时如果某个文件被占用，程序会**逐文件回滚**到更新前。但这条回滚在
Windows PowerShell 5.1 上会被那个占用文件本身打断：异常冲出了异常处理，后面的还原、
清理、复检全都不跑，安装区停在半新半旧——而屏幕上还写着「已恢复原状」。

现在每个文件的还原都单独兜底，一个文件失败不会拖垮其余；真的没还原成功时，
它会如实说出是哪几个文件。

### 2. 下载失败被误报成「这个版本没有安装包」（macOS）

`curl -f` 对**任何** HTTP 错误都返回同一个退出码——404、403 限流、429、500、502 全都一样。
旧代码把那个退出码当成「没有这个文件」，于是限流会被说成「缺包」，还顺带掐掉了本该有的
直连重试。现在按真实状态码判断，只有 404/410 才算缺包，其余按网络故障重试。

### 3. 检查更新多了一条兜底路径

问「最新版是几版」现在有两条路：官方 API（语义明确，但匿名配额只有 60 次/小时）和
网页重定向（不吃配额，但在受限网络里容易整段超时）。**API 优先、网页兜底**——
API 被限流时，网页这条路能救回来。

## 另外

- 回归用例里修掉了一条**恒真**的断言：它看着在测「跳过未启用的更新源」，实际上无论代码
  对错都会通过。现在它真的会失败。
- 取版本的路径也带上了形态校验：某些平台在仓库改名时会先跳转到新地址，直接取地址尾段
  会把字面量当成版本号——现在这种跳转会被识别并忽略。

## 升级方式

打开菜单选 `5 检查更新`。
