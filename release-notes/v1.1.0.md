# v1.1.0

终端窗口不用再重开了——**已经开着的窗口，敲一下回车就跟着代理状态走**。

## 这次解决什么

以前装好之后，只有新打开的终端才认得代理。已经开着的窗口一直是旧状态，必须关掉重开。原因是
操作系统的硬规则：环境变量只在程序启动那一刻复制一次，之后父进程怎么改都影响不到已经在跑的
程序。

这一版换了做法：每次回到提示符、准备执行下一条命令之前，重新读一遍当前状态。于是：

- 翻墙软件开着 → 敲回车，这个窗口就用上代理
- 翻墙软件关了 → 敲回车，这个窗口恢复直连
- 正在跑的长命令（比如 `dsh web`、`vim`、一次长编译）**完全不受影响**，跑完回到提示符才同步

## 想手动接管也行

默认是"全自动跟随"，但你可以让某个窗口不跟随：

| 你想做什么 | 怎么做 |
| --- | --- |
| 这个窗口固定直连（翻墙开着也不用代理） | `export ENVPROXY_TERM=off`（Windows：`$env:ENVPROXY_TERM='off'`） |
| 恢复自动跟随 | `unset ENVPROXY_TERM`（Windows：`Remove-Item Env:ENVPROXY_TERM`） |
| 这个窗口用别的代理 | 直接 `export HTTPS_PROXY=...`——你自己设的值我们永远不动 |

第三条的判据是**值是否等于我们上次写下的那个**，不是"看起来像不像本机地址"。所以你自己跑的
本地 mitmproxy（`127.0.0.1:8080`）、公司代理、socks5 地址，一律不会被我们误删或覆盖。

## 和你自己的设置不打架

- 只清"确实是我们写的值"。判据记在状态文件里，逐项比对。
- 钩子里的函数永不输出、永不返回非零。这一点很关键：zsh 的 `precmd` 钩子只要有一环返回非零，
  后面的钩子（你的主题、补全）全都不执行，提示符会坏掉。
- 卸载只摘掉我们那一段标记块，你的 `.zshrc`、`$PROFILE` 里其余内容一个字节都不动。标记不成对时
  更是连碰都不碰。

## 性能

每次回车多花约 0.3 毫秒。不用 `launchctl getenv` 那类做法，因为每调用一次要起一个进程，
8 个变量加起来够让人感觉到卡顿——这是实测出来的差别，不是估的。

## 兼容性

- Windows：PowerShell 5.1 及以上（系统自带即可）
- macOS：zsh 与 bash 3.2 都支持（系统自带版本）

## 顺带修掉的

- 状态文件在 `set -u` / `nounset` 环境下会报 "unbound variable" 的问题。有些人的 shell 配置里
  开着这个选项，之前会看到报错。
- 升级后终端同步脚本没跟着更新，导致改了逻辑却送不到你手里。现在自愈时会比对内容。
