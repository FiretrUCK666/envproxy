# v2.1.2

这一版修三个 bug。头一个**很严重**：它会删掉你自己的环境变量。

## 严重：跑一次自检，你的用户环境变量可能被整个删掉

如果你跑过 `tests\test-win-pure.ps1`（或者让 AI 跑过），可能会发现终端里
`PATH`、`TEMP` 这些莫名其妙的失效，或者后台程序反复报「变量被人改坏了」。

**那不是一个 bug 的两个症状，是同一个 bug 的两端。**

事情是这样的：自检为了不碰你真实的环境变量，会建一批临时的注册表键当"沙箱"，
跑完再删掉。问题出在有一个用例文件（`tests/cases/readme.ps1`）在**跑到一半**
就把沙箱拆了、把变量指回了真实位置。而它后面还有用例要跑。

等到全部跑完、外层去清沙箱时，它读到的是**真实路径**——于是执行了
`Remove-Item HKCU:\Environment -Recurse -Force`，把当前用户整个环境变量键
删空。`PATH`、`TEMP` 连同代理变量一起没了。

后台监控每 30 轮自愈一次，发现代理变量消失就重新写回，于是日志里反复出现
「变量被人改坏了」——**症状离根因太远，一直没人往测试上想**。

现在分两处修：

- 用例文件不再碰沙箱的拆装，只留一个地方做（外层末尾）。
- 外层加了一道护栏：删之前先确认"这四个键确实是本次沙箱"。变量被改坏时
  它一个字节都不删，并且明确报出来——而不是安静地删掉别人的东西。

验证过：修复前每跑一次自检新增一条「变量被人改坏了」；修复后跑完 0 新增。

## 探测可能卡十几秒

Windows 侧判断"本机某个端口还在不在"时，连上之后要拿这条连接做一次代理握手。
原来用的是同步的连接调用，配了两个超时参数——但那两个参数只管**连上之后**
的读写，管不了连接本身。

所以当某个本机端口处于半开状态（不回拒绝包，也不回同意包）时，这一连就会
一直等下去，直到系统级的 TCP 超时才放手。

实测对照：连一个不可达地址，旧写法 **21 秒**，新写法 **0.3 秒**，差 62 倍。
而监控每轮都要探测，卡住的直接后果是状态翻转明显变慢，屏幕上看不出异常。

现在改成异步连接加自己卡时限，与同一个文件里另一处判活用的是同一套写法。

## 同一个程序在两个平台显示成不同的客户端

客户端识别表里，`stash` 和 `quantumult` 在 Windows 侧被归到 Clash 系，
在 macOS 侧被归到 Surge 系。而 Surge 那条的名字上明明写着「Surge / Stash」。

后果不是崩溃，是"同一个程序在 Mac 上叫这名、在 Windows 上叫那名"，而
门禁一直全绿——因为它只比对两边的进程名加起来是不是同一批（两边都有 stash，
所以相等），**归属差异看不见**。

现在两侧统一归 Surge 系，并且门禁改成按条目逐行比对（名字、端口、进程名三项）。
故意改坏试过：门禁当场变红并指出是哪一条。

## 内部

- `doctor` 用例改全局落点后没有还原，补上 `finally`。当前它恰好排在最后，
  所以看不出问题；但那是执行顺序的巧合，不是契约。

## 升级

装过旧版本的，打开菜单选 **1 安装 / 修复** 即可。

**如果你怀疑自己的环境变量已经受损**：走一遍「1 安装 / 修复」会重新写回代理
变量；`PATH`、`TEMP` 这些系统变量如果被删了，需要手工补回或在系统设置里恢复。
新版本的自检不会再动它们。
