# v2.1.1

这一版是**修 bug**，没有新功能。修的都是那种「屏幕上看着一切正常、实际已经
出问题」的毛病——最值得升级的一类。

## macOS 侧：一个会让菜单崩掉的错

### 「网络救援」页面一打开就报错

macOS 上选「网络救援」，屏幕上会闪过一行 `clear_screen_safe: command not found`，
然后页面内容错乱。原因是这个函数被写在另一个函数的**里面**，只有那个函数被
调用过之后它才存在。而「网络救援」是第一个用它的地方，用的时候还没创建。

现在它被挪到文件顶层，谁先调用都能用。

## macOS 侧：卸载后桌面上留下删不掉的图标

### 卸载不清快捷方式

Windows 侧卸载时会问「那些程序图标留不留」，macOS 侧**根本没问，也没删**——
桌面上的图标留下来了，而它们指向的程序已经被卸载掉，双击没有任何反应。

更麻烦的是卸载完的检查也发现不了：它只检查运行时文件，不检查图标。

现在两侧行为一致：卸载时先问留不留（默认保留），说删就删干净，卸载后的
检查也会把图标算进去。

## macOS 侧：图标名里带着一串看不懂的乱码

### 桌面图标名后面的那串十六进制

给程序建图标时，为了区分「同一个程序的走代理版和直连版」，内部用一段
哈希值做身份。但那串哈希**直接印在了图标名上**，桌面上看到的是
`Antigravity_a3f9c1e2（翻墙）.app` 这种名字——用户完全没法照着念。

Windows 侧一直是干净的 `Antigravity（翻墙）.lnk`。

现在 macOS 侧也干净了：显示名读程序自己的名字，哈希只留在内部目录里。
真出现同名冲突时才退回带哈希的名字。

顺带修好了「确认页显示的图标名」和「实际建出来的图标名」不一致的问题——
以前确认页显示干净的、建出来带乱码，用户看到的和得到的不一样。

## 两侧：探测代理时会漏掉 IPv6

### 只试了 127.0.0.1

判断「本机有没有代理在跑」时，程序会去连本机的代理端口。但 macOS 侧的
一部分检查**写死了 `127.0.0.1`**，只试 IPv4。

如果有人的代理只绑了 IPv6 回环（`::1`），这台机器就会被判定成「没有代理」，
而且**不报任何错**。

现在两侧都按 `127.0.0.1` → `::1` 的顺序试。

### macOS 判定端口活着的方法会误判

macOS 侧判断「这个端口还在不在」用的是 `curl`。问题是 `curl` 会真的去建一条
隧道——连一个必然失败的地址，`curl` 返回非零，于是**活着的端口被判成死的**。

现在改用 shell 自带的 `/dev/tcp`，只连 TCP 不建隧道，与「浏览器代理修复」
那边用的是同一个判据。

## 内部整理

- Windows 侧「浏览器代理修复」里有一个写死的变量名，改成从变量表取
- Windows 侧一段永远不成立的条件判断（它读的字段根本不存在）——这段代码
  从来没执行过，删掉
- macOS 侧日志定位器的排序算法修好了：端口号 9 和 10 以前会排错顺序
- 定位器现在会先检查进程是否还活着，再比日志时间——以前可能选中一个
  已经退出的进程
- 删掉两个没人调用的 macOS 死函数、六个 Windows 空壳函数

## 文档

`AGENTS.md` 里补了「界面规矩」三条：横线宽度由标题算、退出提示按回到哪里
分档、用户看得到的名字里不许出现内部标识。这些规矩以前只写在代码注释里，
换个地方写新页面就容易忘。

## 升级

装过旧版本的，打开菜单选 **1 安装 / 修复** 即可。已开着的终端窗口里的代理
变量不受影响，不用重开。

**macOS 用户注意**：如果你之前卸载过、且桌面上留着点不动的图标，升级后可以从
桌面手动删掉它们——新版本管不到旧版本留下的东西。
