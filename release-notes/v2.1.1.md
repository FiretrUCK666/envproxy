# v2.1.1

这一版没有加新功能，改的是「它看到了什么」和「它怎么给你看」。核心只有一件事：**状态页说它自己看见的东西，而不是它能猜到的东西。**

## 你会直接看到的变化

**自定义端口终于能被认出来。** 这是一个会让人以为工具坏了的故障。你把翻墙软件的端口从 7078 改成 7099，代理明明在工作、终端也能正常上网，状态页却打「翻墙代理：未检测到（当前无翻墙代理在运行）」，而同一屏的「代理变量」那行写着「已注入 (http://127.0.0.1:7099)」。两行自相矛盾。

原因不在探测本身——7099 的监听、握手、真实连通三层全部通过。是**状态页和监控用了两套不同的判据**：状态页为了快，只扫「常见端口表 + 进程名」，而 7099 不在那张表里。现在状态页先直接验「变量里那个端口」（一个 TCP 连接，不到 100 毫秒），验得到就直接用；只有在验不到时才会去扫。慢一点换不说谎，这个取舍是值的。

**改端口后不用再等半分钟。** 上面那个 bug 还有第二个成因，更隐蔽：候选集签名区分不出「扫描深度」，于是全扫发现 7099、下一轮快扫看不见它，签名从 `7099` 变成空，被当成「集合变了」，缓存被清、判成直连，再下一轮全扫又「发现变化」。这个本该是强信号的机制，被自己的节流反复触发，恢复被钉在最多 10 轮约 27 秒。现在快扫不再覆盖全扫的签名，并且刚丢掉端口的那一刻会立刻深扫一次，不等节流。

**状态页的标签不再跟着状态变色。** 以前每行整行套一个颜色：状态好就整行绿，「代理变量」为空就整行灰，连「代理变量」这四个字本身也灰掉。而人扫一眼最先看到的恰恰是标签。现在标签固定一种颜色，只有冒号后面的内容按状态变——绿是正常、黄是要注意、灰是不用管。两侧一致。

**帮助里那些要敲的命令恢复成绿色。** 上一版有一个提交顺手把命令色从绿改成了青，和大标题、段标题同色，于是「哪一行能整行复制去跑」这个区分没了。现在命令是绿的，标题是青的。

**`~/.envproxy` 里剩下的东西会被如实说出来。** 卸载时如果那个文件夹里有不是本安装写的文件（典型情况：在 Git Bash 里跑过 macOS 版的 install，往 Windows 家目录写了 `proxy.env`、`owned.env`），以前要么不报、要么报成「没清干净，请手动删」。现在它单独说一句「这几样没有动，可能是你自己放的」，不再让人误以为卸载失败、更不会诱导人删掉不该删的东西。

## 修掉的「以为是好的，其实没有」

这轮有两个缺陷属于这一类，都出在测试自己身上。

**Windows 自检会写你真实的注册表。** 那两处用的是 `.NET` 的 `OpenSubKey` 加一份手抄的路径，没有跟着自检的沙箱走。跑一次自检，就会把它那 5 个值写进真实的 `HKCU\Software\EnvProxy\Owned`。在 CI 上是隐形的（全新机器没有那个键），在我这台机器上也隐形（真实端口恰好就是测试用的那个值）——但换一台端口不同的机器，已开窗口里的值就会从此「不是我们写的」，再也清不掉。现在两处都从子键声明派生，自检跑完还会把临时键删掉、把四个子键复原。

**更新失败的原因会被重试结果盖掉。** 失败要分六类报给你（连不上 / 配额用尽 / 对方故障 / 拿到的不像安装包 / 这版没提供 / 本机临时目录不可写），词表还有优先级——配额用尽排在本机故障之前，因为它更可行动。但「先走 API、失败换另一条路重试」这条路上，第二次的结果直接覆盖了第一次的原因，于是本该报「配额用尽」的场合报成了别的。这个缺陷在 v2.1.0 就已经在，两侧都有。

## 顺带修掉

- **回环地址不该走代理。** 更新时若要经代理取包，而目标本身就是本机地址，那一跳是多余的、还可能失败。现在跳过。两侧判据还各自实现了一套，大小写、`user:pw@` 前缀、`127.0.0.2` 这些写法结论不一致——已经统一，并用同一张 10 条的用例表钉住。
- **mac 上那个从不被调用的心跳。** `write_heartbeat` / `monitor_beat_alive` 三个函数一个调用点都没有，而两份 README 都把 `monitor.beat` 列成 mac 会生成的文件。函数和文档两处都删了——mac 判活靠 pid 文件 + `pgrep`，不需要心跳。
- **`mac/envproxy.sh` 在 Git Bash 里能跑。** 它会往你的家目录写 macOS 格式的运行时文件，而 Windows 卸载不认识它们。现在入口在非 macOS 上一律拒绝（只放行 `self-test` 和 `help`），这就是上面那个「`~/.envproxy` 里有别人的文件」的来源。
- **帮助第 3 条里手抄的 5 个变量名。** 加第 6 个代理变量时，这一处不在任何门禁里，漏改的后果正是「半代理」：cmd 用户照帮助清掉 5 个，第 6 个还留着。现在从变量表生成，数字也一起生成。
- **帮助第 7 条让人「附最后 20 行日志」却不给命令。** 补了两条能直接复制的（PowerShell 的 `Get-Content ... -Tail 20` 和 Git Bash 的 `tail -n 20`），都实测过能跑出内容。

## 一个说明

macOS 侧这轮做了同样的代码修改，也跑过自检（全部通过），但**没有在真机上验证**。Windows 上每个场景我都实测过：多开两个代理、单独关一个、快速反复启停十次、非标准端口、单次探测失败不误删变量。mac 只有自检覆盖。

## 升级

打开菜单选「检查更新」，或者：

```
# Windows
powershell -ExecutionPolicy Bypass -File win\envproxy.ps1 -Update

# macOS
bash mac/envproxy.sh update
```

已经装着的用户直接升即可，不需要先卸载。升级走的是同一套校验：先对 GitHub 公布的 sha256、再比包内 `VERSION`、再确认库清单齐全，任何一项不过就中止且现版一个字节不动。
