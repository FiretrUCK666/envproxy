## v1.5.0：变量只写规范拼写、判"断"改保守

### 修了什么

Windows 的环境变量名**大小写不敏感**：`HTTP_PROXY` 与 `http_proxy` 是同一个变量，
注册表里也只存得下一个。写入这两个拼写会互相覆盖，同时让运行期出现**同名两种拼写的重复
环境块**——任何按"大小写不敏感字典"建表的宿主（.NET 系）在读取时直接抛
`An item with the same key has already been added`，连 `Get-ChildItem Env:` 都枚举不出来，
而派生的子进程继续继承同一个块，**一个终端窗口里跑的软件会一起受影响**。

### 改成了什么

- **Windows 侧只写 5 个变量名**（`HTTP_PROXY/HTTPS_PROXY/ALL_PROXY/NO_PROXY/NODE_USE_ENV_PROXY`）。
  兼容面零损失：Windows 不分大小写，用任何拼写去取都拿到同一个值。
- **注入、删除、复查共用同一张表**（`$ProxyVarNames` + `Get-ProxyVarTable`），
  三者不可能漂移；删除后按名复查一遍，确保"按名之后确实一个都不剩"——无主残留正是
  "半代理"诡异行为的来源。
- **macOS 侧写 9 个**：`launchctl` 与环境块真大小写敏感，大小写各一份各有归属。
  这是平台语义差异，代码里以 `DIVERGE(Win)` / `DIVERGE(Mac)` 各自标注。
- **判"断"改成比判"通"保守**：连续 3 次探测失败才判"断"（按 15 秒节流约 45 秒），
  一次成功立即判"通"并清零计数。判"断"的代价是「删变量 + 全系统广播」，影响机器上每一个
  应用；误留代理变量的代价只是多等一会儿——两个代价不对称，判据就不许对称。
- **阈值具名化**：Windows `$NodeFailThreshold` / `$NodeCheckThrottleSec`，
  macOS `NODE_FAIL_THRESHOLD` / `NODE_CHECK_THROTTLE_SEC`，两侧都不再出现裸数字。

### 环境块不受影响的边界（重要）

进程环境块在进程创建时定型，之后改用户级变量**不会**修复已经存在的进程块。
因此升级后：**新开的终端/程序立刻干净**（由 explorer 拉起、读的是注册表），
而升级前就开着的终端及其子进程仍带着旧的重复块——把那个终端、以及从它启动的程序
整个关掉重开即可，**不需要注销**。
