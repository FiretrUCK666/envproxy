## v1.5.0：修掉 Windows 上的"大小写双写"——它会污染整个会话环境

### 根因

Windows 的环境变量名**大小写不敏感**：`HTTP_PROXY` 与 `http_proxy` 是同一个变量，
注册表里也只存得下一个。而旧版按 curl 惯例把 9 个名字（大小写各一份）都写一遍，实测后果有三：

- 注册表折叠成 1 个键，后写的那次覆盖先写的——"给两种拼写都留一份"在 Windows 上根本不存在，
  实际留下的是小写那次写的值，改一行顺序就会换行为；
- 运行期会留下**同名两种拼写的重复环境块**。任何按"大小写不敏感字典"建表的宿主（.NET 系）
  在读取时直接抛 `An item with the same key has already been added`——连
  `Get-ChildItem Env:` 都枚举不出来，而派生的子进程继续继承同一个块，
  **一个终端窗口里跑的软件会一起受影响**；
- 注入清单与删除清单两处各写一遍，天然会漂移（`NO_PROXY` 曾因此留下无主残留）。

### 改法（治本，不是压症状）

- **Windows 侧只写 5 个变量名**（`HTTP_PROXY/HTTPS_PROXY/ALL_PROXY/NO_PROXY/NODE_USE_ENV_PROXY`）。
  改名不改兼容面：Windows 不分大小写，用任何拼写去取都拿到同一个值，行为零损失。
- **注入与删除共用同一张表**（`Get-ProxyVarTable` + `$ProxyVarNames`），两者不可能再漂移；
  删除后按名自检一次，把历史版本写下的同名残余一并清掉。
- **macOS 侧维持 9 个**：`launchctl` 与环境块真大小写敏感，大小写各一份确实各有归属。
  这是平台语义差异，代码里以 `DIVERGE(Win)` / `DIVERGE(Mac)` 标注。

### 顺带修掉的状态横跳

监控日志实测：弱网下 90 分钟内状态翻转 12 次，半小时内 6 个完整来回，而当时代理端口正常监听、
握手与节点都通——翻转来自"探测打不通"被当成了"代理没了"。而每次翻转都会向全系统广播一次
环境变更，惊动机器上每一个应用。

- **判"断"改为比判"通"保守**：连续 3 次探测失败才判"断"（按 15 秒节流约 45 秒），
  一次成功立即判"通"并清零计数（抖动不累积）。判"断"的代价（删变量 + 全系统广播）
  远大于误留变量（多等一会儿），两个代价不对称，判据就不该对称。
- 阈值改为具名常量（Windows `$NodeFailThreshold` / `$NodeCheckThrottleSec`，
  macOS `NODE_FAIL_THRESHOLD` / `NODE_CHECK_THROTTLE_SEC`），两侧都不再出现裸数字。

### 已经中招的机器怎么恢复

畸形块只活在**修复前就存在的终端及其子进程**里，注册表本身是干净的：
把这些终端、以及从它们启动的程序（含终端里跑着的 GUI）整个关掉重开即可，**不需要注销**。
新开的终端由 explorer 拉起、直接读注册表，实测已是干净的单拼写环境。
