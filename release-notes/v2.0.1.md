# v2.0.1

这一版**没有新功能**，装上去和原来一样用。

它修的是 macOS 状态页「最近日志」那三行的两个显示问题，另外把一批「检查通过、但其实没在检查」的测试与门禁补成真的。

## 最重要的一条：macOS 上带表情符号的日志行会显示成乱码方块

**谁会遇到。** 在 macOS 上用这个工具、并且日志里出现表情符号（emoji）的人。

**发生了什么。** 状态页最下面那三行「最近日志」会按终端宽度截断。截断要按字符走，而那段代码推进的步长只认 1、2、3 字节三种情况——表情符号是 4 字节的，于是它被按 3 字节推进一步，剩下的 1 个字节被留给下一轮。结果截断点落在字符中间，输出的字节序列**不是合法的 UTF-8**，屏幕上就是一个乱码方块。

**怎么修的。** 补上 4 字节这一支。现在截断点永远落在字符边界上。

## 第二个：日志行最多会溢出一格，正好顶满终端宽度

**发生了什么。** 截断的预算是「最多多少格」，但补上去的省略号（`…`）自己也占一格，这一格没有算进预算。于是实际宽度是上限加一。一条 80 列的日志行拿到 78 格预算、输出 79 格，前面再加两格缩进就是 81 格——超过终端宽度，自动折行。

而状态页是按**绝对行号**逐行画的（每次只重写变了的那几行）。一旦某一行折行，它下面每一行的位置就都错开一格，屏幕上是整块内容往下串。

**怎么修的。** 与 Windows 侧同一判据：截到上限减一，最后补一个省略号。实测两边现在给出同一个宽度。

## 第三条：同一条日志行在 macOS 上要算 4 到 8 秒

**发生了什么。** 计算一段文字占几格的那个函数**每调用一次就起一个外部进程**（`od`，用来把字符转成十六进制）。而截断是逐字符调用它的，于是一条 80 列的中文日志行要起 34 到 65 次。本机实测一趟 4.3 到 8.1 秒。

你打开状态页看到的就是「卡住了」。而它只是三行日志。

**怎么修的。** 整行一次性转成十六进制，之后的解码全靠 shell 自己的算术，一个字符都不再起进程。同一条日志行从 34 次降到 2 次，耗时从 4372 毫秒降到 184 毫秒。

## 第四条：一个缓存从来没生效过

计算宽度的函数里有个「记住上一次算过的字符串」的缓存。但它只在**同一个进程**里才起作用，而所有调用点都在子 shell 里——子 shell 里做的赋值传不回来。实测连续三次算同一个字符串，缓存命中 0 次，`od` 照样起了三次。

删掉了。它留着只会让人以为「这里已经优化过了」。

## 第五条：ANSI 颜色序列被当成可见字符

终端会把 `ESC[36m` 这种序列当控制指令执行，屏幕上不占格子。macOS 侧算宽度时没剥掉它们，而 Windows 侧剥了。一条 34 格的彩色标题在 macOS 上被算成 51 格——于是「这一屏太宽了、画不下」的判断会误触发，白白降级成静态输出。

现在两侧剥除判据一致：带颜色和不带颜色算出来同一个宽度。

## 测试与门禁：把「检查通过」变成真的

这一版里四项检查被补成了真的。它们不影响你日常使用，但决定了「全绿」这两个字还算不算数。

**一条永远为真的断言。** 有一条断言写成了「某条件 **或者 真**」，无论代码怎样它都通过。真正管住那件事的是紧挨着的两条断言，这条等于什么都没测。删了。

**数调用次数时把注释也数进去了。** 有两条断言在数「这个清理函数被调了几次」。判据是全文搜索名字——而那个名字在两句解释性注释和一行函数定义里也出现。于是把**两个真实调用点全删掉**，命中数仍然够，断言照样绿。现在只数真正的调用，并扣掉定义那一行。反向验过：把两处调用注释掉，断言立刻红。

**把函数挪个文件，整份自测直接中止。** 有八处断言用「找到函数名 → 往后截一段」的方式取函数体，却没检查「找没找到」。找到时返回 -1，紧跟着的截取就抛异常；而测试文件开头把错误设成了「一遇错就停」。后果是把某个函数挪到别的文件（重构时很常见）会让**整个测试进程当场死在第 3000 行**，后面两百多条一条都不跑，屏幕上还看不出是「找不到函数」。

现在统一改用按花括号配对取函数体——找不到就返回空串，断言红、其余照跑。

**版本号检查会误伤系统版本。** 「README 里不许写死版本号」这条门禁原来用的是通用正则，凡是形如 `x.y.z` 的数字一律算违规。补一句「需要 macOS 14.0.1 以上」就红了，写个日期 `2026.10.29` 也红。现在只认本项目版本的两种写法（`EnvProxy 2.0.0`、`v3.1.4`），系统版本与日期不再触发。

## 另外：删掉了一个本地提交钩子

仓库里没有它，它住在 `.git/hooks/` 下——那个目录**永远不进版本库、永远不会被任何人看到**，所以它里面的中文注释坏成了问号也没人发现。

它检查的东西是正式门禁第三项的**更窄子集**：不查 `win/` 以外的 PowerShell 文件、不查 `.cmd` 的文件编码、不查 Git Bash 用的脚本。于是「钩子绿」和「CI 绿」含义不同——这是一种更危险的绿，因为它让人以为已经查过了。

项目自己的规矩是「同一判断只准有一处实现」。留着它就是第三处。删掉之后，本地检查的权威来源回到 `.github/workflows/check.yml` 一处，`CONTRIBUTING.md` 里写着本地怎么跑。

## 验证

- Windows 自检：PowerShell 7 与 PowerShell 5.1 **各 958 条断言全过**
- macOS 自检：全部通过，其中新增 6 条宽度与截断的断言
- 新增的断言都做了反向验证：故意改坏一次，确认它会红

这一版新增的宽度回归用例：

- `…`、`→`、`—` 各占一格，`中`、`Ａ` 各占两格（判据不能只看 UTF-8 字节数）
- 表情符号占两格，且截断时不会被劈开
- ANSI 颜色序列不占宽度
- 截断结果宽度不超过上限（1、2、5、6、10、20、40 各测一遍）
- 放得下时原样返回，一个字节都不动
- 截断不把 locale 泄漏给调用方

## 兼容性

没有不兼容改动。没有新增依赖。变量集合、注入判据、阈值、菜单编号、帮助内容都没动。

Windows 侧行为无变化——上面四条修的都是 macOS 侧，以及两侧共用的测试与门禁。
