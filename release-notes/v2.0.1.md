# v2.0.1

这一版修掉一个**会让人上不了网**的缺陷，另外把一批「屏幕上报成功、实际没做到」的地方改成如实报告。

没有新功能，没有不兼容改动，装上去和原来一样用。

## 最重要的一条：关掉翻墙软件后，代理变量可能永远清不掉

**谁会遇到。** 在装这个工具**之前**就已经设过代理变量的人——公司代理、以前用过的别的工具留下的值、手动设过 `HTTP_PROXY` 的机器，都算。

**发生了什么。** 关掉翻墙软件后，三个地址变量（`HTTP_PROXY` / `HTTPS_PROXY` / `ALL_PROXY`）继续指向一个已经没人接听的端口，而 `NO_PROXY` 和 `NODE_USE_ENV_PROXY` 反而被删掉了。结果是一套**半套变量**：连 `localhost` 都要走一个死掉的代理，`git`、`curl`、`npm` 全部超时失败——但屏幕上写的是「已删除代理变量，恢复直连」。

更麻烦的是它会自己复发：终端提示符每开一个新窗口都会重新读一次状态，读到那套变量还在，于是又注入一遍。

**根因。** 判断「这个变量是不是我们写的」原来问的是「安装前你有没有设过这个名字」，而不是「现在的值是不是我们写下的那个」。前一个问题一旦是肯定答案就永远是肯定答案，于是我们注入的值再也收不回来。

**怎么修的。** 改成先比对「归属记录」——我们自己写下的每个值都记了账，值对得上就一定是我们的。这条判据在这个文件里本来就有（还原快照、跳过快照都在用），只有清理那一条没走它。

**一个不受影响的情况。** 你自己起在本机的代理（mitmproxy、内网跳板）不会被误删：它和你记录里的地址不是同一个值，判据自然落到「这是使用者的」那一侧。

## 不再谎报成功

**记不下你原来的设置时，现在会说出来。** 安装时会把你原来的代理设置抄一份存起来，卸载时按它还原。这一步写失败原来完全静默——你卸载后发现自己原来的公司代理没了，而安装时屏幕上一切正常。现在会明确提示「没能记下你原来的代理设置，请先抄一份」。

**还原失败时不再销毁备份。** 卸载时如果写回失败（被安全软件或组策略拦住），原来仍然会删掉那份备份，等于**把你的原值和唯一副本一起销毁**，然后提示你「照上面列出的位置手动删」——数据已经没了，建议却指向再删一次。现在这一步失败就停手，备份留着，并告诉你怎么收尾。

**macOS 关代理时写不进文件也说了。** 那一刻 `proxy.env` 还是上一份内容，已开着的窗口每次敲回车会把死端口**重新设一遍**，而那正是「敲回车就跟上」的反面，屏幕上看不出来。现在会如实报告。

## 两端行为对齐

**同样的失败，退出码该一样。** 「问题反馈」写不出文件时，Windows 原来退 0（说成功了），macOS 退 1。现在都是 1——在脚本里 `envproxy -Report && 发送` 不会拿着一份不存在的报告往下走。

**macOS 实时状态页补齐两个承诺。** 它原来没有底部那句操作提示，也不认 Esc（Windows 一直都认 0 / q / Esc 三个键）。现在两边一致。

**状态页的标签收成一张表。** 那一屏有两套画法（按回车看一次 / 等它自己刷新），标签原来各写一遍，改名必然漏一处——症状是同一台机器上两种方式看到两个不同的产品名。现在共用一份。

## 菜单编号不再写死

状态页、帮助、错误提示里「选 N（某某）」的提示有几十处，数字原来是手写的。菜单项一旦重排（加一项、挪一组），这些数字就全部指向错的命令——不是排版问题，是把人引到一个会改坏东西的动作上。

现在编号和名字都从菜单表取。实测：把「安装 / 修复」的编号改成 9，帮助里的提示自动变成「选 9（安装 / 修复）」。

有一处例外：macOS 的帮助正文住在不展开的 heredoc 里，只能写字面量。那里由门禁逐项核对它与菜单表一致，写错会当场报红。

## 帮助与文档修正

- Windows 帮助的开关那一段漏了 `-Advanced`，补上了。为了不超宽，那一屏拆成两行。
- README 里「4 个地址类变量」的表述不准（地址类是 3 个，`NO_PROXY` 是第 4 个但它是例外清单），中英两份都已更正。
- README 说「`report-*.txt` 卸载不删」，但选「连日志一起删」时它确实会被删掉。改成如实描述。
- 帮助主题 3 和 4 重写：按窗口分开讲，命令改成能整段复制的完整形式。
- 命令行的每一行都标了「在哪个窗口敲」。

## 顺带修掉的小问题

**Windows 固定入口的两个显示问题。** 「查看中继」那一屏在第一次轮询超时时会直接退出，现在留着等下一轮；端口记录文件原来只在启动时写一次，界面可能读到过期的端口，现在每轮重建。

**删掉一个没人调用的函数。** 中继的旧端口选择器（`Select-RelayPort`）在新实现里已经被 `StartRange` 取代，全仓零引用，删了。

**三处指向错处的注释。** 探测层一条注释说「204 / 200 / 3xx = 节点通」，与它上面 40 行的「不认裸 200」直接矛盾（裸 200 是强制门户劫持的典型应答）；一处指向了不存在的函数名；还有两处把快照字段和阈值的核对记成了门禁 6，实际在门禁 15。

## 验证

两侧自检全绿，12 条硬门禁逐条跑过。

这一版里**门禁本身也补了几处漏洞**——它们不影响使用者的日常，但会让「检查通过」变得可信：

- 分发包用的是**真实归档**（`git archive`）而不是拷工作树。原来拷工作树恰好跳过了唯一要验的那一层：哪些文件不该进包。
- 端口表、进程名表、第三档快照阈值原来**完全没有门禁**。补上了，两侧逐项比对。这三样单侧漏加不会报错、不会误判，只是「在别人的机器上变慢」，屏幕上看不出来——正因为不出错，才必须由门禁管。
- 面向上百条用户能看到的文字，扫描范围从「帮助正文」扩到**所有界面文案**（菜单项、菜单提示、状态页）。
- 安装包顶层文件清单不再写死 8 个名字，改成从 `.gitattributes` 派生。

新增的回归用例都做了反向验证：故意改坏一次，确认它会红。其中一条抓出了我自己引入的问题（macOS 帮助正文里塞了不会展开的命令替换），已修正。
