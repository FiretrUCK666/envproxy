# v1.1.6

这一版只有一件事：**把 v1.1.5 在 macOS 侧弄丢的一处兜底还回去**。

## 一、macOS 侧：lsof 解析不出端口时，要退到 netstat 再试一次

v1.1.5 之前的做法是：先用 `lsof` 拿本机在监听的端口；如果一个端口都没解析出来，
就改用 `netstat` 再拿一次——两条路都空的，才算「本机没有代理在监听」。

v1.1.5 把这条兜底收窄了：只有 `lsof` **自己跑不起来**的时候才退到 `netstat`。
看起来更严格，实际开了一个口子：`lsof` 的输出格式一变（系统改版会改），
它照样跑成功、照样退出 0，只是端口解析不出来——这时端口表是空的，
而空表在状态机眼里就是「本机没有代理在监听」，于是你的代理变量被删掉。

也就是说，v1.1.5 想修的「读不出来就别乱动」那个问题，在 macOS 侧留了一个尾巴：
读不出来的那条路修好了，但「读出来却看不明白」的那条路漏了。

这一版把兜底恢复成原来的样子：

- `lsof` 解析出了端口 → 用它；
- `lsof` 什么都没解析出来 → 退到 `netstat` 再试一次；
- 两条路都读不出来 → 这一轮是「不知道」，沿用上一次的状态，**不动你的代理变量**，
  只在日志里留一条记录（v1.1.5 已经加上的那条）。

顺带说明：`lsof` 明确跑成功、而且什么都没输出（退出码 1，意思是「没有匹配的进程」），
这时候即使 `netstat` 不可用，也敢判「本机真的没有监听端口」——这是读到了「空」，
不是读不出来。

Windows 侧没有这个问题：那边一直是「`netstat` 的输出形状变了就转走 WMI 那一路」，
v1.1.5 没动它。

## 兼容性

- 安装包名、下载直链、标签形状、发版流程都没变。
- 变量集合、注入与删除的判据、去抖与迟滞语义都没变。
- 变的只有一处：macOS 侧端口枚举读不出端口时的兜底顺序，回到 v1.1.4 之前的行为。

## 升级方式

打开菜单选 `5 检查更新`。
