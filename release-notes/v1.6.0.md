## v1.6.0：尊重用户的例外设置，变量坏了自己修

### 起因

有分析认为某个代理软件往环境变量里写了 `[::1]` 这种带方括号的写法。实测下来责任方不对
（那个软件写的是 Windows 系统代理，格式是 `localhost;127.*;<local>` 那一套分号写法，
而且它不碰环境变量），但顺着这条线索查出一个真问题：**本工具会覆盖用户与其它软件写在
环境变量里的东西**，而且变量被改坏之后没人修。

### 改了什么

**一、`NO_PROXY` 只增不减**

环境变量是用户级共享资源，用户可能在里面放了自己的例外（公司内网、调试域名）。原先
本工具每次注入都把这几个变量整份覆盖，用户的例外会被冲掉，而且与别的软件互相覆盖。
现在 `NO_PROXY` 按"补齐"处理：默认条目照写，已存在的条目原样保留，合并时按大小写
不敏感去重。用户手动加的例外不会再被冲掉。

**二、默认例外集收录两种 IPv6 写法**

默认值由 `localhost,127.0.0.1,::1` 改为 `localhost,127.0.0.1,::1,[::1]`。两种写法都收是
因为工具们认的不一样：有的按 shell 惯例认裸写的 `::1`，有的按 URL 字面量认带方括号的
`[::1]`。谁认哪种由工具自己决定，本工具只保证"该走直连的本机地址，两种写法都覆盖到"。

**三、卸载只回收自己写的东西**

删除变量时，`NO_PROXY` 与 `NODE_USE_ENV_PROXY` 只在值确实等于本工具写下的那一个时才清除；
值不是本工具写的，一个都不动。其余代理变量仍按名整套清除。

**四、幂等判据从"只看代理地址"改成"整套变量"**

原先只比对代理地址那一个值，于是"地址对、但别的变量被删或漂移"的半代理状态永远无人
纠正。现在比对整套：齐了则一个字都不写、一次广播都不发；不齐则补齐。

**五、变量坏了自己修（治本的那一刀）**

`apply_state` 只在状态翻转时被调用，状态稳定在"翻墙中"时它永远不会执行，所以把校验放在
里面等于没有。现在监控每 30 轮（约 60–90 秒）额外做一次整表核对，缺什么补什么。实测：
把 `NO_PROXY` 改成只剩 `localhost` 之后不管它，45 秒内自动修回原值。

**六、顺手修掉一处竞态**

点"安装"时，安装入口与刚启动的监控会同时校正变量，日志里出现同一秒两条重复的注入记录，
同时发两次全系统广播。现在校正动作用全局互斥锁串起来：先到的一方写完，后到的一方看到
已就位就什么都不做。

### 双端对等

上面六条在 Windows（`win\envproxy.ps1`）与 macOS（`mac\envproxy.sh`）两侧同语义实现，
差异只在写入通道（注册表+广播 / proxy.env+launchctl）与变量拼写份数（5 个 / 9 个），
均按既有约定以 `DIVERGE` 标注。默认例外集在两侧各只有一处定义，不会漂移。

### 验证

- Windows：注入一个模拟的用户例外 `mycorp.internal,*.lan` 后再触发校正，用户条目完整保留，
  同时补上方括号写法；同一值再校正一次不再变化（幂等）。
- Windows 删除路径两种场景都实测：值属于本工具则整套清除（注册表剩余代理键 0 个）；
  值带用户例外则原样保留。
- Windows 稳态自愈实测：制造漂移后不重启，45 秒自愈。
- macOS：用 Git Bash 驱动真实的 `merge_no_proxy`，空值/已有默认/带用户例外/大小写与空格
  差异/幂等五项全部通过。
- 三条门禁（sh 语法、ps1 解析、编码红线）全绿；两份 README 标题 24、表格行 58、
  引用块 24 一一对应。
