# v1.1.13

这一版修的是「卸载没把你的原样还回来」：装之前你自己设过的环境代理变量，卸完就没了。

## 现象

装之前，很多人的终端里本来就有代理变量——可能是自己设的，也可能是别的工具设的，端口还各不相同。

安装时会先把这些原值拍一份快照，卸载时按快照还回去。Windows 上这份快照存在注册表的
`HKCU:\Software\EnvProxy\Backup` 里，问题就出在这里：

写路径记录的那一步会"确保这个注册表键存在"，用的是 `New-Item -Force`。这个参数在注册表上
不是"已经有了就跳过"，而是**把键清空重建**——连带把下面的快照一起删掉。

而监控每次启动都会走那一步。于是结果是这样的：

1. 安装：先拍快照，紧接着启动监控；
2. 监控启动一两秒内，快照被清空；
3. 卸载：想按快照还原，快照已经没了——你原来那套变量删掉了就回不来了。

Windows 上这条链一直存在，只是从来没人注意，因为卸载"看起来很正常"。

## 这一版怎么改的

**建键只在键不存在时才建**，绝不覆盖已有的键。三个地方一起改：更新路径记录、登录时的定位器、
以及快照本身。

**补一个注册表专用的判断**（`Test-RegKey`）。原来判断"键在不在"用的是文件系统那套函数，
它对 `HKCU:\...` 这种路径永远回答"不存在"——照着它判断，已存在的键被当成不存在，下一步就又
回到了清空重建。现在注册表路径一律用前者，文件路径用后者，两边不再混用。

**顺手修了两处**：

- 停止监控时，从命令行里取脚本路径的判据原要求带引号。自己手动起的监控不带引号，取不到它
  自己的目录，优雅停止退化成强杀，还会在实际不用的目录里留一个没人消费的停止标志。
- 监控起不来时，原来只说"可能被另一个副本占着锁"。现在会直接报出那一份在哪，以及怎么办；
  没看到别的副本时，就说清是启动被拦，给出该查的两处。

## 说明文档也改了口气

README 里几处原本在讲"程序内部怎么走"——走哪个域名、试几次、有几种失败原因。这些对使用者
没用，还容易看糊涂。这一版把它们改成说人话：

- 升级那段不再写接口地址和重试次数，只说"直接连 GitHub，多数网络本来就通；万一提示连不上，
  把翻墙软件开关一次再试"。
- 校验值那段不再写算法名，只说"下载完先对一遍，对不上就不装"。
- "为什么它不容易出错"那张表里，把"检查端点""域段""CONNECT 握手"换成"外部站点""能转发请求"。

数字一个没删：7 个站点、15 秒、1KB、200KB、30 轮、连续 3 次，都还在原处。

## 兼容性

- 变量集合、注入与删除的判据、去抖与迟滞语义都没变。
- 只修了 Windows 侧的快照保全；macOS 侧本来就用文件存快照，没有这个问题。
- 已经在用的人不需要做任何事：下一次「安装 / 修复」会自动用上新的判据。

## 升级方式

打开菜单选 `5 检查更新`。
