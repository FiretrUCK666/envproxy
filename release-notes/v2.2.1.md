# v2.2.1

这一版**没有新功能**，全是修 bug。修的都是上一版（v2.2.0）里真实存在的问题，
其中几个会让工具在某些情况下**说假话**——而那正是这个项目最想消灭的东西。

如果你装了 v2.2.0，建议更新。

## 修了五个会真伤到人的问题

### 一、屏幕上印出「选 选 1（安装 / 修复）」

上一版改菜单系统时漏了一处：菜单项的完整名字已经自带「选」字，而调用它的地方
又各自在前面加了一个「选」，于是屏幕上真的印出两个。

会看到它的地方：卸载前的确认提示、几条出错提示。读起来像打字错误。

### 二、卸载失败却报「成功」

在没有可交互终端的场合（脚本里调用、计划任务里跑），卸载会拒绝执行——这是对的，
它不能替你做决定。但它当时返回的**退出码是 0**，意思是「成功」。

后果不是显示问题：`envproxy.ps1 -Uninstall; if ($?) { 删掉备份 }` 这类脚本会
以为卸干净了，然后去删掉唯一一份还能还原的备份。

现在它返回 1，如实表示「没做到」。

### 三、状态页两版说法相反

状态页有两种看法：等它自己刷新，或者按回车看一屏静态的。同一个状态，这两处
**曾经会给出相反的颜色和结论**。

典型的那个状态是「代理变量还在，但后台程序已经停了」：

```
实时刷新看到的那一版：已注入 (http://127.0.0.1:7078)     绿色，像一切正常
按回车看到的那一版：  已注入（…），但没人维护            黄色 + 终端会连不上
```

上面那句是实话。下面那句是骗人的——翻墙软件一断，那个地址不会被清掉，
终端就会连一个不存在的端口。

现在两版从同一张表取结论和说明，不会再各说各话。

### 四、macOS 的后台程序会在第一次注入代理时崩掉

macOS 版第一次成功注入代理、要写日志的那一行，引用了一个在那时并不存在的变量。
开了严格模式之后，这一行会直接把后台程序打死。

它麻烦的地方在于**症状里没有线索**：代理通了、后台程序无声消失、日志里一条错误都没有。
状态页只报「未运行」，看起来像被别的软件关掉了。

### 五、macOS 的「网络救援」修不了任何东西

v2.2.0 新加的网络救援，在 macOS 上一条都修不了——它读数据时漏了一列，
于是每一条记录都被判成「认不出是什么」，全部跳过。

更糟的是界面上的说法：它会把这件事说成「查的时候还在，动手的时候已经没了
（可能是你自己关掉了）」——把我们自己的解析错误赖给了使用者。

## 顺便修的几件小事

**状态页每 2 秒白烧一次扫描。** 统计桌面快捷方式数量要扫一遍磁盘，实测约 112 毫秒。
两处渲染各扫一次，而它们要的只是同一个数字。现在一帧只扫一次，单帧渲染从 120 毫秒
降到 29 毫秒。

**macOS 的帮助页面挤在一起。** 终端里看到的那一份少了一道排版，段落之间没有空行，
整页贴成一坨。同一个主题，重定向到文件看是好的，屏幕上看着挤——因为那是两条路径。

**macOS 的问题报告比 Windows 少两节。** 少了「网络体检」和「后台程序快照」。
而帮助里明明写着「报告里已经有网络体检的结论，不用你另外描述」——翻遍报告找不到。

**macOS 卸载的退出码和 Windows 相反。** Windows 拒绝执行时返回 1，macOS 返回 0。
这一条路径恰恰是自动化脚本最常走的那条。

## 内部变化（使用者感觉不到）

这一版做了几次结构调整，目的是让以后改起来更不容易出错：

- Windows 侧从 12 个库变成 14 个：拆出了 `screen`（画屏幕的那一层）和
  `report`（唯一会写文件、会问问题的那一层）。后者拆出去之后，「状态页只读不问」
  这条约定看一眼文件名就有答案，不再只靠一句注释守着。
- 两个平台的状态页标签收进唯一一张常量表，并加了门禁逐项比对——以前 mac 侧根本
  没有这张表，24 处中文散在各处，改名要全仓搜。
- 「平台差异必须有标注」这条规矩以前没人检查，现在有门禁了。加了之后立刻抓到
  我当场写错的一处。

## 验证

- 两平台的完整门禁全部通过（15 道）
- Windows 自检在 PowerShell 5.1 与 7 上各跑一遍，都过
- macOS 自检通过
- 三次结构调整都用**输出逐字节比对**证明没改变任何屏幕上会出现的内容

## 升级方式

打开菜单选「3 检查更新」，或者直接用安装包覆盖。配置文件、快照、运行日志都不会丢。
