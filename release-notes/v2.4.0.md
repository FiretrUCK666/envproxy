# v2.4.0

这一版加了一个东西，也修了一批**会让状态显示说假话**的问题。

**新增：固定入口。** 有些程序会把代理地址记进它自己的设置里，翻墙软件一换端口，那些程序就连不上，而你还得去它的设置里改一遍。现在建图标时会自动用一个永不变的本地地址（`http://127.0.0.1:17099`）代替翻墙软件的真实端口，背后自动跟着变。它们记的是固定入口，换端口不受影响。

**修掉的：翻墙软件关掉后，状态页会一直说"已开启"。** 这不是显示慢，是个真故障——它同时显示"已开启""端口已不在""正在确认"三句互相矛盾的话，而且十几分钟不消失。根因是探测层在"这一轮没看见端口"时一律报告"不知道"，而"不知道"不计入"连续两轮确认"，于是状态永远翻不过来。同样的毛病 macOS 侧也有，一起修了。

## 你会直接看到的变化

**状态页不再自相矛盾。** 关掉翻墙软件后，几秒内就会变成"未检测到（当前无翻墙代理在运行）"，代理变量同时清空、终端恢复直连。以前它可能一直停在"已开启"，让你以为工具坏了。

**两种刷新方式看到的东西一样了。** 「查看状态」和「实时刷新」本来是两套画法，同一台机器上按回车看到 8 行、等它自己刷新看到 6 行，缺的正好是"上次更新没完成""系统代理可能残留"这两段的**处理办法**。现在两版逐字一致。

**macOS 上"代理变量被改坏"终于会报出来了。** 后台每轮都在算"变量和当前状态对不对得上""变量写进去了没有"，但 mac 侧算了从来不显示——变量被别的程序改掉时，状态页仍然说"一切正常"，而终端其实连不上。现在会报进"有 N 项要注意"。

**macOS 的配色亮了一档，与 Windows 一致。** 原来那边用的是暗色档，同屏"绿字=能整行复制去跑"这个识别线索被削弱了。

**macOS 卸载会多删一个文件。** `notify.last` 记着"上次提示过代理变了"，卸载时没删掉，重装后第一次真的换端口会**什么提示都没有**——被上一份安装留下的值吃掉了。

## 修掉的问题

**交接握手把 `2000` 当成了成功。** 判定"这个端口是不是代理"靠发一个 CONNECT 请求看回应，判据原来是"以 200 开头"，于是 `HTTP/1.1 2000` 也能通过。现实中不会有服务器这么回，但这类模糊地带不该留——现在要求状态码整段相等，两侧同改。

**固定入口的状态读错了进程。** 「查看中继」那一屏跑在独立进程里，而中继跑在监控进程里，判据读的是后者内存里的对象——于是中继明明在跑，界面永远显示"没在工作"。改成读落盘的端口文件 + 发一个专用探针，跨进程也准。

## 关于 macOS 没有固定入口

固定入口需要在一个进程里同时做"接受连接"和"转发"，macOS 侧的 bash 没有这种能力（Windows 侧用的是系统自带的 .NET 类型，不引入任何依赖）。所以这一项只在 Windows 上有。macOS 侧沿用原来的做法：每次启动读当前代理，翻墙软件换端口后重开一次图标即可。文档里写清了这一点与原因。

## 验证

两侧自检全绿，新增 20 条回归用例，并用"故意改坏代码"的方式确认它们真的会红：

- 9 个真实场景的组合行为（正常开着 / 关掉 / 换成表外端口 / 两个软件同时开 / 首次启动 / 换端口 / 端口被非代理程序占着）
- 11 条握手判据（哪些应答才算代理）
- 两版状态页输出逐项比对

Windows 与 macOS 的判据、阈值、文案在这一版里逐项核对过。
