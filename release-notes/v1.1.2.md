# v1.1.2

## 升级不再需要开着翻墙软件

这一版只改一件事：**检查更新和下载安装包，改成优先走 `api.github.com`。**

以前更新走的是 `github.com` 的网页与下载地址。那个域名在受限网络里时通时不通——
同一台机器上实测过连续 5 次下载超时，而 `api.github.com` 一直稳定（200 / 0.2 秒）。
结果就是：明明网络能用，点「检查更新」却报失败。

现在两条路都在，顺序固定：

1. **先走 API**：向 `/releases/tags/<标签>` 问出安装包在仓库里的编号，再从
   `/releases/assets/<编号>` 取文件。这条路会 302 到 GitHub 的资产 CDN，常见受限网络里仍然通。
2. **再退回直连**：上面那条拿不到时，才用原来的 `github.com/.../releases/download/...`。

两条都失败才算这个源不可用。**所以正常情况下，升级这件事不需要网络代理。**

## 顺带说清楚一件事

「问最新版」和「取安装包」现在是同样的思路：API 优先、另一条兜底。版本号与安装包仍然
来自同一个源，不会出现「拿 A 的版本号去下 B 的包」。

## 兼容性

- 安装包名、下载直链、标签形状、发版流程都没变。
- 更新入口的交互没变：发现新版默认问你要不要装，非交互环境只提示不动作。
- 旧版本升级到这一版，走的还是旧版本的更新逻辑——它拿到的是新包，装完就换成新逻辑。

## 升级方式

打开菜单选 `5 检查更新`。
