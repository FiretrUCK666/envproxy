# v2.3.0

这一版没有新功能，全是在把**看得见的地方**整理干净：间隔、对齐、留白，以及问题反馈时该问你的那几句话。

用起来会发现：菜单和帮助读起来不再是一坨字，状态页能一眼看出哪里是哪里，报问题的时候它知道该问你什么。

## 你会直接看到的变化

**每一屏的间隔统一了。** 以前是这里记得空一行、那里忘了，屏幕上就是一段挤一段松。单看每一行都挑不出错，整页读起来就是别扭，说不清哪里不对。现在空行由结构决定，规则有两条：

- 标题**上下各空一行**。标题在给下面内容起头，挤着就开始读很闷；上面空一行，每个标题因此成为独立一段。
- 表格块**前后**各空一行，块内行与行之间不空。表格是嵌在正文里的另一类东西，两侧不留白会跟正文糊在一起；块内逐行空行又会把它拆成一格一段。

帮助的六个主题、高级功能页、状态页全都按这一套走。

**状态页分成了三组。** 原来八行数据紧贴在一起，观感是「一坨字」，眼睛找不到落点。现在：

- 监控进程、开机自启一组——后台在不在
- 翻墙代理、代理变量一组——翻墙链路通不通
- 终端同步单独一组——已开着的窗口跟不跟得上

组内紧凑、组间留白。版本号和最近日志也各占一段。

**状态页的两种刷新方式看起来一样了。** 「查看状态」和「实时刷新」本来是两套画法，排版各走各的，于是同一屏在两种情形下长相不同。现在两版共用同一套分组和顺序。

**帮助目录的编号列对齐了。** 原来编号和标题之间的间距是写死的两个空格，主题一旦上两位数，那一行就会整体右推一格，清单从整齐一列变成参差的。现在列宽按最大编号算。

**「管理走代理的快捷方式」不再往右飘。** 编号缩进从 4 格收到 2 格，明细从 8 格收到 4 格。原来是内容被推到屏幕中段偏右，长路径一折行就贴到右边框。

**问题反馈改成先问你四句话。** 以前它只收机器状态就生成文件，你拿到的是「这台机器当时长什么样」，而不是「哪里坏了」。现在先问：

1. 哪一步出的问题？
2. 屏幕上显示了什么？
3. 你本来希望它做什么？
4. 还有什么想补充的？

前三问给了例子，第四问故意不给——想写什么都行，报了错原文、试过什么都行。四句都空着时会提醒你「这样的报告发出去，对方只能反问你要细节」，并允许取消。

**报告里直接写着发到哪。** 顶部和结尾都有项目地址，不用另外去找。

**帮助 6 说清了唯一的反馈渠道。** 以前那句「不会也没关系，直接发给帮你的人」删掉了——它让人以为有别的门路。现在明确写着「本项目只在这里收问题」，并给出完整地址。

**「它是谁做的、在哪」进了帮助 1。** 以前整个工具里找不到任何 GitHub 地址。

## 修掉的「看着正常，其实不一致」

**帮助 3 的一段话放错了位置。** 「别用 unset HTTP_PROXY」那两句本来是在讲 Git Bash 的一个坑，却贴在 cmd 的说明后面，读起来像在说 cmd。

**状态页底部提示贴着边框线。** 「正在实时刷新 · 按 0 或 Esc 返回」紧挨着结束的 `====`，会被读成框里的内容——而它是这一屏的操作说明。

**标题下面没有空行。** 状态页的结论「一切正常」直接顶着标题，帮助页也是。

## 这一版为什么算「次版本」而不是「修订」

界面排版、菜单与帮助结构、报错文案、反馈流程都变了——按项目约定，使用者能直接看到的变化抬次版本号。

## 需要你知道的

**旧版报告还在。** 这一版之前生成的问题报告格式不同（没有你那四句回答），升级后不影响任何东西，那些文件留在原处。

**发版说明里的示例数字来自本机。** 端口、PID 这类值在你机器上会不一样，那正常。
