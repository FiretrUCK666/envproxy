# v1.1.3

这一版修的全是**「工具在说假话」**的问题：报出来的原因跟真实原因对不上，
或者明明判断不了，却报得像是有结论。分四块说。

## 一、更新失败不再冤枉人

以前查安装包编号时，只要对方回了 200，就一律当成「这一版没提供安装包」。

问题在于 200 不一定是发布页。企业代理、门户劫持都会回 200，只是正文变成了一张
HTML 登录页，或者一个写着「Bad credentials」的对象。那时候报「发布方没提供这个文件」，
既冤枉了维护者，又把你引到 Releases 页面——那里同样拿不到。

现在先看正文是不是真的发布信息（顶层有 assets 列表）：

- 是 → 这一版里确实没这个文件，才报「没提供」；
- 不是 → 报「连不上」。中间那层换了内容，该做的动作是开代理或换网络，不是干等。

## 二、下载完会跟 GitHub 公布的校验值对一下

GitHub 在资产列表里给了每个安装包的 sha256，查编号那一步顺手就拿到了——不额外发请求，
也不额外下文件。对不上就不装：装坏了比不装更糟。

以前只验「能不能打开」，而 zip 能不能打开和内容有没有被改过是两回事。

## 三、两个会让「代理变量被误删」的坑

**端口枚举**：以前判断「这次解析是不是失败了」，用的信号恰好来自解析本身——
行形状一变（多一列、状态列带空格），一行都匹配不上，工具就把「我读不出来」
当成「本机没有端口在监听」，下一轮就把你的代理变量删了。现在「有没有 TCP 行」
单独数（协议列不会被本地化），形状变了走慢的那条路兜底，一条都没有就明说读不出来。

**校验**：以前把「文件读不出来」（杀毒软件刚扫过、文件被短暂锁住）当成「内容被改过」，
于是一个完好的安装包被拒之门外，提示还说「可能下载不完整，或被中间网络改写」。
现在校验有三种结果：对得上 / 对不上 / 读不出来，读不出来按跳过处理。

## 四、macOS 侧的几处加固

- **监控的识别**：以前看命令行里有没有 `install`、`stop` 这些字。装在名字带 install 的
  目录里，监控会被当成一次性命令——于是认为「监控没在跑」又起一个，停的时候也停不掉。
  现在看的是参数位置。
- **操作锁**：以前锁是 mkdir 出来的、持有者 pid 是 afterwards 写进去的。中间那半秒里
  另一个进程读到空 pid，把锁当成陈旧的接管了——两个安装同时跑就互相覆盖文件。
  现在锁一出现就是完整的。
- **改 shell 配置**：以前是就地截断重写，中途失败或被杀就留下半截 `.zshrc`
  （配置坏了比没装更糟）。现在先写临时文件再改名，软链会先解析到真实文件。
- **自启动自愈**：以前重载 launchd 代理会给正在跑的监控发终止信号，而紧接着启的新监控
  可能抢不到单实例锁——结果「自愈」完监控没了，直到下次登录才恢复。
- **问版本时的响应头临时文件**：以前用按进程号算的固定名字、而且从来不删。现在名字不可预测，
  用完就删。

## 兼容性

- 安装包名、下载直链、标签形状、发版流程都没变。
- 变量集合、注入与删除的判据、去抖与迟滞语义都没变。
- 新增：命令行打错选项时会说清并退出（以前会静默进入监控模式），
  更新入口的退出码现在如实反映结果（0 达成目的 / 1 失败 / 2 用法错误）。

打开菜单选 `5 检查更新`。
