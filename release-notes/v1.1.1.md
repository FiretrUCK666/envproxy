# v1.1.1

这一版修的是「屏幕说好了、实际没好」这一类故障。它们都不会报错，也不会让程序崩，只是安安静静地做错事——所以能一直藏着。顺手把一个会删掉你数据的卸载动作堵上了。

## 这一版修掉的大问题

- **macOS 上「给程序建图标」这个功能，其实是 100% 失败的。** 建图标的时候要用到程序名，而那段代码里拿程序名的那一行在重构时丢了。macOS 的命令行工具默认对「用了没定义的变量」直接报错退出，于是每一次建图标都在最后一刻失败，屏幕上是那句会让人去查磁盘权限的「建不出来（目标文件夹不可写？）」——而文件夹明明好好的。Windows 版没有这一段，所以只有 mac 用户会撞上，且无从判断。

- **macOS 上「撤销」系统代理修复，永远报没成功。** 撤销干的事情是把当初关掉的代理设置重新打开，所以撤完之后，体检页当然又看见那些设置「指向已经没程序的端口」——而撤销的判据恰好是「现在还有没有这样的设置」，于是它永远判自己失败。实际已经改回去了，屏幕却一直说没改回去，用户被劝着反复撤销，越撤越乱。现在改成按「跟当初记下来的样子对不对得上」判。

- **同一次撤销还会把你的浏览器代理写坏。** 记录里存的是完整地址 `http://127.0.0.1:7078`，而系统命令要的是「服务器名」和「端口」两样东西。原来把整条地址当成服务器名传了进去，系统照收不误、命令返回成功——浏览器随后拿着一个不存在的服务器名去连。这条命令自己返回 0，只要看退出码就永远发现不了。现在拆成裸地址加端口，并且补上了「自动配置脚本」那条状态开关：原来只写回地址、不重新打开，你的 PAC 就永远停在关着。

- **Windows 上卸载时选「保留快捷方式」，会把你的图标落点记录一起删掉。** 那份记录存着你把图标放在哪（比如 D 盘某个文件夹）。丢了它，图标还在桌面上，但管理页看不见它；它的启动脚本会被当成「没有对应图标的孤儿」，你在管理页删掉那条孤儿，桌面上的图标就变成双击报错。而保留快捷方式时，卸载复检不把这个目录算残留，屏幕上从头到尾没提过一个字。

- **macOS 的图标管理页和状态页之间有处对不上。** 有一类问题是真的、但本工具不替你动手（比如网址解析被指到本机一个没人听的端口）。体检页原来把这类算成「没发现问题」——第一句是绿的「这几处设置都没发现问题」，紧接着的提醒区却在说网页会打不开。误报平安比不说更坏。

## 顺手清掉的东西

- **Windows 卸载不再白等 3 秒。** 那段代码想「等几秒看监控会不会自己把自启动改回来」，但卸载全程拿着操作锁，而监控那边的自愈要的正是同一把锁、拿不到就立刻放弃——所以那 3 秒在任何情况下都等不到东西。
- **Windows 覆盖安装不再留临时文件。** 清理用的是相对目录名，从子目录里跑更新时（菜单触发的路径就是这样）它查的是不存在的路径，被「忽略错误」静静吞掉。残留永远清不掉，而屏幕一切正常。
- **删掉了一批没人用的代码和只写不读的变量**，以及十几处与代码不符的注释——包括 README 里一处把「要直连」指到了「建走代理图标」那一项（照着做会做反）、中英文各有一处「三个地方」和「四个地方」自相矛盾。

## 测试与门禁

这一版没有新功能，力气都花在「让下一次的错藏不住」上：

- **macOS 自检改成开着「未定义变量即报错」跑。** 原来它把这条关掉了——于是上面那个「建图标 100% 失败」的 bug 在生产里必崩、在自检里却全绿。这一条是整件事的根：测试环境比生产环境宽松，等于没测。
- **修好了 4 处「空断言」**：8 条握手判据的断言把参数传错了位，实际在拿期望值跟自己比（`2000` 这种非法应答本该判失败，却一直是绿的）；另外 3 处写成了恒真。这些修完之后才真正在测东西。
- **体检页「状态页不许联网」那道门禁补全了**：原来只查 macOS 状态页的 2 个函数，实际有 7 个。往剩下 5 个里插一句联网调用，门禁一处都不会红——而那正是最容易被人「顺手加一下」的地方。现在补齐并做了反证：故意插一句，门禁立刻红。
- **macOS 自检里的三处测试自身缺陷**：沙箱在最后一段用例跑完之前就被删了；桩函数的「还原」写错了，把真函数删掉而不是恢复；一处固定 sleep 等异步。都改了。

## 已知边界

- 这一版没有新功能，用法与 v1.1.0 完全一样。升级方式不变：Windows 打开菜单选「检查更新」，macOS 跑 `update`。
- macOS 依然没有固定入口（`17099` 那一层只有 Windows 有）：把地址写进自己配置里的程序，翻墙软件换端口时要改一次，「网络与代理修复」能帮你改到当前端口。
