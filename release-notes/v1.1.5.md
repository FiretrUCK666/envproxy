# v1.1.5

这一版修的是**「同一个情况，两端给的说法不一样」**和**「判断不了的时候却做了决定」**这两类问题。
上一版把「工具在说假话」修掉了一半，这一版把剩下的一半补齐。

## 一、端口读不出来时，不再动你的代理变量

监控每几秒要问一次「本机还有没有代理在监听」。这个「读」如果失败了——
工具本身读不出来、或者系统的输出格式变了——以前会被当成「本机没有代理」，
接着就把你的代理环境变量删掉，让你以为翻墙软件坏了。

现在两边都分得清「读不出来」和「没有」：

- 读不出来 → 这一轮是「不知道」，沿用上一次的状态，不动你的变量，日志里留一条记录；
- 真的没有 → 才走删除。

Windows 侧以前只是留了条日志、照样删；macOS 侧连日志都没有。这一版两边行为一致。

## 二、命令行打错时真的会退出

README 一直写着「参数写错会退出（退出码 2）」，但 Windows 侧的代码没做这件事：
`powershell -File` 对不认识的参数不报绑定错误，只是把它们悄悄丢进一个没人读的变量，
于是敲错一个选项就会**静默进入监控模式**——你以为在装东西，工具在后台常驻起来了。

现在：

- Windows：`-Foo`、`-Installt` 这类打错的选项，以及多余的位置参数，都会说清并以退出码 2 退出；
- macOS：`--purge` 用在 `uninstall` 以外的地方、多余的位置参数，同样报用法错误。

## 三、同一份应答，两端不再给出相反的结论

以前有几个地方，Windows 和 macOS 对同一份应答会给出不同的原因，用户按提示做的事也就相反：

- 对方回 200 + 一个能解析但不是发布信息的 JSON（比如被劫持的登录页）：
  Windows 当成「服务端出错，等一会儿重试」，macOS 当成「连不上，去开代理」。
  现在统一按「连不上」处理——中间那层换了内容，该做的动作是开代理或换网络。
- 查安装包编号时，文件明明在发布里、但编号取不出来：
  以前报「这一版没提供安装包」，那是冤枉维护者，也会让你白跑一趟 Releases 页面。
  现在单独归一类：文件是有的，但拿下来不能用。

## 四、macOS 侧另外几处

- **问不到人不再谎报「已取消」**：以前读终端失败和「用户答 n」走同一条路，
  打印「已取消」还给出成功退出码。现在问不到人就说清「没法提问」，退出码 1。
- **下载前就判断能不能提问**：以前是先下载再发现问不到人，白烧一次配额和一份安装包。
- **校验值工具坏了不再静默跳过**：某些机器上 `shasum` 存在但跑不起来，
  校验被跳过，提示却还写着「已下载并校验通过」。现在两个工具都试，
  跳过时提示也会说实话。
- **带开关的一次性命令不再被当成监控**：`uninstall --purge`、`update --yes` 这类命令，
  以前因为看的是命令行最后一个词，被判成「监控在跑」。

## 五、多了一道门禁：跨端行为核对

以前的门禁都只看文字和常量，看不出行为漂移——同一个应答，一端继续更新、另一端说「没提供安装包」，
这种问题就是从门禁缝里漏过去的。

现在有一份跨端用例表（17 条），门禁会把同一批应答喂给两侧，比对两边得出的结论。
两边只要有一处不同，门禁当场失败。改了一侧的解析规则忘了改另一侧，会被这道门禁挡住。

## 兼容性

- 安装包名、下载直链、标签形状、发版流程都没变。
- 变量集合、注入与删除的判据、去抖与迟滞语义都没变。
- 监控在你没动它的时候，行为和以前一样；变的只是「它读不出来的时候不再乱动」。

## 升级方式

打开菜单选 `5 检查更新`。
