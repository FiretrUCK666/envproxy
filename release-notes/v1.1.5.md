# v1.1.5

这一版修的是「macOS 上卸载之后，家目录里留下一个删不掉的 `~/.envproxy`」。功能没有增减，用法与 v1.1.4 一样。

## 问题

macOS 侧有两个东西要写进本工具的家目录：

- **程序外壳**（给某个程序定的「走代理 / 固定直连」规矩，存放位置）
- **落点记录**（你自选过把图标放在哪些目录）

它们的路径本来是分别计算的：

| 东西 | 原来从哪算 |
| --- | --- |
| 程序外壳 | `$HOME/.envproxy/apps` |
| 落点记录 | `$ENVPROXY_HOME/shortcut-dirs.txt` |

**两个源头不一样，就会分家。** 只要设了 `ENVPROXY_HOME` 这个环境变量（它本来就是允许改的），外壳会建在 `$HOME/.envproxy/apps`，而卸载去删 `$ENVPROXY_HOME/apps` —— 删不到。

删不到的后果是一连串的：目录非空 → 最后那句 `rmdir` 静默失败 → 提示说「已恢复到安装前的状态」，而家目录还在 → 连 `--purge` 也清不掉。

（Windows 侧没有这个毛病：那两个目录都从 `Get-InstallDir()` 算，本来就是同一个根。）

## 改了什么

**两个目录都从 `ENVPROXY_HOME` 算。** 这才谈得上「卸载时整份带走」。

同时加了两条回归断言，钉住这件事不再复发：

- 外壳目录与落点记录必须同根
- 根必须就是 `ENVPROXY_HOME` 本身

## 顺手清掉的一处开发残留

在 Windows 机器上反复跑 macOS 自检，会在 `~/.envproxy` 下留下几个 macOS 格式的 `.app` 外壳，指向的临时目录早已不存在。它们是开发过程产生的死数据（Windows 侧完全不使用这个目录）。

产生它们的旧测试已经不再这样写了，删掉之后连跑两遍自检确认不会重建。

## 已知边界

- 这一版没有新功能，用法与 v1.1.4 完全一样。
- 这个修复只影响 macOS 侧；Windows 侧的同类路径一直是同根，没有改动。
- 已经留下的残留不会被自动清掉（旧版本卸载时删不到它们），需要手动删掉 `~/.envproxy`。
