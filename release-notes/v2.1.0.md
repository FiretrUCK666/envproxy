# EnvProxy 2.1.0

菜单 5 里的「浏览器代理修复」升级成「网络与代理修复」。它现在一次看三处设置，
而不只是浏览器那一层。

## 新增

- **终端工具的代理残留**。`git config --global http.proxy …` 和 `~/.npmrc` 里写死的地址
  优先级高于本工具管的环境变量——所以会出现「浏览器好好的，只有 git 或 npm 连不上」。
  这一项现在会查出来，并按同一套判据修掉（本机地址 + 端口已死）。
- **网址解析的两处设置打架**。如果你给「所有网络」设过 DNS，又给某一个 Wi-Fi 单独设过，
  系统只用其中一处，另一处不生效——平时没有任何地方会告诉你。这一屏会点出来。
- **DNS 指向本机但没人应答**。翻墙软件改过系统 DNS 又没改回去时会出现。
  这一项**只提醒、不自动改**：改回自动获取之后路由器会给什么地址，改之前拿不到这个答案，
  猜错比原来的毛病更糟。

## 改了什么

- **还原点从单份变成事务日志**（`monitor/doctor.journal`）。以前只有一份、而且只写一次，
  修第二处时会覆盖第一处的还原点。现在每次修复各留一份，留最近 5 次，
  按 `r` 撤销的是**上一次**修复。旧的 `doctor.bak` 仍然能读，升级上来的人第一次按 `r` 就能用。
- **固定入口（17099）现在也认 SOCKS 协议**。以前把它填进只发 SOCKS 握手的地方，
  会卡十几秒然后失败；现在同一地址 HTTP 和 SOCKS 都通，浏览器和那些工具都不用改设置。
- 修复页的结论分成三段：要修的、不归本工具碰的、只是提醒的。

## 内部

- 体检逻辑拆成检查器层（`insp` 库）：加一层网络检查 = 写一个读取函数 + 表里加一行，
  界面、报告、备份、还原都不用改。门禁 16 新增一段，核对表里声明的函数在本侧真实存在、
  可修的层必须有撤销函数、两侧的检查器列表同序。

## 升级

照常打开菜单选 1（安装 / 修复）。
