# v2.1.0

这一版只修一件事：**工具会把一条已经坏掉的代理，判成「正在翻墙」。**

如果你遇到过「几乎不能翻墙（浏览器不行），但工具状态页一切正常、终端里 git/npm 全挂」，
这一版就是冲那个来的。建议更新。

---

# 问题是什么

工具判断「代理到底能不能出去」，原来的做法是：经本地代理端口访问 6 个检测网址，
任意一个返回预期响应就算通过。

这个判据漏掉了一种情况：**那个检测网址，不挂代理也能打开。**

「这个网址会不会被墙」不是网址自己的属性，而是「你这台机器的网络 + 翻墙软件的分流规则」
共同决定的。同一个网址在不同网络下答案可以完全相反。一旦碰上，后果是这样的：

- 翻墙软件的节点其实已经死了，真正被墙的网站一律连不上；
- 但某个检测网址在本地有服务器，直连就能通，走代理也「通」；
- 工具据此判定「翻墙中」，把这条死掉的代理写进每个终端的环境变量；
- **屏幕上全绿，终端里每条命令都失败。**

因为用户看不到工具的判断过程，只会觉得「工具骗我」。

# 这一版怎么改的

判据从「经代理能通」收紧成「经代理能通 **且** 不挂代理打不开」，两个条件同时成立才算数。

具体做法：

- 每个检测网址第一次被使用时，先问一次「不挂代理能不能打开它」，结论记住，之后不再重复问；
- 只有「直连打不开」的那个，它经代理返回的响应才算证据；
- 三条探测路径（快速路径、并行兜底、串行兜底）共用同一个判定函数，不会各写一套。

这样「哪个检测网址能用」就由你这台机器的现场事实决定，换网络、换翻墙软件、换分流规则
都不用改代码。

# 代价

每个检测网址多做一次不挂代理的访问，每个进程只做一次然后缓存。
第一次判断会多花约 1 秒，之后没有额外开销。稳态下的探测流量没有变化。

# 验证

- 复原了那次误判的完整现场：一个只对 gstatic 系应答、其余全 502 的假代理。
  旧判据判「翻墙中」，新判据判「不通」。
- 反向用例：同样的假代理，把检测网址换成「直连打不开」的，必须仍然判「通」——
  否则等于把这个功能删掉。
- 两侧都加了用例；Win 侧自检在 PowerShell 5.1 与 7 上各跑一遍，Mac 侧自检全套通过。
- 用真实正常节点复核：6 个检测网址中 4 个被认定为有效证据、2 个（国内有落地）被排除，
  代理仍判「翻墙中」。

# 影响范围

只改判定逻辑，不改任何写入行为：变量集合、注入与删除条件、去抖与迟滞阈值、
卸载与自愈全部原样。

`AGENTS.md` 里新增一条不变量，说明为什么端点证据必须带这个「合格证」。

# 升级方式

打开菜单选「1 安装 / 修复」，或者直接用安装包覆盖。配置文件、快照、运行日志都不会丢。

# 已知边界

这一版让工具不再「把坏代理说成好的」，但它**修不了翻墙软件本身**。
如果节点域名消失、订阅过期之类的问题发生，工具现在的表现是如实报「代理不通」，
而不是假装一切正常——这时候该去处理翻墙软件那边。
