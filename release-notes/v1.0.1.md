## v1.0.1：程序文件按职责拆分，升级更可靠

程序文件从一个近两千行的大脚本，拆成「入口 + 七个职责库」（`win\lib\` 与 `mac\lib\`）。
功能与用法完全不变——这一版做的是把内部结构理顺，让以后改动更安全、更省事。

### 它会做什么

- 翻墙软件开着的时候，自动把代理写进环境变量，终端里的 `git`、`npm`、`curl` 这类工具跟着走代理；
- 翻墙软件关掉之后，自动把这几个变量删干净，终端立刻回到直连，不会留下"连不上"的残留；
- 常驻监控每 2–3 秒看一眼，判"真的在翻墙"要过三道检查：端口在听、握手能过、真能连出去；
- 变量整套同进同退：Windows 5 个，macOS 9 个（含小写拼写）；判"断"保守（连续 3 次失败才认定），判"通"立刻认回。

### 这一版包含

- 入口只做四件事：解析参数、挂操作锁、加载完整性自检、分派；其余按七个职责分居 `lib\` 下（base / probe / env / runtime / package / update / ops），两端同名同职责；
- 升级时每个文件都走「同目录临时文件 + 整体替换」：写到一半断电或被杀，也不会留下半截文件；
- 安装包校验改为结构校验：两个平台入口必须在，包内每个 `.ps1` 带 BOM 且非空、每个 `.sh` 无 BOM 无 CRLF 且非空。以后加库、改名、挪位置都不用改校验逻辑；
- 入口加载前先验完整性：缺文件时直接说人话——「安装不完整，缺少程序文件：lib\xxx」，并告诉你怎么修，而不是抛一句看不懂的语法错误；
- 两个按钮改成"按复检结论说话"：`1-安装` 会读回复检开机自启动有没有真的写上（被杀软拦住时如实提示，不再一律报成功）；`2-停止监控` 在 macOS 上也一样，进程没停下来就报实情；
- 两端对"端点响应算不算通"统一口径：只认 200 / 204 与 3xx 重定向，其余一律判"断"——错判"通"会把终端流量送进坏节点，错判"断"只是不注入，两个代价不对称，所以从严；
- 升级路径的路径处理加固：安装包目录或安装目录若是 8.3 短名写法，相对路径不再错位（错位会误删文件、把新文件写到错位置）；
- 回归自检扩容：新增原子复制、安装包结构校验、库清单一致性、自启动命令行等用例，Windows 与 macOS 两侧各跑一遍；
- CI 门禁同步加固：编码红线、语法解析、契约常量提取都改为覆盖整个脚本集，另加三条不变量——入口声明的库清单必须与 `lib\` 实际内容一致、库之间不许出现重名函数、macOS 侧不许出现只有新版 bash 才支持的写法。
