# v1.1.11

这一版修的是一处「查更新查错地方」的问题：仓库名从 git 地址里读错，于是好端端的新版本被说成
「发布方没提供安装包」。

## 现象

用 git 接管的副本（开发副本），查更新时会从你自己的 git 远程地址里读出「谁的发布页」。
读法是按地址的长相套的，默认它长这样：

```
https://github.com/主人/仓库名.git
```

换成带端口的写法就不对了：

```
ssh://git@ssh.github.com:443/主人/仓库名.git
```

`443` 是端口号，却被当成了主人名。查询地址于是变成
`https://api.github.com/repos/443/主人/releases/latest`——一个不存在的仓库。

不存在的仓库，GitHub 回 404。而 404 在这套代码里的含义是「这一版确实没提供安装包」。
两件事叠在一起，状态页就会说：

> 最新版本 : 检查失败（……上没有提供这个版本的安装包。请到 Releases 页面手动下载……）

发布页上明明挂着安装包，却让使用者去手动下载。

## 这一版怎么改的

不再按地址的长相去套，改成按**位置**取：不管什么协议、什么主机、有没有端口、有没有
`.git` 后缀，仓库标识永远是地址路径里的**最后两段**。

主机不是 GitHub 的（换成本地镜像或别的托管），就不从远程读，退回内置的默认仓库——
既不报成「没提供安装包」，也不会拿着别的主机的地址去问。

## 兼容性

- 变量集合、注入与删除的判据、去抖与迟滞语义都没变。
- 只改了「仓库标识从哪来」这一个纯函数，Windows 与 macOS 两侧同一套判据。
- 顺带为这个函数加了回归用例：https、scp 写法、带端口的 ssh、尾部斜杠、非 GitHub 主机、
  本地路径、空地址，七种写法两侧各钉一遍。

## 升级方式

打开菜单选 `5 检查更新`。
