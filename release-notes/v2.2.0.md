# v2.2.0

这一版**加了一个新功能**：网络救援（高级功能 → 4）。

它修的是「翻墙软件被强行关掉之后，浏览器连国内网站都打不开」这件事。正常关软件不会出这个问题，正常退出时软件会把自己写进系统的那条设置撤掉；但关机、断电、任务管理器结束进程这几种情况下它来不及撤，于是浏览器还照旧把请求发给一个**已经不存在的程序**——线没断，是路指错了。

## 新功能：网络救援

放在「高级功能」里，不在主菜单——平日用不到它，它是出事时用的。

**它会做什么。** 读出系统里所有层代理设置，挑出「指向本机、但那个程序已经不在」的那一种，修掉，并先留一份底、随时能还原。

**它不会做什么。** 公司或学校给的代理，一个字节都不碰。别的地址（不是这台电脑自己）同样一律不动。被管理员统一管着的机器也不动。

这条边界比功能本身重要：判错的代价是删掉你唯一能用的代理路径，那比不修更糟。

### 三种情况，说的不是同一句话

屏幕上第一句永远是「你现在是什么情况」，这三种分得很清：

**设置残留（能修）**
```
查下来：浏览器被指到了一个已经关掉的程序上。
        所以网页打不开——线没断，是路指错了。
```

**节点问题（不能修，也不该修）**
```
查下来：代理程序还开着，端口也在，但它连不上外面。
        这多半是节点的问题，不是设置坏了。
        关掉重开代理软件、或者换一个节点试试。
```

**真的没事**
```
查下来：浏览器这边的设置没发现问题。
```

第二种是这一版特意分出来的。以前它会显示「没发现问题」，而你会以为工具什么都没查出来，然后自己去动系统代理——**删掉代理设置并不恢复网络**（程序还在跑、还占着端口），只会把你原本能用的路径删掉。

### 每条结论都说清「凭什么」

不是只给一个「能修」，而是说明依据，以及你下一步能做什么：

```
代理地址是本机，端口 7078 上有程序在听，连得上。
证据：占用端口的是 MonoCloud_Mix.bin，像是 MonoCloud 在跑；它应答了代理握手，确实在工作。
你可以：不需要做什么。
```

### 它也如实说清自己管不到哪儿

有些程序的断网**根本不会出现在系统代理设置里**：Proxifier、新版 Netch、SSTap、各种游戏加速器，它们走的是驱动、虚拟网卡与路由表。

这类问题扫注册表扫到天荒地老也扫不出来。所以查不到问题时它会补一句：

```
这个工具只管「浏览器代理」这一层。
如果网还是不通，问题可能在别处：虚拟网卡、路由表、或防火墙规则。
```

不说这句，你会在错误的方向上找出路。

## 顺手改好的几处

**菜单编号变成绿色了。** 高级功能页里 `1 2 3 4` 现在单独显示为绿色，名字和说明是白色。绿色在这个项目里一直是「这是你要敲的东西」的意思，所以一眼就能看到该按哪个。

**状态页也会提示节点问题了。** 代理在跑但连不出去时，「有 N 项要注意」里会多一条：

```
- 代理在跑，但它连不上外面（多半是节点问题，换个节点试试）
```

这条只在**确实拿到证据**时才出现。拿不到证据就不说——宁可不说，也不能猜。

**两种 PowerShell 版本的行为差异修掉了。** 判断一个地址是不是「本机」时，PowerShell 7 与 5.1 对 IPv6 通配地址给出的写法不一样（`::` 与 `0:0:0:0:0:0:0:0`）。原来只认一种，5.1 上会判错。现在两种都认。

## 背后修掉的几个真问题

这部分你在屏幕上不会直接看到，但每一条都会在真实场景里咬人。

**企业机器会被误判成「没被管」。** 判断「代理设置是否被管理员统一管着」时，用的三个策略名里**有两个根本不存在**——是把策略的英文标题当成了值名。后果是真正被锁死的机器被判成「可以改」，工具去修、改不动、然后报「已修好」。

现在三项都逐字对着微软官方的策略定义（`inetres.admx`）核对过。顺带修了另一个错：那两个值**不在同一个注册表键**下，只查一个键同样会漏。

**macOS 上有一类问题永远检测不到。** 自动配置脚本（PAC）指向一个已经关掉的端口时，网页能开但每次都要先等它超时几秒。这类问题在 macOS 上原来查不出来，因为读 PAC 时没解析端口，端口一直是 0，于是被判成「不是本机的东西」不动。现在能正确解析了，包括带路径、不带路径、`file://` 几种形态。

**一个地址写法会让正在工作的代理被误删。** `0.0.0.0` 在语义上就是「本机任意地址」，但直接拿它去连接，系统会报「地址无效」。于是端口明明活着却被判成连不上 → 判成残留 → 关掉一个正在工作的代理。现在会先把它翻成 `127.0.0.1` 再探。

**PAC 与手动代理在 Windows 上会互相踩。** 有些客户端在关掉 PAC 时会连带清掉代理标志位，所以它必须先清 PAC 再设代理。我们的写法是逐项精确下发，实测不会互踩——但这条结论依赖「只改出问题的那一位」。已经在代码里写明，防止以后有人图省事改成「整段重写」。

**v2rayN 的 `Unchanged` 模式是设计如此。** 用户选了这一档，正常退出时它**故意不清**代理设置，为的是下次开软件直接能用。所以那种残留不是崩溃，是用户的配置。从「能不能上网」看修掉是对的，但文案不该说「上次没关好」——这一版没有为它单独做判断，留到以后。

## 端口表成了一张表

以前「哪些端口可能是代理」和「哪些进程名像翻墙软件」散在好几处，靠门禁比字面量硬撑着。现在收敛成**一张客户端目录表**，其余全部自动从它派生——加一个客户端支持就是表里加一行。

顺带修正了一批端口：Clash Verge Rev 的默认端口是 **7897**（不是大家以为的 7890）、Hiddify 是 **12334**、v2rayN 的端口是「基址 + 偏移」算出来的（改基址整套都跟着变）。

**但这张表不参与判断。** 端口号随便改都不影响结论——命令行实测过：把代理改到 45123、59999、31337 这些表里完全没有的端口，判定依然正确。真实世界里写代理的软件远不止公开的那几家（你机器上这个就是一套自研商业客户端），按名单认从根上有天花板。

## 验证

- Windows 自检：PowerShell 7 与自带的 5.1 各跑一遍，全过
- macOS 自检：全部通过
- CI：ubuntu 与 windows-latest 各跑一遍，全绿
- 真机演练：把系统的四层代理设置当现场，逐一造出「健康 / 残留 / 通配地址 / 公司代理」四种局面，判定、修复、还原、现场复原逐步核对过

新增的断言里有几条是专门钉住「不许误报」的：

- 探测死活只连 TCP 端口、**不建隧道**（判「能不能访问目标」会把活着的代理判死，然后误删）
- 状态页永远不采集握手（所以它不可能误报节点问题）
- 老版本的快照缺新字段时，必须仍判「可用」而不是「损坏」
- 拿到 `upstream-fail` 才提节点问题，拿不到时一句都不说
- 菜单编号必须单独上色、且用的就是那个「要敲的东西」的颜色

## 兼容性

没有不兼容改动。没有新增依赖。变量集合、注入判据、阈值、菜单编号、帮助内容都没动。

有两处行为变化，都是修正：

**退出码。** 这一版没有动它。

**状态页多一条提示。** 代理在跑但连不出去时，「有 N 项要注意」会多一条。以前这种情况显示「一切正常」——那是错的，你会以为终端能正常用。

**高级功能页的编号变色。** 屏幕上的绿字比以前多了一处。这是可读性的改动，不影响任何功能。

升级不需要卸载重装，直接覆盖即可。已经装好的机器，旧快照缺新字段时状态页照常工作，不会因为升级瞬间的数据不完整而报错。
