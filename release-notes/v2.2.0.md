# v2.2.0

这一版修的是一类问题：在你这台机器上一切正常，换一台机器（换了杀毒软件、系统语言、
系统时间，或者换到 Mac）才会踩到，而且不报错。另外 Git Bash 现在也会自动跟上了。

从 2.1.0 升上来不用卸载重装，只有一件事要留意：菜单编号变了，见下面第一条。

## 你会直接看到的变化

**Git Bash 也会自动跟随了。** 以前只有 PowerShell 和 Mac 终端能跟，Git Bash 要重开窗口。
现在它也跟上了——监控每次改状态会顺手存一份小文件，Git Bash 每次回到提示符读那个文件
（约 0.5 毫秒，感觉不到）。

**菜单编号全换了。** 新的是：1 安装 / 修复、2 查看状态、3 检查更新、4 帮助、5 停止监控、
6 一键恢复、0 退出。

从 2.1.0 升上来的话，有两处要特别当心：以前「5 检查更新」现在是「停止监控」；
**以前「6 帮助」现在是「一键恢复」（就是卸载）——想找帮助千万别敲 6，敲 4。**

**只有 cmd 还是不行。** 它没有「每次回到提示符先跑一小段命令」这种机制，这是 Windows
自己的限制，绕不过去。文档里已经把 Git Bash 和 cmd 分开说了。

**状态页开始说实话了。** 以前监控进程被「结束任务」关掉，页面会写「已按你的选择停止」——
好像是你自己停的。现在两种情况分开说：真是你停的，它说「下次登录会自动恢复」；
是进程不在了，它会说「不是点了停止，是进程不在了：可能被结束任务关掉，或崩溃」，
并告诉你怎么让它重新跑起来。
另外，监控没在跑、但系统里还挂着代理变量时，它会额外提醒你：这些变量现在没人维护，
翻墙软件一断开终端就连不上。

**状态页多一行「终端同步」。** 以前状态页只说「监控在跑」，你没法知道已开着的窗口到底
有没有在跟。现在它会明说：已生效 / 装了但跑不起来（附原因）/ 标记不成对 / 没有同步块。

## 修掉的「在别人机器上悄悄失效」

这类问题的共同点：在一台机器上完全正常，换个环境就悄悄失效，还不报错。

| 环境 | 以前会怎样 | 现在 |
|---|---|---|
| 代理只绑 IPv6 回环（`::1`） | 永远检测不到代理，也不报错 | 两个回环地址都试 |
| 系统时间被 NTP 校正过 | 校时后可能永不再探测，代理状态卡死 | 判定改用单调时钟，不受校时影响 |
| 强制门户 WiFi（酒店、机场） | 劫持页面回 200，被当成「代理通了」 | `/generate_204` 只认 204，回 200 不算通 |
| 泰语 / 阿拉伯语系统 | 日志年份写成佛历 / 回历，线索对不上时间 | 时间戳固定用公历 |
| 组策略锁定执行策略 | 终端同步被拦，工具一句话不说 | 区分「组策略强制」与「本地可改」，各给对应提示 |
| 装过两次 | 卸载只摘掉第一块，看起来成功、实际余下一块 | 一次摘干净所有块 |
| 同一台机器多个用户 | 认领别人的监控进程，还会把它停掉 | 按用户 SID 过滤 |
| 杀软改过启动器文件 | 中文注释撑破语法，登录启动项静默失效，自愈却说正常 | 单独校验 BOM，丢了就重建 |
| Homebrew 的 netcat 抢占 PATH | 探测全失败，候选集永远为空 | 先探测 `nc -G` 支不支持，不支持就用 curl 做同样的握手 |
| 临时目录名带方括号 | 解压报「路径不存在」，被误报成「发布包有问题」 | 改用 LiteralPath |

## 修掉的数据安全问题

**`.envproxy.bak` 以前每次写都覆盖。** 装第二次时里面已经是带了我们那一块的版本，
你原来的内容在「装一次 + 卸一次」之后就没了。现在只在第一次写之前备份，它才真的能
还原到装之前。

**原本不存在的文件会留一张字条**，说明「装前不存在、卸载该删」。以前这种情况留的是
0 字节的空文件，打开什么都没有，还原不了任何东西。

**macOS 的临时文件从来没人清理过**：创建写到 `/tmp`，清扫却读 `${TMPDIR:-/tmp}`，
两边不是一个目录。现在统一了，并且同时清理文件和目录（下载的包是文件、解压目录是目录）。
更新时留下的响应头文件还有第二个岔子：创建用的是 `envproxy-update-`，清扫认的是
`envproxy_update.`，前缀不一致，等于永远扫不到自己。现在两边同名了。

**卸载后不再留三个 `.bak` 文件。** 那几张 `.bak` 是安装前给配置文件拍的快照，
以前卸载只摘掉我们写的那一块、快照留在原处，和「卸载后不留残留」对不上。
现在卸载会把它们一并带走（快照里自己写的那句「卸载时应删除」以前没人执行）。

## 顺带

- 更清楚地告诉你是哪个环节失败：端口枚举失败会带上具体原因，以前只写「失败了」。
- 端口在位检查改成三态（在 / 不在 / 读不出来）。读不出来时不再误判成「代理没了」而删你的变量。
- 日志时间戳、版本比较这类地方不再受系统区域设置影响。
- 只绑 IPv6 的代理，注入的地址现在是实际能连上的那个（`http://[::1]:端口`）。
  以前是检测到了却注入 `127.0.0.1`，终端里连不上、状态页还说正常。
- 检查更新不再拒收自己的安装包。这一条以前会让所有老版本都升不上来，
  提示还写着「拿回来的东西没法用」。
- 执行策略的判定不再被安装器自己的 `-ExecutionPolicy Bypass` 盖住：
  以前真实生效值被遮掉，状态页一律报「已生效」。
- **从 Git Bash 启动 PowerShell 5.1 不再报错。** 以前 Git Bash 的同步脚本会同时写
  `HTTP_PROXY` 和 `http_proxy` 两套拼写；Windows 这侧变量名不区分大小写，两套并存会让
  5.1 在枚举环境变量时抛 `An item with the same key has already been added`，
  那个窗口里跑的程序都会受影响。现在只写小写那一套（Windows 查变量时本来就不区分大小写，
  照读不误；Git Bash 里的 curl 也只认小写）。
- **Git Bash 里「敲回车就跟上」以前对一种情况无效**：如果某个窗口里只剩小写拼写的变量，
  清除逻辑只比对了大写那个，就一直清不掉。现在任一种拼写匹配就两套一起清。
- 卸载没清干净时，以前只说「手动删除上述位置」，可上面根本没写是哪些位置。
  现在每条残留都带上具体路径，照着删就行。
- 安装和卸载的提示里会提到 Git Bash，不再只说 PowerShell（实际两边都写了，以前只说一半）。
- 新建的配置文件里那一小段同步代码改成纯英文注释。你的配置文件本来是什么编码我们不知道，
  往里塞中文在 PowerShell 5.1 里会显示成乱码。

## 文档与配图

- README 和菜单里几处说法和实际行为对不上了，都改正了。最要紧的两条：
  「1 安装 / 修复」本来就不会下载新版（它只装当前代码），以前写得像是能升级；
  卸载没清干净时以前让你「手动删除上述位置」，可上面没写是哪些位置，现在每条都带上具体路径。
- 首页那几张示意图里，图标原来是用字符画的，换个字体（手机上尤其明显）就会整体往上飘，
  和旁边的圆点对不齐。现在改成矢量图形，位置由坐标决定，换什么字体都一样。
- 有几句文字超出了卡片的框线（英文版尤其明显），已经收回来了；一张图里没用到的图例也删掉了。

## 内部加固（不影响用法，但你以后升级会更稳）

这一版给自动检查补了一层「接线」检查。起因是发现一类破坏能一路绿灯溜到用户手里：
把某个关键调用删掉一行（比如入口不再进入监控主循环、清理前的判断改成恒假），
所有检查仍然全绿，而功能已经没了。

现在这类「减法」会被当场抓住，Windows 和 macOS 两侧都有。附带的结果是：
安装包如果被误标成「不随包发」，检查会指名道姓报出来（以前只有「不要发什么」的清单，
误加一行就等于少发一个文件，两边永远一致、永远绿）。

## 升级

菜单选「3 检查更新」，按提示确认就行。

**注意：「1 安装 / 修复」不会去下载新版**——它只装当前这份代码，装完顺带告诉你有没有新版。
想升级只能走「3 检查更新」。

装完建议打开一次菜单选「2 查看状态」，确认「终端同步」这一行是「已生效」。
