# v1.1.7

这一版修的是三件会让使用者吃亏的事，其中两件在 macOS 上。

## 一、macOS：端口读不出来时，不会再删掉你的代理变量

v1.1.5 改过一处：读不到本机监听端口时，不再当成"本机没有代理"，而是"这一轮不知道"，
沿用上一次的状态。改漏了两处——**"不知道"在别处又被当成了"没有"**：

- 监控启动时把状态记成了"没有代理"；
- 之后每 30 轮的自愈检查看到"我们处于没有代理的状态，但变量还在"，就把它当成残留清理掉了。

结果是：你明明在翻墙，终端里的代理变量却被悄悄删掉，日志还写着"代理已关闭"。

这一版把"不知道"一路传到底：启动、安装、30 轮自愈三处都认它，
读不出来就沿用现状、**一个变量都不动**，日志写"端口枚举失败 -> 本轮沿用上一状态"。

**Windows 侧没有这个问题**（那边的状态是空值而不是"没有"，自愈检查两个分支都不会进），
这一版是把 macOS 侧补齐到和 Windows 侧一样。

## 二、macOS：`uninstall --purge`、`update --yes` 又能用了

v1.1.5 给命令行加了参数检查（本意是拦住敲错的选项，别让它静默跑起来）。
但检查写成了"参数超过一个就报错"——**开关本身也占一个参数位**，
于是所有"子命令 + 开关"的正常用法一起被拒了：卸载并清日志、跳过确认直接更新，全都报"用法错误"。

Windows 侧不受影响（`-Update -Yes` 一直正常）。

这一版改成只数**多余的位置参数**，开关不计入。行为对照：

| 写法 | 现在的结果 |
| --- | --- |
| `uninstall --purge` | 正常执行（以前报用法错误） |
| `update --yes` | 正常执行（以前报用法错误） |
| `status extra` | 报用法错误，退出码 2（不变） |
| `install --purge` | 报用法错误，退出码 2（不变） |

## 三、两侧：同一份应答，结论终于一致了

更新器要向 GitHub 问"这一版有没有安装包"。回来的内容有两种可能：一份发布信息，
或者别的东西（企业网关劫持时返回的登录页、错误对象）。

判断"这是不是发布信息"，两侧此前用的判据不完全一样，于是**同一份内容，
Windows 侧说"不是发布信息、让你去开代理"，macOS 侧却当成发布信息继续下载**。

这一版两侧统一成：顶层得是一个对象、且带 `assets` 字段才算发布信息。
顶层是数组（哪怕里面正好是发布信息）一律不算。

同时，状态显示页在端口读不出来时不再写"未检测到（当前无翻墙代理在运行）"，
改写"读不出来（端口枚举失败，这一轮不知道有没有代理在运行）"——
读不出来和没有，不是一回事。

## 兼容性

- 安装包名、下载直链、标签形状、发版流程都没变。
- 变量集合、注入与删除的判据、去抖与迟滞语义都没变。
- 变的只有上面三件：macOS 的变量不再被误删、macOS 的带开关命令恢复可用、
  两侧对同一份应答的判断一致、状态页说真话。

## 升级方式

打开菜单选 `5 检查更新`。
