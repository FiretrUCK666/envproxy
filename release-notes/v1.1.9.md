# v1.1.9

这一版把三件事收尾：命令行里"跳过确认"这个开关以前用在哪都算数、Windows 侧算校验值不再看
PowerShell 模块的脸色、macOS 上一版说明里提到的两处修复到这一版才真正发布。

## 一、命令行：`--yes` / `-Yes` 必须跟着它的命令

"跳过确认"是给脚本用的开关：跑更新时不想等人回答，就加上它。

以前它加在哪个命令上都算数——比如 `install --yes`、`status --yes`：脚本写错了，工具照跑不误，
那个"跳过确认"被悄悄丢掉。你以为更新会直接装上，其实它还在等你回答。

这一版把规则钉死：**跳过确认只配更新**，别的命令一律报"参数用错了"并退出（退出码 2），
一个文件都不动。两侧同一套：

| 写法 | 结果 |
| --- | --- |
| Windows `-Update -Yes` | 正常执行 |
| Windows `-Status -Yes` | 报用法错误，退出码 2（以前照跑，开关被丢掉） |
| Mac `update --yes` | 正常执行 |
| Mac `install --yes` | 报用法错误，退出码 2（以前照跑，开关被丢掉） |

"连日志一起删"那个开关（Windows `-Purge`、Mac `--purge`）的规矩不变：只配卸载。
两边现在是同一套判断、同样的提示、同样的退出码。

开关名不分大小写：`--PURGE`、`--Purge`、`--purge` 一样认。

## 二、Windows：算校验值不再依赖 PowerShell 模块

下载完的安装包要和 GitHub 公布的 sha256 对一遍——防止包在路上被改写或截断。

这一步以前用的是 `Get-FileHash`，它不是系统自带的命令，而是 PowerShell 启动时从模块目录里
临时加载的。**模块目录里如果排着别的 PowerShell 版本的模块**（常见于从 PowerShell 7 里
再开一个 5.1 窗口），系统会挑中那个版本，这个命令就"找不到"了。

它不是报错，是**静默缺失**：命令不在了，校验那一步跟着塌掉，而界面看上去一切正常。

现在改成直接用 .NET 自带的 sha256 算法自己算。任何环境都拿得到，不依赖模块自动加载。

## 三、macOS：上一版说明里写的两处修复，到这一版才真正发布

v1.1.8 的说明里写过 macOS 两处修复：端口读不出来时不再删你的代理变量、状态页说"读不出来"
而不是"没有代理在运行"。那两处代码到这一版才随发布出去。

**如果你用的是 v1.1.8，macOS 上这两处还没生效**，请升到这一版。

顺带把 macOS 侧端口枚举的兜底路径也补齐了：走 netstat 兜底时，如果 lsof 已经证明本机有端口
在监听、而 netstat 却解析出空表，那是"输出形状变了"而不是"没有端口"——这种情况以前会被当成
"本机没有监听端口"，现在会如实报"读不出来"。

## 兼容性

- 安装包名、下载直链、标签形状、发版流程都没变。
- 变量集合、注入与删除的判据、去抖与迟滞语义都没变。
- 变的只有上面三件：命令行开关用错位置会被明确拦住、Windows 侧校验值不再依赖模块、
  macOS 那两处修复到这一版才真正生效。

## 升级方式

打开菜单选 `5 检查更新`。
