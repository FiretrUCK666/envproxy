## v1.6.1：撤掉 NO_PROXY 里的方括号写法（它会让 httpx 每次请求都失败）

### 改了什么

默认例外集由 `localhost,127.0.0.1,::1,[::1]` 改回 `localhost,127.0.0.1,::1`：
IPv6 地址**裸写**。

### 为什么（实测，不是推论）

`NO_PROXY` 里 IPv6 有两种写法，但只有裸写是各家的共同规范，方括号写法会让 httpx 直接崩：

| `NO_PROXY` 取值 | httpx 0.28.1 实际发请求 |
| --- | --- |
| `localhost,127.0.0.1,::1` | 成功，HTTP 200 |
| `localhost,127.0.0.1,::1,[::1]` | 抛 `InvalidURL: Invalid port: ':1]'` |

带方括号时**每一次请求都失败**，不只是读环境变量时。根因在 httpx 自己的代码里：它把
`[::1]` 当成普通域名（只有裸写的 `::1` 才会走进它的 IPv6 分支），于是生成了非法匹配模式
`all://*[::1]`。而 httpx 的规范注释写得很清楚——它的示例就是
`NO_PROXY=example.com,::1,localhost,192.168.0.0/16`，方括号由它自己在构造模式时补上。

也就是说：**方括号是 URL 字面量的写法，放进 `NO_PROXY` 是写错了位置**，不是"另一种合法写法"。
上一版把它当成"两种写法都要覆盖"是判断错误，本次撤回。

对照实测（同一批环境变量下）：`requests` 对两种写法都正常；标准库 `urllib` 两种写法下
本机地址判定也都正常。只有 httpx 受影响，但影响面是"每一次请求"，代价远大于收益。

### 新增一条门禁，防止再犯

`tools/check-no-proxy.py`（只用 Python 标准库）做三件事，两个 CI 工作流都跑：

- 从两平台核心脚本里读出默认例外集，断言：不含方括号写法、含裸写 `::1`、含
  `localhost` 与 `127.0.0.1`、且两平台取值一致——源码里各只有一处定义，所以直接从
  源码读，不引入第三份副本；
- 用标准库验证 `127.0.0.1` 被判为直连；
- 起一个本地 HTTP 服务，对两种写法各真发一次请求，断言裸写成功、方括号失败。
  没装 httpx 的解释器则跳过这一项（不算失败），CI 里会先装上。

这条门禁已做变异验证：把默认值临时改回带方括号，门禁立刻以退出码 1 报错并指出文件与原因。

### 给已经装了 v1.6.0 的用户

环境里的 `[::1]` 不会被立刻清掉，但**不影响使用**：`NO_PROXY` 的清理只回收本工具写下的那一份，
当前值与本工具默认值不同，所以按"不动别人的东西"的规矩原样保留。想让环境回到规范写法，
把带方括号的那一项从 `NO_PROXY` 里删掉即可；不删也没有实际影响——httpx 崩的触发条件是
`NO_PROXY` 里存在方括号项，删掉它之后即恢复正常。
