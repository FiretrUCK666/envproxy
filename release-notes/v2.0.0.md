# v2.0.0

这一版把版本号重置，从 2.0.0 重新开始。它包含之前全部改动的累积，
外加几轮彻底的内部整理。

如果你之前装过任何旧版本，**建议更新到这一版**：下面列的这些问题，在旧版本里都真实存在过。

**2.1.0 与 2.1.1 已作废，内容并进这一版。** 那两个版本号从此不存在，
下面第五节「判定的依据」就是它们原本要讲的全部内容。

# 这一版的新东西

## 菜单 5 从「浏览器代理修复」变成「网络与代理修复」

以前它只看浏览器那一层设置。现在一次看三处，因为「连不上网」的原因根本不只在那一层：

- **终端工具自己的代理残留**。`git config --global http.proxy …` 和 `~/.npmrc` 里写死的地址，
  优先级高于本工具管的环境变量——所以会出现「浏览器好好的，只有 git 或 npm 连不上」。
  这一项现在会查出来，并按同一套判据修掉（本机地址 + 端口已死）。
- **网址解析的两处设置打架**。给「所有网络」设过 DNS、又给某一个 Wi-Fi 单独设过时，
  系统只用其中一处，另一处不生效——平时没有任何地方会告诉你。这一屏会点出来。
- **DNS 指向本机但没人应答**。翻墙软件改过系统 DNS 又没改回去时会出现。
  这一项**只提醒、不自动改**：改回自动获取之后路由器会给什么地址，改之前拿不到这个答案，
  猜错比原来的毛病更糟。

**还原点从单份变成事务日志**（`monitor/doctor.journal`）。以前只有一份、而且只写一次，
修第二处时会覆盖第一处的还原点。现在每次修复各留一份，留最近 5 次，按 `r` 撤销的是
**上一次**修复。旧的 `doctor.bak` 仍然能读，升级上来的人第一次按 `r` 就能用。

**固定入口（17099）现在也认 SOCKS 协议**。以前把它填进只发 SOCKS 握手的地方会卡十几秒
然后失败；现在同一地址 HTTP 和 SOCKS 都通，浏览器和那些工具都不用改设置。

## 1.0.0 的用户这次要手动升级一次

1.0.0 那版的更新校验只认它当时知道的那些文件，这一版多了一个文件，所以它会把自己的新包
判成「不合格」并拒绝。这不是这一版的毛病——它来自你手里那版代码，改不了。

**出路**：到项目页面下载这一版的安装包，解压覆盖到你现在放它的那个文件夹，
再双击「安装」一次。之后就恢复自动更新了。只影响从 1.0.0 直接跳过来的情况。

## 这一轮又修掉的几处

- **状态页与 Mac 侧的几处对齐**。状态页开头那句解释「这套设置管到谁」的话已删除，
  结论与下面的表格之间保留一个空行。
- **两端对同一批字符算出的显示宽度必须相等**。原来那道门禁在拿自己重写的规则跟自己比，
  所以两端对零宽字符（组合附加符、零宽连接符、变体选择符）早就算出不同结果也照样全绿。
  现在改成真跑两端的实现来比，并修好了 Mac 侧的两处偏差。
- **握手分类把 3xx 与 5xx 分开了**。以前两者都归「上游坏了」，于是某个普通网页服务回的
  重定向会被解释成「它是代理，但节点挂了」——方向错了。
- **快照读回来时行尾那个 CR 去掉了**。Windows 写的快照是 CRLF，按 `\n` 切完每行末尾
  还留一个 `\r`，`written` 那个时间戳永远对不上格式，整份快照被判「损坏」。
- **不再在快照缺失时认领使用者自己的本机代理**。装过却没有快照，只可能是「装前本机就没这个
  名字」或「快照写失败了」——后者不知道装前是什么，删掉就再也还原不回来。
- **`Global\` 锁不可用时降级到会话级锁**，并且把「建不出锁」与「锁被别人占着」分开说。
  以前两者都报「另一个安装正在进行」——当 `Global\` 不可用时那句话是假的，
  而安装、卸载、停止、更新四个动作会全部永久失败。
- **自启动自愈会先拿操作锁**。以前卸载刚删掉自启动项，监控的自愈恰好跑一轮又把它建回来，
  用户看到「卸了又回来了」。
- **更新失败且回滚未完成时不再跑旧代码重装**。安装区已经半新半旧，用旧代码去覆盖只会更乱。
- 登录定位器不再删 `proxy.env`，改为写 off 哨兵——删掉会让已开着的窗口失去归属记录，
  死代理永远清不掉。
- macOS：端口探活改成三态（在听 / 没在听 / 读不出来）；不再为每个候选端口各取一次时钟；
  两次更新失败不会再覆盖掉上一份备份。

# 判定的依据（原 2.1.0 与 2.1.1 的内容）

这一节回答一个问题：**工具凭什么说「正在翻墙」？**

原来的判据是：经本地代理端口访问 6 个检测网址，任意一个返回预期响应就算通过。
它漏掉了一种情况——**那个检测网址，不挂代理也能打开。**

「这个网址会不会被墙」不是网址自己的属性，而是「你这台机器的网络 + 翻墙软件的分流规则」
共同决定的。同一个网址在不同网络下答案可以完全相反。一旦碰上，后果是这样的：

- 翻墙软件的节点其实已经死了，真正被墙的网站一律连不上；
- 但某个检测网址在本地有服务器，直连就能通，走代理也「通」；
- 工具据此判定「翻墙中」，把这条死掉的代理写进每个终端的环境变量；
- **屏幕上全绿，终端里每条命令都失败。**

所以这一版把判据从「经代理能通」收紧成「经代理能通 **且** 不挂代理打不开」，
两个条件同时成立才算数。

## 三档，不是两档

「不挂代理打不开」这一半，判断结果有三种，不是两种：

- **确定打不开**——解析得出、直连本身也上着网、但这个网站拿不到回应。**只有这一种能当证据。**
- **直连就能通**——证明不了代理。
- **问不出来**——DNS 失败、整条直连不通、拿到不该回的回应。**一律不算证据。**

第三档是关键。把「问不出来」当成「被墙」，等于给坏代理发免费通行证：
你的 DNS 一时抽风、你连着机场和酒店的登录页网络、你的网慢到超时，这三种情况下
六个网址会全被判成「被墙」，于是一条对所有真网站都回 502 的死节点，
只要肯对某个检测网址回一个 204，就会被判成「正在翻墙」。屏幕全绿，终端全挂。

## 结论会过期

「这个网址在你这台机器上会不会被墙」的结论会缓存，但**不再永久有效**：

- 有效期 10 分钟，到点重问；
- 带**网络指纹**（默认网关 + 本机 IP）——换 Wi-Fi、插拔网线、开关 TUN、改分流规则，
  指纹一变就重问；
- 「问不出来」不进缓存，下次再问。

不这么做的话，开机那一瞬间网络还没起来、六个网址全判「被墙」，这个错误结论会永久生效，
之后你换了节点、节点死了，工具照样报「正常」，直到你重启电脑。

## 开了 TUN 的人：退回旧规矩，而不是判死

如果你的代理软件开了 TUN（虚拟网卡接管全部流量），六个检测网址全都能「直连」打开
——于是一个证据都没有，**一个正常工作的代理会被判成「没在翻墙」**，而且不会自愈。

所以六个全「直连可达」被认定为一个明确信号：**这套判据在你的机器上失效了。**
这时退回旧规矩（拿到回应就算通），并在日志里写一句：

```
本机所有检测网址不挂代理也能打开（多半是虚拟网卡接管了全部流量）-> 回到旧判据：经代理拿到回应就算通
```

反过来，六个全「问不出来」时**绝不退回**——那会让死节点靠随便一个 204 重新骗过判决。

## 代价

- 每个检测网址多做一次不挂代理的访问，每个进程只做一次然后缓存。第一次判断多花约 1 秒。
- 慢网（3G、卫星、拥塞）下最多多花 2 到 3 秒：直连探测每个网址最多等 2.5 秒。
- **TUN 场景下这套判据不生效**（会退回旧规矩），也就是说「死节点被判活」的风险
  在 TUN 场景下仍然存在。这是取舍：宁可回到旧行为，也不能把一个好代理判死。

这一版让工具不再「把坏代理说成好的」，但它**修不了翻墙软件本身**。
节点域名消失、订阅过期之类的问题发生时，工具的表现是如实报「代理不通」，
而不是假装一切正常——这时候该去处理翻墙软件那边。

## 自己查一下

看程序目录下的 `monitor\monitor.log`（Windows）或 `~/.envproxy/monitor.log`（macOS）。
如果里面有「本机所有检测网址不挂代理也能打开」，说明判据在你的机器上本来就是降级状态。

# 第一部分：会让你丢东西的

## 跑一次自检，你的用户环境变量可能被整个删掉

这是本次最严重的一条。

自检（`tests\test-win-pure.ps1`）为了不碰你真实的环境变量，会建一批临时注册表键当"沙箱"，
跑完再删。问题出在有一个用例文件在**跑到一半**就把沙箱拆了、把变量指回了真实位置——
而它后面还有用例要跑。

等全部跑完、外层去清沙箱时，它读到的是**真实路径**，于是把当前用户整个
`HKCU\Environment` 删空。`PATH`、`TEMP` 连同代理变量一起没了。

后台监控每 30 轮自愈一次，发现代理变量消失就重新写回，日志里于是反复出现
「变量被人改坏了」——**症状离根因太远，一直没人往测试上想**。

现在分两处修：用例文件不再碰沙箱的拆装；外层加了护栏，删之前先确认"这些键确实是本次沙箱"，
变量被改坏时一个字节都不删，并且明确报出来。

## 卸载失败却报「成功」

在没有可交互终端的场合（脚本里调用、计划任务里跑），卸载会拒绝执行——这是对的，
它不能替你做决定。但它返回的退出码是 0，意思是「成功」。

后果不是显示问题：`envproxy.ps1 -Uninstall; if ($?) { 删掉备份 }` 这类脚本会以为
卸干净了，然后去删掉唯一一份还能还原的备份。

## Windows 停止监控失败时不报错

屏幕会如实打一行「监控进程未能停止」，但退出码仍然是 0。所以
`envproxy.ps1 -Stop; if ($?) { 关机 }` 这类脚本会带着一个还在跑的后台程序往下走。
macOS 那边早就是 1 了——两边本来该一样。

## macOS 的「网络救援」修不了任何东西

它读数据时漏了一列，于是每一条记录都被判成「认不出是什么」，全部跳过。

更糟的是界面上的说法：它会把这件事说成「查的时候还在，动手的时候已经没了
（可能是你自己关掉了）」——把我们自己的解析错误赖给了使用者。

# 第二部分：会让工具说假话的

这个项目最想消灭的就是「看起来正常、实际是错的」。

## 屏幕上印出「选 选 1（安装 / 修复）」

菜单项的完整名字已经自带「选」字，而调用它的地方又各加了一个，于是屏幕上真的
印出两个。会看到它的地方：卸载前的确认提示、几条出错提示。

## 状态页两版说法相反

状态页有两种看法：等它自己刷新，或者按回车看一屏静态的。同一个状态，这两处
曾经会给出相反的颜色和结论。典型的是「代理变量还在，但后台程序已经停了」：

```
实时刷新看到的那一版：已注入 (http://127.0.0.1:7078)     绿色，像一切正常
按回车看到的那一版：  已注入（…），但没人维护            黄色 + 终端会连不上
```

上面那句是实话。现在两版从同一张表取结论和说明。

## 同一个程序在两个平台显示成不同的客户端

客户端识别表里，`stash` 和 `quantumult` 在 Windows 侧被归到 Clash 系，在 macOS 侧被归到
Surge 系。而 Surge 那条的名字上明明写着「Surge / Stash」。

后果不是崩溃，是"同一个程序在 Mac 上叫这名、在 Windows 上叫那名"，而门禁一直全绿
——因为它只比对两边的进程名加起来是不是同一批（两边都有 stash，所以相等），**归属差异看不见**。

现在两侧统一，并且门禁改成按条目逐行比对（名字、端口、进程名三项）。

## 探测可能卡十几秒

Windows 侧判断"本机某个端口还在不在"时，连上之后要拿这条连接做一次代理握手。
原来用的是同步连接加两个超时参数——但那两个参数只管**连上之后**的读写，管不了连接本身。

所以当某个本机端口处于半开状态（不回拒绝包，也不回同意包）时，这一连会一直等下去，
直到系统级 TCP 超时才放手。实测对照：连一个不可达地址，旧写法 **21 秒**，
新写法 **0.3 秒**，差 62 倍。而监控每轮都要探测，卡住的直接后果是状态翻转明显变慢，
屏幕上看不出异常。

## macOS 的后台程序会在第一次注入代理时崩掉

macOS 版第一次成功注入代理、要写日志的那一行，引用了一个在那时并不存在的变量。
开了严格模式之后，这一行会直接把后台程序打死。

它麻烦的地方在于症状里没有线索：代理通了、后台程序无声消失、日志里一条错误都没有。

## macOS 侧：一个会让菜单崩掉的错

macOS 上选「网络救援」，屏幕上会闪过一行 `clear_screen_safe: command not found`，
然后页面内容错乱。原因是这个函数被写在另一个函数的**里面**，只有那个函数被调用过
之后它才存在。而「网络救援」是第一个用它的地方。

## 探测代理时会漏掉 IPv6

判断「本机有没有代理在跑」时，macOS 侧的一部分检查写死了 `127.0.0.1`，只试 IPv4。
如果有人的代理只绑了 IPv6 回环（`::1`），这台机器就会被判定成「没有代理」，而且**不报任何错**。
现在两侧都按 `127.0.0.1` → `::1` 的顺序试。

## macOS 判定端口活着的方法会误判

macOS 侧判断「这个端口还在不在」用的是 `curl`。问题是 `curl` 会真的去建一条隧道
——连一个必然失败的地址，`curl` 返回非零，于是**活着的端口被判成死的**。
现在改用 shell 自带的 `/dev/tcp`，只连 TCP 不建隧道。

## macOS 卸载后桌面上留下删不掉的图标

Windows 侧卸载时会问「那些程序图标留不留」，macOS 侧**根本没问，也没删**——桌面上的
图标留下来了，而它们指向的程序已经被卸载掉，双击没有任何反应。

更麻烦的是卸载完的检查也发现不了：它只检查运行时文件，不检查图标。

## macOS 图标名里带着一串看不懂的乱码

给程序建图标时，为了区分「同一个程序的走代理版和直连版」，内部用一段哈希值做身份。
但那串哈希**直接印在了图标名上**，桌面上看到的是 `Antigravity_a3f9c1e2（翻墙）.app`
这种名字——用户完全没法照着念。Windows 侧一直是干净的。

顺带修好了「确认页显示的图标名」和「实际建出来的图标名」不一致的问题。

# 第三部分：界面

## 不再「一屏一个样」

以前同一个屏幕上能同时出现三种长度的横线。状态页最明显：顶部标题、中间的「最近日志」、
底部收尾，三根线宽度分别是 29 / 38 / 34 个字符，看起来像三个不相关的部件拼在一起。

现在规则只有一条：**一屏之内所有横线一样宽**，宽度由标题决定，不够宽就补到 40 列。
全站十几个页面用的是同一个函数，改一次全部生效。

## 退出提示统一说法

以前「怎么离开这一屏」有八种写法：

`0 = 返回主菜单`、`0 = 返回`、`按回车返回`、`按回车继续`、`按回车回菜单`、
`（按回车返回）`、`按 0 或 Esc 返回`、`看完按回车返回`

现在按「回到哪里」分三档，措辞只有一个来源。而且每一句都同时说清两件事：
**按什么键**、**回到哪里**。

## 高级功能页的三大块分开了

「给某个程序定规矩」「浏览器上不了网的时候」「本工具管不到的地方」这三块，
以前只靠一个小标题区分，中间没有视觉边界。现在块与块之间有一条分隔线。

# 第四部分：性能与内部整理

**状态页每 2 秒白烧一次扫描。** 统计桌面快捷方式数量要扫一遍磁盘，实测约 112 毫秒。
两处渲染各扫一次，而它们要的只是同一个数字。现在一帧只扫一次，单帧渲染从 120 毫秒
降到 29 毫秒。

**Git Bash 的钩子不再手抄变量清单。** 原本手抄了三份（哪些算我们的、大小写怎么对应、
怎么清除），和真正的变量表是两处独立的事实——将来加第 6 个变量时漏改任何一处都不报错，
只是那个变量在 Git Bash 里永远清不掉。现在三份都从同一张表生成。

**`curl_direct` 一直在丢参数。** 转发选项时少写了一个 `--`，`curl` 的选项被 `env`
当成了自己的选项，报错直接退出，**命令一次都没跑过**。影响三处核心探测。

**探测 `nc` 有没有某个开关时，没先问「命令存在吗」。** 机器上没装 `nc` 时它会判成
「支持」，之后每次调用都失败。

**macOS 卸载不清快捷方式、日志定位器排序错误**（端口 9 和 10 会排反）、
**两处死代码**、**若干硬编码的变量名**，都已清理。

# 升级方式

打开菜单选「1 安装 / 修复」，或者直接用安装包覆盖。配置文件、快照、运行日志都不会丢。

**如果你怀疑自己的环境变量已经受损**：走一遍「1 安装 / 修复」会重新写回代理变量；
`PATH`、`TEMP` 这些系统变量如果被删了，需要手工补回或在系统设置里恢复。
新版本的自检不会再动它们。
