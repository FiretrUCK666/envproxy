# v2.0.0

这一版把版本号重置，从 2.0.0 重新开始。它是之前全部改动的累积，
外加一轮彻底的内部整理。

如果你之前装过某个旧版本，建议更新到这一版：下面列的这些问题，在旧版本里都真实存在过。

## 几个会让工具说假话的问题

这个项目最想消灭的就是「看起来正常、实际是错的」。这一轮修掉了几处。

### 屏幕上印出「选 选 1（安装 / 修复）」

菜单项的完整名字已经自带「选」字，而调用它的地方又各加了一个，于是屏幕上真的
印出两个。会看到它的地方：卸载前的确认提示、几条出错提示。

### 卸载失败却报「成功」

在没有可交互终端的场合（脚本里调用、计划任务里跑），卸载会拒绝执行——这是对的，
它不能替你做决定。但它返回的退出码是 0，意思是「成功」。

后果不是显示问题：`envproxy.ps1 -Uninstall; if ($?) { 删掉备份 }` 这类脚本会以为
卸干净了，然后去删掉唯一一份还能还原的备份。

### 状态页两版说法相反

状态页有两种看法：等它自己刷新，或者按回车看一屏静态的。同一个状态，这两处
曾经会给出相反的颜色和结论。典型的是「代理变量还在，但后台程序已经停了」：

```
实时刷新看到的那一版：已注入 (http://127.0.0.1:7078)     绿色，像一切正常
按回车看到的那一版：  已注入（…），但没人维护            黄色 + 终端会连不上
```

上面那句是实话。现在两版从同一张表取结论和说明。

### macOS 的后台程序会在第一次注入代理时崩掉

macOS 版第一次成功注入代理、要写日志的那一行，引用了一个在那时并不存在的变量。
开了严格模式之后，这一行会直接把后台程序打死。

它麻烦的地方在于症状里没有线索：代理通了、后台程序无声消失、日志里一条错误都没有。

### macOS 的「网络救援」修不了任何东西

它读数据时漏了一列，于是每一条记录都被判成「认不出是什么」，全部跳过。

更糟的是界面上的说法：它会把这件事说成「查的时候还在，动手的时候已经没了
（可能是你自己关掉了）」——把我们自己的解析错误赖给了使用者。

## 顺手修的几件

**状态页每 2 秒白烧一次扫描。** 统计桌面快捷方式数量要扫一遍磁盘，实测约 112 毫秒。
两处渲染各扫一次，而它们要的只是同一个数字。现在一帧只扫一次，单帧渲染从 120 毫秒
降到 29 毫秒。

**macOS 的帮助页面挤在一起。** 终端里看到的那一份少了一道排版，段落之间没有空行。

**macOS 的问题报告比 Windows 少两节。** 少了「网络体检」和「后台程序快照」，
而帮助里明明写着「报告里已经有网络体检的结论」。

**macOS 卸载的退出码和 Windows 相反。** 这一条路径恰恰是自动化脚本最常走的那条。

**菜单影响的那张对照表有几格是错的。** 「检查更新」那一行画的是「什么都不碰」，
实际上它装完新版之后会重跑一次安装收尾，自启、监控、变量、定位器都会被重新处理。

## 内部整理（使用者感觉不到）

- Windows 侧从 12 个库变成 14 个：拆出了 `screen`（画屏幕的那一层）和 `report`
  （唯一会写文件、会问问题的那一层）。后者拆出去之后，「状态页只读不问」这条约定
  看一眼文件名就有答案，不再只靠一句注释守着。
- 两个平台的状态页标签收进唯一一张常量表，并加了门禁逐项比对。
- 「平台差异必须有标注」这条规矩以前没人检查，现在有门禁了。
- 菜单影响的那张对照表改成由脚本生成：九行五列共 45 格，手写时改一处漏一处。

## 验证

- 两平台的完整门禁全部通过（15 道）
- Windows 自检在 PowerShell 5.1 与 7 上各跑一遍，都过
- macOS 自检通过
- 结构调整用输出逐字节比对证明没改变任何屏幕上会出现的内容

## 升级方式

打开菜单选「3 检查更新」，或者直接用安装包覆盖。配置文件、快照、运行日志都不会丢。

## 关于版本号

之前的 2.0.x / 2.1.0 / 2.2.x 全部作废，标签与发布记录已删除，从这一版起重算。
唯一的例外是 1.0.0，它保留着，作为这个项目最早的一份记录。
