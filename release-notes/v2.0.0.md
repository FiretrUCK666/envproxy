# v2.0.0

菜单多了一个「帮助」，文档按普通人的理解方式重写了一遍。

标成 2.0 是因为文档几乎全改了：结构、说法、例子。程序行为没有破坏性变化，老版本升级上来不会有任何不适。

## 新的：6 帮助

装完放着不管，过几个月想改点什么，往往想不起来命令怎么写。现在打开菜单选 `6`，一屏看完：常用命令、三种窗口的区别、几个容易踩的坑。

也可以在终端直接调：

- Windows：`powershell -ExecutionPolicy Bypass -File envproxy.ps1 -Help`
- macOS：`bash envproxy.sh help`

帮助里写全了这些东西：

- 装完会发生什么，三种窗口分别怎么处理
- 为什么开着的窗口要按一次回车（讲清原理，不是让你死记）
- 每条常用命令，以及它只影响当前窗口
- 让某一条命令不走代理时，`curl`、`git`、`npm`、`wget`、`docker` 各怎么写
- `. $PROFILE` 是在做什么，开头的点号为什么不能少，适用于哪些 shell
- 菜单另外几项分别是干什么的
- 日志在哪、多大、写满怎么处理
- 觉得不对劲时该点哪个

## 修的功能问题

### 菜单可能少印一项

菜单的显示和它接受的编号以前是两份清单，加功能容易只改一处。现在共用一张表，加一项就一定显示出来。

### 帮助里的命令在 Windows 上跑不起来

帮助里写 `curl --noproxy "*"`，在 PowerShell 里这条是错的：`curl` 被当成了 `Invoke-WebRequest` 的别名。现在写 `curl.exe`。

### 一条测试是假的

「会不会误删你自己的代理」这段有四条断言，但它准备的数据有问题，四条走的其实是同一个分支：把判断逻辑整段删掉，它们照样全过。现在每条都摆好真实状态、只改被测那一项，也验证过故意改坏会立刻报红。

### 状态显示其实会写日志

「查看状态」承诺只读、不改任何东西，但它会快扫一次端口，而扫描失败时顺手往 `monitor.log` 里写了一行。现在这条路径不再落盘，跑多少次状态都不动文件。

### 开机自启失效了还报「已启用」

卸载不彻底、或者你手动删过文件夹时，自启记录还在，但它指向的启动文件已经不在了，登录时什么都不会起来，状态页却照样报「已启用」。现在会判「记录还在，但启动文件已不存在」，并告诉你怎么重建。

### 升级会把你的配置行尾改掉

改写 `$PROFILE` 时用的是「按行写」，行尾固定成 CRLF，于是 LF 保存的配置文件被悄悄改成 CRLF。功能不受影响，但会污染你的 diff 和仓库的行尾约定。现在沿用原文件的行尾。

### 程序文件损坏时会静默失败

`.ps1` 如果被存成「UTF-8 无 BOM」，中文 Windows 上的 PowerShell 5.1 会把中文注释读成乱码、撑破语法，整个程序起不来。以前这种情况是「什么都不打印、退出码 0」，计划任务会把它当成成功。现在启动时先解析一遍，解析不过就明说哪个文件、什么原因，退出码 1。

## 升级

打开菜单选 `5 检查更新`，同意就装。不用为升级开翻墙软件。

只替换程序文件，你的日志、`monitor\` 里的运行标记都不动。
