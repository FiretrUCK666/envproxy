# v2.0.0

这一版加了**固定入口**：一个永不变更的本地地址，让那些把代理地址记进自己设置里的程序不再因为翻墙软件换端口而失效。

同时修掉了一批**会让状态页说假话**的问题——它们不报错、不崩溃，只是安静地显示错误的信息，而那比直接坏掉更难发现。

> 版本号说明：这是重新整理后的一版，版本号从 2.0.0 重新开始。功能上它包含此前所有累积改动，装它不用管旧版号。

## 固定入口（新功能，仅 Windows）

**它解决什么。** 有些程序会把你给的代理地址写进它自己的配置里，之后就认那一个。翻墙软件一换端口，那些程序就连不上，而你还得去它的设置里手动改一遍——每次换端口都要改一遍。

**它怎么做。** 建图标时自动用一个永不改变的本地地址（`http://127.0.0.1:17099`）代替真实端口。程序记的是这个固定地址，背后自动跟着翻墙软件走。你什么都不用做，也没有开关要拨。

**看它在干什么。** 高级功能页多了「3 查看中继」，那一屏会实时显示入口地址、当前转发到哪个端口、工作状态。翻墙软件换了端口、关了又开，那一屏会自己跟着变，不用退出重进。

**它没在工作也不要紧。** 图标会退回去读当前代理地址，照样能用。

**macOS 没有这一项。** 它需要在一个进程里同时做"接受连接"和"转发"，macOS 侧的 bash 没有这种能力（Windows 侧用的是系统自带的 .NET 类型，不引入任何依赖）。macOS 侧沿用原来的做法：每次启动读当前代理，换端口后重开一次图标即可。

## 修掉的状态页问题

**关掉翻墙软件后，状态页会一直说"已开启"。** 这不是显示慢，是探测层的判断错了：它在"这一轮没看见端口"时一律报告"不知道"，而"不知道"不计入"连续两轮确认"，于是状态永远翻不过来。屏幕上会同时出现"已开启""端口已不在""正在确认"三句互相矛盾的话，十几分钟不消失。Windows 与 macOS 都有这个问题，一起修了。

**同一条故障还有第二个入口。** 端口探测偶尔失败一次，就会把已经攒下的"待确认"证据清零，于是永远凑不满两轮。这条也修了，两侧同改。

**两种刷新方式看到的东西不一样。** 「查看状态」和「实时刷新」本来是两套画法。同一台机器上按回车看到 8 行、等它自己刷新看到 6 行，缺的正好是"上次更新没完成""系统代理可能残留"这两段的**处理办法**。现在两版逐项一致，并且有回归用例逐条比对，改一版漏另一版会立刻被抓住。

**macOS 上"代理变量被改坏"从来不报。** 后台每轮都在算"变量和当前状态对不对得上""变量写进去了没有"，但那边算了不显示——变量被别的程序改掉时，状态页仍然说"一切正常"，而终端其实连不上。现在会报进"有 N 项要注意"。

**macOS 的配色亮了一档**，与 Windows 一致。原来那边用的是暗色档，同屏"绿字=能整行复制去跑"这个识别线索被削弱了。

**macOS 卸载会多删一个文件**（`notify.last`）。它记着"上次提示过代理变了"，卸载时不删，重装后第一次真的换端口会什么提示都没有。

## 修掉的判断错误

**交接握手把 `2000` 当成了成功。** 判断"这个端口是不是代理"靠发一个 CONNECT 请求看回应，判据原来是"以 200 开头"，于是 `HTTP/1.1 2000` 也能通过。现在要求状态码整段相等，两侧同改。

**固定入口的状态读错了进程。** 「查看中继」跑在独立进程里，而中继跑在监控进程里，判据读的是后者内存里的对象——于是中继明明在跑，界面永远显示"没在工作"。改成读落盘的端口文件 + 发一个专用探针。

**只监听 IPv6 回环的代理会完全走不通固定入口。** 这类配置（mihomo / sing-box 的 `bind-address: "::1"`）在终端里一切正常，但走固定入口百分百失败，用户只会觉得"某个软件坏了"。现在按地址族连接，两个回环地址都试。

**并发一高就卡。** 原来每条连接都占着共享线程池，而线程池超过初始大小后补线程很慢。实测 50 条并发时最后一条要等 22 秒——浏览器一个页面就有几十条连接。现在每条连接一个专属线程，同样 50 条并发，最后一条 58 毫秒。

**请求头被拆成两段就整条失败。** 原来只读一次就当完整头，客户端分两次写出（很常见）或者 Cookie 很大时，会把半截头转给上游，然后客户端挂满超时才收到错误。现在读到空行为止。

**换端口时有极小概率整个功能起不来。** 原来选端口是"先试绑一次、放手、再绑一次"，两步之间被别的程序抢走就直接放弃，而旁边还有十几个空闲端口。现在一次绑到底，失败就换下一个。

**中继自己挂了不会自动恢复。** 监听线程异常退出后，它自己还以为在跑，状态检查也以为在跑，于是没人去重建它——图标还能点，但永远不走代理。现在主循环每轮确认它活着，死了就重建。

## 验证

两侧自检全绿。这一版新增的回归用例都做了"故意改坏代码确认它会红"的验证：

- 9 个真实使用场景的组合行为（正常开着 / 关掉 / 换成表外端口 / 两个软件同时开 / 首次启动 / 换端口 / 端口被非代理程序占着）
- 11 条握手判据（哪些应答才算代理）
- 两版状态页输出逐项比对（含"删掉一段就报红"的反向验证）
- 中继的并发、分片请求头、IPv6 上游、状态探针、端口释放

Windows 与 macOS 的判据、阈值、文案在这一版里逐项核对过。
