# v2.0.0

这一版把版本号重置，从 2.0.0 重新开始。它包含之前全部改动的累积，
外加几轮彻底的内部整理。

如果你之前装过任何旧版本，**建议更新到这一版**：下面列的这些问题，在旧版本里都真实存在过。

---

# 第一部分：会让你丢东西的

## 跑一次自检，你的用户环境变量可能被整个删掉

这是本次最严重的一条。

自检（`tests\test-win-pure.ps1`）为了不碰你真实的环境变量，会建一批临时注册表键当"沙箱"，
跑完再删。问题出在有一个用例文件在**跑到一半**就把沙箱拆了、把变量指回了真实位置——
而它后面还有用例要跑。

等全部跑完、外层去清沙箱时，它读到的是**真实路径**，于是把当前用户整个
`HKCU\Environment` 删空。`PATH`、`TEMP` 连同代理变量一起没了。

后台监控每 30 轮自愈一次，发现代理变量消失就重新写回，日志里于是反复出现
「变量被人改坏了」——**症状离根因太远，一直没人往测试上想**。

现在分两处修：用例文件不再碰沙箱的拆装；外层加了护栏，删之前先确认"这些键确实是本次沙箱"，
变量被改坏时一个字节都不删，并且明确报出来。

## 卸载失败却报「成功」

在没有可交互终端的场合（脚本里调用、计划任务里跑），卸载会拒绝执行——这是对的，
它不能替你做决定。但它返回的退出码是 0，意思是「成功」。

后果不是显示问题：`envproxy.ps1 -Uninstall; if ($?) { 删掉备份 }` 这类脚本会以为
卸干净了，然后去删掉唯一一份还能还原的备份。

## Windows 停止监控失败时不报错

屏幕会如实打一行「监控进程未能停止」，但退出码仍然是 0。所以
`envproxy.ps1 -Stop; if ($?) { 关机 }` 这类脚本会带着一个还在跑的后台程序往下走。
macOS 那边早就是 1 了——两边本来该一样。

## macOS 的「网络救援」修不了任何东西

它读数据时漏了一列，于是每一条记录都被判成「认不出是什么」，全部跳过。

更糟的是界面上的说法：它会把这件事说成「查的时候还在，动手的时候已经没了
（可能是你自己关掉了）」——把我们自己的解析错误赖给了使用者。

# 第二部分：会让工具说假话的

这个项目最想消灭的就是「看起来正常、实际是错的」。

## 屏幕上印出「选 选 1（安装 / 修复）」

菜单项的完整名字已经自带「选」字，而调用它的地方又各加了一个，于是屏幕上真的
印出两个。会看到它的地方：卸载前的确认提示、几条出错提示。

## 状态页两版说法相反

状态页有两种看法：等它自己刷新，或者按回车看一屏静态的。同一个状态，这两处
曾经会给出相反的颜色和结论。典型的是「代理变量还在，但后台程序已经停了」：

```
实时刷新看到的那一版：已注入 (http://127.0.0.1:7078)     绿色，像一切正常
按回车看到的那一版：  已注入（…），但没人维护            黄色 + 终端会连不上
```

上面那句是实话。现在两版从同一张表取结论和说明。

## 同一个程序在两个平台显示成不同的客户端

客户端识别表里，`stash` 和 `quantumult` 在 Windows 侧被归到 Clash 系，在 macOS 侧被归到
Surge 系。而 Surge 那条的名字上明明写着「Surge / Stash」。

后果不是崩溃，是"同一个程序在 Mac 上叫这名、在 Windows 上叫那名"，而门禁一直全绿
——因为它只比对两边的进程名加起来是不是同一批（两边都有 stash，所以相等），**归属差异看不见**。

现在两侧统一，并且门禁改成按条目逐行比对（名字、端口、进程名三项）。

## 探测可能卡十几秒

Windows 侧判断"本机某个端口还在不在"时，连上之后要拿这条连接做一次代理握手。
原来用的是同步连接加两个超时参数——但那两个参数只管**连上之后**的读写，管不了连接本身。

所以当某个本机端口处于半开状态（不回拒绝包，也不回同意包）时，这一连会一直等下去，
直到系统级 TCP 超时才放手。实测对照：连一个不可达地址，旧写法 **21 秒**，
新写法 **0.3 秒**，差 62 倍。而监控每轮都要探测，卡住的直接后果是状态翻转明显变慢，
屏幕上看不出异常。

## macOS 的后台程序会在第一次注入代理时崩掉

macOS 版第一次成功注入代理、要写日志的那一行，引用了一个在那时并不存在的变量。
开了严格模式之后，这一行会直接把后台程序打死。

它麻烦的地方在于症状里没有线索：代理通了、后台程序无声消失、日志里一条错误都没有。

## macOS 侧：一个会让菜单崩掉的错

macOS 上选「网络救援」，屏幕上会闪过一行 `clear_screen_safe: command not found`，
然后页面内容错乱。原因是这个函数被写在另一个函数的**里面**，只有那个函数被调用过
之后它才存在。而「网络救援」是第一个用它的地方。

## 探测代理时会漏掉 IPv6

判断「本机有没有代理在跑」时，macOS 侧的一部分检查写死了 `127.0.0.1`，只试 IPv4。
如果有人的代理只绑了 IPv6 回环（`::1`），这台机器就会被判定成「没有代理」，而且**不报任何错**。
现在两侧都按 `127.0.0.1` → `::1` 的顺序试。

## macOS 判定端口活着的方法会误判

macOS 侧判断「这个端口还在不在」用的是 `curl`。问题是 `curl` 会真的去建一条隧道
——连一个必然失败的地址，`curl` 返回非零，于是**活着的端口被判成死的**。
现在改用 shell 自带的 `/dev/tcp`，只连 TCP 不建隧道。

## macOS 卸载后桌面上留下删不掉的图标

Windows 侧卸载时会问「那些程序图标留不留」，macOS 侧**根本没问，也没删**——桌面上的
图标留下来了，而它们指向的程序已经被卸载掉，双击没有任何反应。

更麻烦的是卸载完的检查也发现不了：它只检查运行时文件，不检查图标。

## macOS 图标名里带着一串看不懂的乱码

给程序建图标时，为了区分「同一个程序的走代理版和直连版」，内部用一段哈希值做身份。
但那串哈希**直接印在了图标名上**，桌面上看到的是 `Antigravity_a3f9c1e2（翻墙）.app`
这种名字——用户完全没法照着念。Windows 侧一直是干净的。

顺带修好了「确认页显示的图标名」和「实际建出来的图标名」不一致的问题。

# 第三部分：界面

## 不再「一屏一个样」

以前同一个屏幕上能同时出现三种长度的横线。状态页最明显：顶部标题、中间的「最近日志」、
底部收尾，三根线宽度分别是 29 / 38 / 34 个字符，看起来像三个不相关的部件拼在一起。

现在规则只有一条：**一屏之内所有横线一样宽**，宽度由标题决定，不够宽就补到 40 列。
全站十几个页面用的是同一个函数，改一次全部生效。

## 退出提示统一说法

以前「怎么离开这一屏」有八种写法：

`0 = 返回主菜单`、`0 = 返回`、`按回车返回`、`按回车继续`、`按回车回菜单`、
`（按回车返回）`、`按 0 或 Esc 返回`、`看完按回车返回`

现在按「回到哪里」分三档，措辞只有一个来源。而且每一句都同时说清两件事：
**按什么键**、**回到哪里**。

## 高级功能页的三大块分开了

「给某个程序定规矩」「浏览器上不了网的时候」「本工具管不到的地方」这三块，
以前只靠一个小标题区分，中间没有视觉边界。现在块与块之间有一条分隔线。

# 第四部分：性能与内部整理

**状态页每 2 秒白烧一次扫描。** 统计桌面快捷方式数量要扫一遍磁盘，实测约 112 毫秒。
两处渲染各扫一次，而它们要的只是同一个数字。现在一帧只扫一次，单帧渲染从 120 毫秒
降到 29 毫秒。

**Git Bash 的钩子不再手抄变量清单。** 原本手抄了三份（哪些算我们的、大小写怎么对应、
怎么清除），和真正的变量表是两处独立的事实——将来加第 6 个变量时漏改任何一处都不报错，
只是那个变量在 Git Bash 里永远清不掉。现在三份都从同一张表生成。

**`curl_direct` 一直在丢参数。** 转发选项时少写了一个 `--`，`curl` 的选项被 `env`
当成了自己的选项，报错直接退出，**命令一次都没跑过**。影响三处核心探测。

**探测 `nc` 有没有某个开关时，没先问「命令存在吗」。** 机器上没装 `nc` 时它会判成
「支持」，之后每次调用都失败。

**macOS 卸载不清快捷方式、日志定位器排序错误**（端口 9 和 10 会排反）、
**两处死代码**、**若干硬编码的变量名**，都已清理。

- Windows 侧从 12 个库变成 14 个：拆出了 `screen`（画屏幕的那一层）和 `report`
  （唯一会写文件、会问问题的那一层）。
- 两个平台的状态页标签收进唯一一张常量表，并加了门禁逐项比对。
- 菜单影响的那张对照表改成由脚本生成：九行五列共 45 格，手写时改一处漏一处。
- 门禁从 15 道增加到 17 道，新增的两道专门盯「代码里有、屏幕上看不见」的死角。

# 验证

- 两平台的完整门禁全部通过（17 道）
- Windows 自检在 PowerShell 5.1 与 7 上各跑一遍，都过
- macOS 自检通过（688 项断言）
- 实测确认：修复前每跑一次自检就新增一条「变量被人改坏了」的日志；修复后 0 新增
- 实测确认：连接超时从 21 秒降到 0.3 秒
- 结构调整用输出逐字节比对证明没改变任何屏幕上会出现的内容

# 升级方式

打开菜单选「1 安装 / 修复」，或者直接用安装包覆盖。配置文件、快照、运行日志都不会丢。

**如果你怀疑自己的环境变量已经受损**：走一遍「1 安装 / 修复」会重新写回代理变量；
`PATH`、`TEMP` 这些系统变量如果被删了，需要手工补回或在系统设置里恢复。
新版本的自检不会再动它们。
