翻墙软件只管浏览器，不管终端。`git`、`npm`、`curl` 这类工具靠一组叫「环境变量」的设置知道代理的地址，才连得上外面。

EnvProxy 自动维护这组设置。翻墙软件开着，它把代理地址写进去；关掉，它删掉。日常不需要记任何命令。

## 0. 装完之后会发生什么

装完之后多数情况什么都不用做。分三种，只有第三种需要动手。

| 你的情况 | 会发生什么 | 需要做什么 |
|---|---|---|
| **装完之后打开的窗口或程序** | 启动时读到的就是当前状态 | **什么都不用做** |
| **装完之后打开，后来代理又变了** | 需要重新读一次状态 | 按一次回车，或随便运行一条命令 |
| **装之前就打开的窗口** | 安装时同步脚本没有加载进去 | 重新打开一次，或手动加载一次 |

### 为什么已经打开的窗口要按一次回车

环境变量是每个程序启动时从系统读一份，读完就固定在这份副本里。之后系统里的值变了，已经在运行的程序不会跟着变。

所以新打开的窗口读到的总是当前值，已经打开的窗口读到的还是它启动那一刻的值。要让旧窗口跟上，只能让它重新读一次。

EnvProxy 会在每次命令执行完、终端重新显示提示符的时候读一次状态。提示符就是等着你输入命令的那串字符，比如 `C:\Users\你的名字>` 或 `$`。每次执行完命令，它都会重新出现，所以这个时机不需要额外操作。

### 关于 AI 工具、编辑器、IDE

它们启动终端时通常会新开一个进程，新进程读到的是当前的环境变量，所以不需要做任何事。

有两种情况需要重启那个工具：它在安装 EnvProxy 之前就已经打开；或者它是常驻后台的服务，不随用随开。判断方法很简单，连不上就重启它一次。

## 1. 安装（3 步，5 分钟）

1. 点 **[这里下载 Windows 版安装包](https://github.com/FiretrUCK666/envproxy/releases/latest/download/EnvProxy-win.zip)**（Mac 版点 [`EnvProxy-mac.tar.gz`](https://github.com/FiretrUCK666/envproxy/releases/latest/download/EnvProxy-mac.tar.gz)）
2. 解压到任意位置，文件夹可以改名。进入 `win` 文件夹双击 **`打开菜单.cmd`**（Mac 进入 `mac` 双击 **`打开菜单.command`**），再选 **`1 安装 / 修复`**
3. 看到「监控进程：已启动」就装好了

安装会做五件事：把已有同名环境变量的值存一份（卸载时用来还原）、注册开机自动启动、往终端的启动配置里加一段脚本（Windows 是 PowerShell 的 `$PROFILE`，5.1 和 7 两个位置都写；Mac 是 shell 的 rc 文件）、启动监控、立即校正一次环境变量。屏幕上会逐步显示进度（Windows 4 步、Mac 3 步，快照合并在第 1 步里）。

<img src="./assets/readme/first-run.svg" width="100%" alt="安装三步：下载对应平台的包 → 双击打开菜单选 1「安装 / 修复」→ 看到「监控进程：已启动」；下方并排对比：装完之后新开的窗口立即生效，装之前就开着的窗口只要重开一次（或手动加载一次同步脚本）也会跟上">

出问题就打开菜单选 **`1 安装 / 修复`**。它能修好大部分问题，重复运行不会多装一份，不会中断网络，也不会丢失你的设置。

> 从网上下载的包第一次双击如果被拦截：右键文件 → 属性 → 解除锁定（或运行 `Unblock-File .\EnvProxy-win.zip`），不要修改执行策略。

### 更新

打开菜单选 **`5 检查更新`**：先说明最新版本号和这一版改了什么，同意之后才安装。

- **升级不需要开翻墙软件**：多数网络本来就能连。如果提示连不上，把翻墙软件开关一次再试。
- **安装前核对校验值**：下载完成后先核对，对不上就不安装。装坏了比不装更麻烦。
- **只替换程序文件**：你的文件、日志、`monitor\` 里的运行标记都不会被改动。安装完成后监控用新代码重启。

## 2. 打开菜单

双击 `打开菜单.cmd`（Mac 是 `打开菜单.command`）。它只负责把选择的编号转给真正的程序执行，自己不改动任何文件。

| 选 | 做什么 | 影响哪些部分 |
|---|---|---|
| **1** | 安装 / 修复。首次安装，或者觉得不对劲都选它 | 程序文件 + 开机启动 + 终端同步脚本 + 环境变量 |
| **2** | 查看状态：监控、代理、环境变量、版本 | 只读取，不改动 |
| **3** | 停止监控。临时停用，下次登录会恢复 | 监控进程 + 环境变量 |
| **4** | 一键恢复。完全卸载，回到安装之前 | 全部清除（日志可选保留） |
| **5** | 检查更新。先说明，同意才安装 | 只替换程序文件 |
| **6** | 帮助。忘记怎么用就看它 | 只打印文字，不改动 |
| **0** | 退出菜单 | 无 |

**直接按回车等于查看状态**，这是最常看的一项。菜单顶部会显示监控是否在运行、当前版本号，不需要进去看。

<img src="./assets/readme/buttons.svg" width="100%" alt="菜单每个选项影响哪些部分：安装影响程序文件、开机启动、终端同步脚本和环境变量；查看状态只读取；停止只清除监控和环境变量；一键恢复全部清除只留日志；检查更新只替换程序文件">

### 日志

`monitor\monitor.log`（Mac 是 `mac/monitor/monitor.log`）记录它做过的判断。上限 200KB，写满之后只保留最近 200 行。

卸载时会询问是否保留，选择保留就只留这一份，其余全部清除。

## 3. 常用操作一页纸

这一节把所有需要手动输入的命令集中在一起。**Windows 和 Mac 的写法不同，注意不要抄错行。**

### 3.1 让某个窗口固定直连（不跟随翻墙软件）

在那个窗口里执行：

| | 命令 |
|---|---|
| Windows | `$env:ENVPROXY_TERM = 'off'` |
| Mac | `export ENVPROXY_TERM=off` |

**按一次回车生效。** 之后这个窗口无论翻墙软件开着还是关着，都保持直连。**不会影响其他窗口。**

要恢复成跟随翻墙软件：

| | 命令 |
|---|---|
| Windows | `Remove-Item Env:ENVPROXY_TERM -ErrorAction SilentlyContinue` |
| Mac | `unset ENVPROXY_TERM` |

同样按一次回车。

### 3.2 让某个窗口使用别的代理（比如公司代理）

**顺序不能颠倒：先锁定窗口，再设置代理。**

| 步骤 | Windows | Mac |
|---|---|---|
| 1. 先锁定 | `$env:ENVPROXY_TERM = 'off'` | `export ENVPROXY_TERM=off` |
| 2. 再设置代理 | `$env:HTTPS_PROXY = 'http://你的地址:端口'` | `export HTTPS_PROXY=http://你的地址:端口` |

为什么必须先锁定：翻墙软件运行期间，只要它更新这个窗口，就会把代理地址改成它自己的。先锁定之后，它不再改动这个窗口。

**我们自己写入的值和你自己设置的值分得清。** 公司代理、你自己装的抓包工具、其他端口的地址，只要值和我们写入的不一样，就不会被清除。

### 3.3 查看当前是否走代理

| | 命令 |
|---|---|
| Windows | `$env:HTTPS_PROXY` |
| Mac | `echo $HTTPS_PROXY` |

有值表示走代理，为空表示直连。

### 3.4 临时绕过代理运行一条命令

有时希望某一条命令不走代理：

| | 命令 |
|---|---|
| Windows | `curl.exe --noproxy "*" 网址` |
| Mac | `curl --noproxy '*' 网址` |

Windows 上必须写 `curl.exe`。PowerShell 把 `curl` 识别成 `Invoke-WebRequest` 的别名，直接输入 `curl` 会报参数错误。

除 `curl` 之外的工具各有各的写法（`git` 用 `-c http.proxy=`，`npm` 用 `--no-proxy`），不在这个工具的处理范围内。

### 3.5 让一个已经打开的窗口立刻跟上

不想重新打开窗口时，在那个窗口里执行一次：

| | 命令 |
|---|---|
| Windows | `. $PROFILE` |
| Mac | `. ~/.envproxy/prompt-sync.sh` |

执行之后，这个窗口以后每次回车都会自动跟上。

## 4. 出问题了按这个顺序查

**按顺序排查，上一步试完再往下走。**

| 你看到的 | 最可能的原因 | 怎么办 |
|---|---|---|
| 提示「无法识别的开关」或用法错误 | 参数打错，或者用了缩写 | 参数必须写全，不支持缩写。对照菜单里列出的写法 |
| 终端还是不能翻墙 | 这个窗口是安装之前打开的 | 重新打开一个窗口。不想重开就执行 3.5 的命令 |
| 终端还是不能翻墙，重新打开也不行 | 监控没有在运行 | 打开菜单选 1（安装 / 修复） |
| 提示「安装不完整，缺少程序文件」 | 文件夹没有完整复制过来，或者文件被删除 | 到 Releases 页面重新下载，解压后覆盖这个文件夹。**通过「检查更新」升级会自动清理本平台的旧文件** |
| 环境变量删掉之后又出现 | 节点本身不稳定，监控按实际情况写入 | 正常现象。持续这样说明节点质量差，换一个 |
| 断开之后环境变量迟迟不删 | 软件的「断开」没有真正断开（内核还在运行），节点仍然可以连上 | 正常现象。想立刻停止就退出翻墙软件 |
| 上面都试过还不行 | — | 打开菜单选 2，把状态截图；再选 1 修复一次 |

> 大部分问题都可以用菜单的 **选 1** 解决。它不会重复安装，不会中断网络，也不会丢失你自己的设置。

## 5. 它是怎么判断在不在翻墙的

每 2 到 3 秒检查一次（翻墙时 2 秒，直连时 3 秒），但**不会看到端口就认定**。要同时满足三个条件：

<img src="./assets/readme/mechanism.svg" width="100%" alt="三层验证流程图：每 2 到 3 秒枚举本机监听端口，能应答 CONNECT 握手的才进入候选；再对候选逐个做真实连通测试；通过之后才写入代理变量">

1. **有端口在监听** —— 本机有程序打开了代理端口
2. **它确实是代理** —— 发送一次 `CONNECT` 握手，必须返回 `HTTP/1.x 200` 才算。这一步排除开发服务器和普通网页服务
3. **它确实连得通外面** —— 通过这个端口访问候选的 **7 个不同的站点**，**任意一个**真正拿到响应就算通过（先试上次成功的那个，失败再并行试其余）

**三个条件全部满足才认定在翻墙，才写入环境变量。** 所以本机运行一个网页服务不会被误判。

它不认品牌、不认进程名、不认端口号。那些信息只用来加快扫描，判断始终走上面三个条件。

<img src="./assets/readme/states.svg" width="100%" alt="日常三种状态：连上翻墙软件就写入整套代理变量，4 到 10 秒；断开或退出就删除变量恢复直连，退出约 5 秒，只断开约 15 到 50 秒，重新连上约 10 到 25 秒；换端口、换软件、反复抖动都自动跟上，变量不受影响">

**判断断开比判断连通更谨慎**：单次探测失败不算断开，要连续失败满 10 秒且至少 3 次才处理；而一次成功立即判定连通。因为误删环境变量的代价大，多等一会儿的代价小。

实际感受（连上和断开的快慢）：

| 操作 | 生效时间 |
|---|---|
| 打开翻墙软件 | 4–10 秒 |
| 完全退出翻墙软件 | 约 5 秒 |
| 只断开、没有退出 | 约 15–50 秒 |
| 断线后重新连上 | 约 10–25 秒 |

得出结论之后还会**多盯 1 分钟**加密观察，判断错了可以自己修正。

**写入哪些环境变量**（翻墙时整套写入，断开时整套删除）：

| 变量 | 写入值 | 作用 |
|---|---|---|
| `HTTP_PROXY` | `http://127.0.0.1:端口` | http:// 请求的代理 |
| `HTTPS_PROXY` | `http://127.0.0.1:端口` | https:// 请求的代理 |
| `ALL_PROXY` | `http://127.0.0.1:端口` | 兜底变量，其他变量没有覆盖的协议使用它 |
| `NO_PROXY` | `localhost,127.0.0.1,::1` | 本机地址不走代理 |
| `NODE_USE_ENV_PROXY` | `1` | 让新版 Node 工具（原生 fetch）也读取环境变量里的代理 |

Windows 写 5 个，macOS 写 9 个（同样 5 个，再加一份小写拼写）。这是平台本身的差异：Windows 的变量名不区分大小写，写小写只会覆盖自己；macOS 区分大小写，有的工具只读取小写形式。

<details>
<summary>这些设置为什么这样定（不影响使用，可以展开看）</summary>

- 代理值统一用 `http://` 写法，不用 `socks5://`。本地代理端口两种协议都能应答，部分工具只接受 `http://`，统一之后兼容范围最大，功能没有损失。`dsh` 这类工具遇到 SOCKS 写法会警告并跳过。
- Windows 不写两种拼写的原因：两种拼写在那里是同一个变量，重复项会让 .NET 系宿主在建立变量表时报 `An item with the same key has already been added`，同一个终端窗口里运行的所有程序都会受影响。
- `NO_PROXY` 里的 IPv6 地址要直接写 `::1`。写成 `[::1]` 会被 httpx 当成普通域名并生成非法匹配模式，之后每一次请求都报 `InvalidURL`。方括号是 URL 字面量的写法，放在这里是位置错了。
- 你自己的 `NO_PROXY` 条目不会被删除，只做补充；卸载时也只回收这个工具写入的值。
- 环境变量被其他程序改坏（覆盖、清空、少一项）不用处理：监控每 30 轮核对整张表，不完整就补回来。
- 下表中的工具不读取上面这 5 个变量，需要单独配置（这不是本工具的缺陷）：

| 工具 | 配置位置 |
|---|---|
| Maven | `settings.xml` 的 `<proxies>` |
| Gradle | `gradle.properties` 的 `systemProp.http(s).proxyHost/Port` |
| JDK 原生 HttpClient | JVM 系统属性（或 `java.net.useSystemProxies` 使用系统代理） |
| Docker Desktop 的 `docker pull` | Docker Desktop 自己的设置（它忽略 `daemon.json` 里的代理配置） |

- `NODE_USE_ENV_PROXY` 只对新版 Node 生效：`node:http(s)` 需要 22.21 / 24.5 以上，`fetch()` 需要 22.21 / 24.0 以上。低版本设置了也不会生效，这是预期行为。

</details>

## 6. 为什么它不容易出错

设计上的取舍是：不确定的时候不做改动。

- **读不到信息时不做处理**：端口列表读不出来时，它不会当成「没有代理」去删除你的环境变量，而是沿用上一次的状态。
- **只清除值仍等于我们写入的那些**：你手动改过的值、公司代理、其他端口的地址，都不会被清除。没有归属记录时不做任何改动，避免删掉你自己的配置。
- **修改配置文件之前先备份**：Windows 的 `$PROFILE`、Mac 的 rc 文件，改写之前都留一份 `.envproxy.bak`。写不进去就完全不改动。
- **写入方式保证文件完整**：先把内容写进临时文件，写完再整体替换。中途断电或被强制结束，原文件仍然完整。
- **重复安装没有副作用**：已经安装正确的状态下不会改动你的设置，再运行一次也不会出问题。
- **卸载之后逐项检查**：卸载完成后逐项读回确认，有残留就报告「未完成」，不会声称成功。

## 7. 性能与流量

- **稳定状态下开销很小**：判断稳定之后，每个端口最多每 15 秒探测一次，只读取响应头，不读正文，每次不到 1KB。
- **收集证据时缩短间隔**：出现失败但还没达到阈值时，改成 5 秒一次；结论确定后立刻恢复到 15 秒。
- **卸载后不留残留**：环境变量、开机启动、定位脚本、终端同步脚本块全部清除，只保留你选择保留的日志。
- **终端提示符几乎没有延迟**：它只在每次显示提示符之前读取一个本地文件，不启动任何外部进程。

## 8. 文件夹里都有什么

解压之后大体是这样（文件夹名可以修改；每个包只包含自己平台的目录，Windows 包里没有 `mac\`，反过来也一样）：

```
EnvProxy\
  win\                    Windows 版：打开菜单 + 入口 + 程序库
    打开菜单.cmd         唯一需要双击的文件：菜单（安装/状态/停止/恢复/更新/帮助）
    envproxy.ps1         入口：解析参数、获取操作锁、加载自检、分派

  mac\                    Mac 版：同样的菜单 + 入口 + 程序库

    envproxy.sh          入口（与 win\envproxy.ps1 对应）
    locator.sh           定位脚本模板（安装时复制到 ~/.envproxy/locator.sh）
    prompt-sync.sh       终端同步脚本模板（安装时复制到 ~/.envproxy/prompt-sync.sh，rc 文件里只写一行引用它）
    lib\                 七个程序库（与 Windows 同名同职责）
    monitor\             运行时自动创建（同 Windows，日志格式一致）
  README.md               中文说明（本文）
  README.en.md            英文说明
  LICENSE                 MIT 许可证
  VERSION                 版本号
  release-notes\          每个版本改了什么（选「检查更新」时会直接显示）
  assets\readme\          README 的配图
```

- **两个包各管一个平台**：`EnvProxy-win.zip` 安装 Windows（`win\` 和共享文件），`EnvProxy-mac.tar.gz` 安装 Mac（`mac\` 和共享文件）。各下各的，另一个平台的目录互不影响。
- **程序文件的范围**：`win\`、`mac\`、`release-notes\`、`assets\` 由更新流程管理，按包内清单对齐。日常只需要打开 `win\`（Mac 上是 `mac\`）。
- **你自己的文件**：最外层只覆盖同名文件，不会删除；`monitor\` 里的日志和运行标记永不覆盖、永不删除。

## 9. 关于复制备份文件夹

**可以复制、改名、移动到别的位置。** 但需要注意一件事：**原位置一旦改名或移动，正在运行的监控就找不到自己的脚本了**，它会自行退出并清除代理变量（这是为了避免留下过期的代理设置）。

所以改名或移动之后，让它恢复运行有两种办法：

- **等到下次登录**：定位脚本会找到新位置并接管。
- **立即恢复**：双击一次「安装 / 修复」。想省时间可以用这一条。

搜索范围是**桌面、文档、下载、OneDrive、`.config` 这几个常用位置向下 6 层**，以及**各磁盘根目录 4 层**。移动到这些范围之外（比如 `C:\Projects\EnvProxy`）定位脚本找不到，必须双击一次「安装」。

复制出来的备份**不会被误认为正在使用的那一份**（按日志活跃程度判断哪一份在运行），所以备份目录可以一直保留。

## 10. 给朋友/新电脑部署

1. 把安装包放到新电脑上，两种方式任选：点 **[Windows 版下载](https://github.com/FiretrUCK666/envproxy/releases/latest/download/EnvProxy-win.zip)**；或者把已经解压好的整个文件夹复制过去（U 盘、网盘、压缩包都可以）
2. 双击 `win\打开菜单.cmd`，选 `1 安装 / 修复`
3. 完成。不需要管理员权限，不需要安装其他东西

> Windows 用户可以到此为止。两个平台各有各的安装包：Mac 用户直接下载 Mac 包；已有的文件夹里包含 `mac\` 也可以照常使用。

## 11. 技术边界（5 条）

<img src="./assets/readme/limits.svg" width="100%" alt="五条技术边界：纯 TUN 模式不写入变量、不修改系统代理设置、不改变已经运行的程序、不管需要自己配置代理的工具、不提供界面">

| 边界 | 原因 | 影响 |
|---|---|---|
| **纯 TUN 模式不处理** | 它不监听本地端口，没有端口可以判断 | 这种模式下所有流量本来就经过它，不需要额外设置。它和企业 VPN 无法区分，判断错误会删掉你唯一的代理路径，所以不做处理 |
| **不修改系统代理设置** | 那会影响浏览器和其他程序 | 只写入用户级环境变量，你随时可以在系统设置里确认没有被改动 |
| **不改变已经运行的程序** | 环境变量只在进程启动时读取一次 | 已经打开的窗口需要按一次回车（这是操作系统的机制，见第 0 节） |
| **不管需要自己配置代理的工具** | 它们不读取这几个变量 | Maven、Gradle、Docker 等见第 5 节的折叠表 |
| **不提供界面** | 零依赖是安装前提 | 只有一个菜单，没有托盘图标，没有窗口 |

## 12. macOS 版

### 12.1 与 Windows 版的区别

Windows 写注册表并广播通知，Mac 写 `~/.envproxy/proxy.env` 并调用 `launchctl setenv`。两条路径同时更新，看到的行为一致。

<img src="./assets/readme/mac-paths.svg" width="100%" alt="macOS 双路写入：终端读取 ~/.envproxy/proxy.env，从 Dock 启动的程序读取 launchctl 环境变量，两条路径同时更新">

### 12.2 安装（3 步）

1. 把 Mac 包（`EnvProxy-mac.tar.gz`）放到 Mac 上任意位置（或者把包含 `mac\` 的整个文件夹复制过去：U 盘、隔空投送、压缩包都可以）
2. 进入 `mac` 双击 `打开菜单.command`，选 `1 安装 / 修复`
3. 看到「监控进程：已启动」就装好了

不需要 Homebrew、Python、Node，不需要 `sudo`，macOS 12 及以上自带的 `zsh` 就够。（只要 Mac 版：下载 [`EnvProxy-mac.tar.gz`](https://github.com/FiretrUCK666/envproxy/releases/latest/download/EnvProxy-mac.tar.gz)。）

### 12.3 菜单（与 Windows 一致）

菜单编号、行为、影响范围与 Windows 完全一致（包含 `6 帮助`、`0 退出`）。直接按回车等于查看状态。

### 12.4 `mac` 文件夹里都有什么

见第 8 节的文件夹结构。Mac 多两个模板文件：`locator.sh`（定位脚本）和 `prompt-sync.sh`（终端同步脚本）。

### 12.5 Mac 上首次安装可能遇到的三个问题

<img src="./assets/readme/mac-blockers.svg" width="100%" alt="Mac 首次安装三个问题：下载文件被隔离、脚本没有执行权限、系统设置阻止了后台项目">

| 症状 | 原因 | 怎么办 |
|---|---|---|
| 双击没有反应，或提示「无法打开」 | 下载的文件被系统隔离 | 右键 → 打开；或在终端执行 `xattr -d com.apple.quarantine 打开菜单.command` |
| 提示「权限不够」 | 脚本没有执行权限 | 在终端执行 `chmod +x 打开菜单.command` |
| 安装完成但状态显示未运行 | 系统设置阻止了后台项目 | 系统设置 → 通用 → 登录项与扩展，允许它运行 |

### 12.6 Mac 技术边界

Windows 的前 4 条同样适用（TUN、系统代理、已运行程序、需要自己配置的工具），第 5 条换成 Mac 的说法（Mac 也没有界面）。另外两条：

- **`launchctl` 的环境变量在登录和重启时清空**：所以监控每 30 轮重新写入一次，重启之后会自动补回来。
- **`~/.envproxy/` 是固定位置**：安装完成后里面有这些文件。`locator.sh` 是定位脚本。`prompt-sync.sh` 是终端同步脚本，rc 文件里只写一行引用它。`path.conf` 记录项目路径。`proxy.env` 保存终端这一路的环境变量和当前状态。`owned.env` 记录我们写入过的值，清除时只清除这些。`prev.env` 是安装时保存的原始值，卸载时用来还原。另外还有 launchd 的输出重定向文件。项目文件夹可以移动到其他位置，下次登录会自动重新定位；备份文件夹不会被误选。卸载时这些文件全部清除，只保留你选择保留的 `monitor.log`。

### 12.7 给朋友/新 Mac 部署

把整个文件夹复制过去，进入 `mac` 双击 `打开菜单.command`，选 `1 安装 / 修复`，完成。
