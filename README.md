翻墙软件只管浏览器，不管终端。`git`、`npm`、`curl` 这类工具靠一组叫「环境变量」的设置知道代理的地址，才连得上外面。

EnvProxy 自动维护这组设置。翻墙软件开着，它把代理地址写进去；关掉，它删掉。日常不需要记任何命令。

## 0. 装完之后会发生什么

装完之后绝大多数情况都不用管。只有一种情况要动手，就是下面表格的最后一行。

| 你的情况 | 会发生什么 | 需要做什么 |
|---|---|---|
| **装完之后打开的窗口或程序** | 启动时读到的就是当前状态 | **什么都不用做** |
| **装完之后打开，后来代理又变了** | 需要重读一次 | 按一次回车就行 |
| **装之前就打开的窗口** | 安装时同步代码还没装进去 | 重开一个窗口，或执行 3.5 的命令 |

### 为什么开着的窗口要按一次回车

每个程序只在启动那一刻读一次环境变量，读完就固定了。之后系统里改了，已经在跑的窗口不会跟着变。

所以新窗口自动是对的，老窗口得让它重读一次。EnvProxy 挑的时机是每次命令跑完、屏幕重新出现光标的时候——你本来就一直在敲命令，所以不用专门做什么。

### AI 工具、编辑器、IDE

它们开终端一般是新开一个进程，所以自动就是对的。

两种要重启那个工具：装 EnvProxy 之前就开着的；或者它是常驻后台、不随用随开的。拿不准就重启一次。

## 1. 安装（3 步，5 分钟）

1. 点 **[这里下载 Windows 版安装包](https://github.com/FiretrUCK666/envproxy/releases/latest/download/EnvProxy-win.zip)**（Mac 版点 [`EnvProxy-mac.tar.gz`](https://github.com/FiretrUCK666/envproxy/releases/latest/download/EnvProxy-mac.tar.gz)）
2. 解压到任意位置，文件夹可以改名。进 `win` 双击 **`打开菜单.cmd`**（Mac 进 `mac` 双击 **`打开菜单.command`**），选 **`1 安装 / 修复`**
3. 看到「监控进程：已启动」就好了

安装会做五件事：存一份你原来的变量值（卸载时还原）、设置开机自启、往终端配置里加一段同步代码、启动监控、立即校正一次变量。屏幕上会显示进度（Windows 4 步、Mac 3 步）。

<img src="./assets/readme/first-run.svg" width="100%" alt="安装三步：下载对应平台的包 → 双击打开菜单选 1「安装 / 修复」→ 看到「监控进程：已启动」；下方并排对比：装完之后新开的窗口立即生效，装之前就开着的窗口只要重开一次（或手动加载一次同步脚本）也会跟上">

出问题就打开菜单选 **`1 安装 / 修复`**。它能修好大部分问题，重复运行不会多装一份，不会中断网络，也不会丢失你的设置。

> 从网上下载的包第一次双击如果被拦截：右键文件 → 属性 → 解除锁定（或运行 `Unblock-File .\EnvProxy-win.zip`），不要修改执行策略。

### 更新

打开菜单选 **`5 检查更新`**：先说明最新版本号和这一版改了什么，同意之后才安装。

- **升级不需要开翻墙软件**：多数网络本来就能连。如果提示连不上，把翻墙软件开关一次再试。
- **安装前核对校验值**：下载完成后先核对，对不上就不安装。装坏了比不装更麻烦。
- **只替换程序文件**：你的文件、日志、`monitor\` 里的运行标记都不会被改动。安装完成后监控用新代码重启。

### 日志

`monitor\monitor.log`（Mac 是 `mac/monitor/monitor.log`）记录它做过的判断。上限 200KB，写满之后只保留最近 200 行。

## 3. 常用操作一页纸

**先说清楚：这一节不是必读的。** 装完之后翻墙软件一开一关，终端自己就跟着切了，你一条命令都不用敲。

**下面这些事，绝大多数用菜单就够了**：停止监控、彻底卸载、检查更新、看状态，都在菜单里，双击一下就行，不用敲命令。本节讲的是菜单做不到的那几件事——想单独处理某一个窗口的时候。

看不懂可以整节跳过，不影响正常使用。真觉得不对劲，打开菜单选 1。

### 这些命令在哪个终端里敲

用的是 **PowerShell**，不是老式的「命令提示符」（cmd）。

Windows 上你日常接触的窗口基本都是 PowerShell，不用担心：

| 你怎么打开的窗口 | 是 PowerShell 吗 |
|---|---|
| 开始菜单搜「PowerShell」 | 是 |
| Win+R 输入 `powershell` | 是 |
| Windows Terminal | 是（默认就是） |
| VS Code 的终端 | 是（默认就是） |
| 开始菜单搜「命令提示符」或「cmd」 | **不是**，那些命令在这里会报错 |

分辨方法看提示符：开头有 `PS` 的是 PowerShell，比如 `PS C:\Users\你的名字>`。

**如果你确实在用 cmd**，对应的写法不一样：

| 目的 | PowerShell | cmd |
|---|---|---|
| 固定直连 | `$env:ENVPROXY_TERM = 'off'` | `set ENVPROXY_TERM=off` |
| 恢复自动 | `Remove-Item Env:ENVPROXY_TERM` | `set ENVPROXY_TERM=` |
| 查看代理 | `$env:HTTPS_PROXY` | `set HTTPS_PROXY` |

Mac 上就是「终端」这个 App，默认 zsh，命令用 `export` 那一列。

下面每条命令都在**你要改的那个窗口里**输入，**只影响那个窗口**。Windows 和 Mac 写法不同，别抄错行。

### 3.1 让一个窗口固定直连

翻墙软件开着的时候，想让某个窗口不走代理：

| | 命令 |
|---|---|
| Windows（PowerShell） | `$env:ENVPROXY_TERM = 'off'` |
| Mac | `export ENVPROXY_TERM=off` |

执行完这个窗口就一直直连，直到你关掉它。要恢复自动：

| | 命令 |
|---|---|
| Windows（PowerShell） | `Remove-Item Env:ENVPROXY_TERM -ErrorAction SilentlyContinue` |
| Mac | `unset ENVPROXY_TERM` |

### 3.2 让一个窗口走公司代理

**顺序不能反：先锁定窗口，再设代理。**

| 步骤 | Windows（PowerShell） | Mac |
|---|---|---|
| 1. 先锁定 | `$env:ENVPROXY_TERM = 'off'` | `export ENVPROXY_TERM=off` |
| 2. 再设代理 | `$env:HTTPS_PROXY = 'http://你的地址:端口'` | `export HTTPS_PROXY=http://你的地址:端口` |

为什么必须先锁定：不锁定的话，翻墙软件一更新这个窗口，就把你的代理地址盖掉了。

你自己设的值不会被删。只要和我们写入的不一样，公司代理、抓包工具、别的端口都原样留着。

### 3.3 检查现在走不走代理

| | 命令 |
|---|---|
| Windows（PowerShell） | `$env:HTTPS_PROXY` |
| Mac | `echo $HTTPS_PROXY` |

有值就是走代理，空的就是直连。

### 3.4 让某一条命令不走代理

不同工具写法不一样，没有通用的一条命令。

| 工具 | Windows（PowerShell） | Mac |
|---|---|---|
| `curl` | `curl.exe --noproxy "*" 网址` | `curl --noproxy '*' 网址` |
| `git` | `git -c http.proxy= -c https.proxy= clone 仓库地址` | 同左 |
| `npm` | `npm --noproxy=registry.npmjs.org install 包名` | 同左 |
| `wget` | 系统不自带，装过才有 `wget.exe --no-proxy 网址` | `wget --no-proxy 网址` |
| `docker` | 改 Docker 自己的设置，没有单条命令的写法 | 同左 |

四个实测确认过的坑：

- **PowerShell 里 `curl` 和 `wget` 都是别名，两个都指向 `Invoke-WebRequest`**。直接敲会报「参数找不到」，所以 curl 要写 `curl.exe`。（PowerShell 7 里没有这两个别名，这条只对系统自带的 5.1 成立。）
- **`npm` 的 `--noproxy` 只认域名，写 `*` 没用**。它不会报错，请求照样打到代理上——你以为绕过了，其实没有。要写具体域名，比如 `--noproxy=registry.npmjs.org`。
- **`npm --no-proxy` 会被理解成 `--proxy=false`**，不是「被忽略」，也和你想要的「不走代理」不是一回事。用 `--noproxy=域名`。
- **`git` 的 `-c http.proxy=` 后面必须留空**。留空表示「这一条命令不用代理」，写别的值就是「改用这个代理」。

另外，npm 只认 `HTTPS_PROXY`，不认 `HTTP_PROXY`。EnvProxy 两个都写，所以 npm 能正常工作；但如果你自己只设 `HTTP_PROXY`，npm 是不走代理的。

这些写法都是各工具自己的，不是 EnvProxy 提供的。不加这些参数时，它们读的才是 EnvProxy 写入的环境变量。

### 3.5 让已经开着的窗口立刻跟上

先看你是哪种情况：

| 你的窗口 | 会怎样 | 要做什么 |
|---|---|---|
| 装完之后打开的 | 自动就是对的 | 什么都不用做 |
| 装完之后打开的，但代理后来变了 | 手里还是旧状态 | 按一次回车 |
| 装之前就打开的 | 同步代码从没装进去 | 重开一个，或执行下面的命令 |

第三种情况，重开窗口最省事。不想重开，就在那个窗口里执行一次：

| | 命令 |
|---|---|
| Windows（PowerShell） | `. $PROFILE` |
| Mac | `. ~/.envproxy/prompt-sync.sh` |

**这两条命令是什么**：`$PROFILE` 是 PowerShell 每次启动时自动跑的文件，安装时往里面放了一段同步代码，这条命令就是手动跑一次它。Mac 那个文件是同步脚本，作用一样。

**四点要注意**：

- 开头的 `.` 和后面的空格都不能少。`.` 的意思是「在当前窗口里执行这个文件」。
- 只对 PowerShell（Windows）和 zsh、bash（Mac）有效。Mac 上的 fish 不支持。
- 执行完只影响这一个窗口。其他已开着的窗口要各自执行，或者直接重开。
- 如果这个窗口里从来没装过 EnvProxy，`$PROFILE` 指向的文件可能不存在，会看到「找不到路径」的红字。那是正常的，重开一个窗口就行。

## 4. 出问题了按这个顺序查

**按顺序排查，上一步试完再往下走。**

| 你看到的 | 最可能的原因 | 怎么办 |
|---|---|---|
| 提示「无法识别的开关」（Windows）或「无法识别的参数」（Mac） | 参数打错，或者用了缩写 | 参数必须写全，不支持缩写。对照菜单里列出的写法 |
| 终端还是不能翻墙 | 这个窗口是安装之前打开的 | 重新打开一个窗口。不想重开就执行 3.5 的命令 |
| 终端还是不能翻墙，重新打开也不行 | 监控没有在运行 | 打开菜单选 1（安装 / 修复） |
| 提示「安装不完整，缺少程序文件」 | 文件夹没有完整复制过来，或者文件被删除 | 到 Releases 页面重新下载，解压后覆盖这个文件夹。**通过「检查更新」升级会自动清理本平台的旧文件** |
| 环境变量删掉之后又出现 | 节点本身不稳定，监控按实际情况写入 | 正常现象。持续这样说明节点质量差，换一个 |
| 断开之后环境变量迟迟不删 | 软件的「断开」没有真正断开（内核还在运行），节点仍然可以连上 | 正常现象。想立刻停止就退出翻墙软件 |
| 上面都试过还不行 | — | 打开菜单选 2，把状态截图；再选 1 修复一次 |

> 大部分问题都可以用菜单的 **选 1** 解决。它不会重复安装，不会中断网络，也不会丢失你自己的设置。

## 5. 它是怎么判断在不在翻墙的

每 2 到 3 秒检查一次（翻墙时 2 秒，直连时 3 秒），但**不会看到端口就认定**。要同时满足三条：

<img src="./assets/readme/mechanism.svg" width="100%" alt="三层验证流程图：每 2 到 3 秒枚举本机监听端口，能应答 CONNECT 握手的才进入候选；再对候选逐个做真实连通测试；通过之后才写入代理变量">

1. **有端口在监听** —— 本机有程序开了代理端口
2. **它确实是代理** —— 发一次 `CONNECT` 握手，必须回 `HTTP/1.x 200`。这一步排除开发服务器和普通网页服务
3. **它确实连得通外面** —— 通过这个端口访问 **7 个不同的站点**，**任意一个**真拿到响应就算通过

三条全过才写入变量。所以本机开着个网页服务不会被误判。

它不认品牌、不认进程名、不认端口号——那些只用来加快扫描，判断永远走这三条。

<img src="./assets/readme/states.svg" width="100%" alt="日常三种状态：连上翻墙软件就写入整套代理变量，6 到 10 秒；断开或退出就删除变量恢复直连，退出约 8 秒，只断开约 15 到 50 秒，重新连上约 10 到 25 秒；换端口、换软件、反复抖动都自动跟上，变量不受影响">

**判断开比判连通更谨慎**：单次失败不算断开，要连续失败满 10 秒且至少 3 次才动手；一次成功则立刻判连通。因为误删变量代价大，多等一会儿代价小。下结论后还会多盯 1 分钟，判错了能自己改回来。

| 操作 | 生效时间 |
|---|---|
| 打开翻墙软件 | 约 6–10 秒 |
| 完全退出翻墙软件 | 约 8 秒 |
| 只断开、没退出 | 约 15–50 秒 |
| 断线后重新连上 | 约 10–25 秒 |

**写入哪些变量**（翻墙时整套写，断开时整套删）：

| 变量 | 写入值 | 作用 |
|---|---|---|
| `HTTP_PROXY` | `http://127.0.0.1:端口` | http:// 请求的代理 |
| `HTTPS_PROXY` | `http://127.0.0.1:端口` | https:// 请求的代理 |
| `ALL_PROXY` | `http://127.0.0.1:端口` | 兜底，其他变量没覆盖的协议用它 |
| `NO_PROXY` | `localhost,127.0.0.1,::1` | 本机地址不走代理 |
| `NODE_USE_ENV_PROXY` | `1` | 让新版 Node 工具也读环境变量里的代理 |

Windows 写 5 个，macOS 写 9 个（同样 5 个，再加一份小写拼写）。Windows 变量名不区分大小写，写小写只会覆盖自己；macOS 区分大小写，有的工具只认小写。

<details>
<summary>这些设置为什么这样定（不影响使用，可以展开看）</summary>

- 代理值统一用 `http://`，不用 `socks5://`。本地代理端口两种协议都应答，部分工具只接受 `http://`，统一之后兼容面最大，没有损失。`dsh` 这类工具遇到 SOCKS 会警告并跳过。
- Windows 不写两种拼写：两种拼写在那里是同一个变量，重复项会让 .NET 系宿主建表时报 `An item with the same key has already been added`，那个窗口里跑的所有程序都受影响。
- `NO_PROXY` 里的 IPv6 要裸写 `::1`。写成 `[::1]` 会被 httpx 当成普通域名，之后每次请求都报 `InvalidURL`。方括号是 URL 的写法，放错了位置。
- 你自己的 `NO_PROXY` 条目不会被删，只做补充；卸载时也只回收我们写入的值。
- 变量被别的程序改坏了不用管：监控每 30 轮核对整张表，缺了就补回来。
- 下面这些工具不读上面那 5 个变量，要单独配（不是本工具的问题）：

| 工具 | 配置位置 |
|---|---|
| Maven | `settings.xml` 的 `<proxies>` |
| Gradle | `gradle.properties` 的 `systemProp.http(s).proxyHost/Port` |
| JDK 原生 HttpClient | JVM 系统属性（或 `java.net.useSystemProxies`） |
| Docker Desktop 的 `docker pull` | Docker Desktop 自己的设置（它忽略 `daemon.json` 里的代理） |

- `NODE_USE_ENV_PROXY` 只对新版 Node 生效：`node:http(s)` 要 22.21 / 24.5 以上，`fetch()` 要 22.21 / 24.0 以上。低版本设了没用，属预期。

</details>

## 6. 为什么它不容易出错

原则是：**拿不准的时候不动**。

- **读不出来就不动**：端口列表读不出来时，不会当成「没有代理」去删你的变量，而是沿用上一次的状态。
- **只清我们写下的值**：你改过的手设值、公司代理、别的端口，一个都不动。没有归属记录时干脆不动。
- **改配置前先备份**：Windows 的 `$PROFILE`、Mac 的 rc 文件，改写前都留一份 `.envproxy.bak`。写不进去就一字不改。
- **写文件保证完整**：先写临时文件再整体替换。中途断电或被杀，原文件还是完整的。
- **重复装无害**：已经装对了就不动你的设置，再跑一次也不出问题。
- **卸载后会复查**：逐项读回确认，有残留就报「未完成」，不会假装成功。

## 7. 性能与流量

- **稳定状态下开销很小**：判断稳定之后，每个端口最多每 15 秒探测一次，只读取响应头，不读正文，每次不到 1KB。
- **收集证据时缩短间隔**：出现失败但还没达到阈值时，改成 5 秒一次；结论确定后立刻恢复到 15 秒。
- **卸载后不留残留**：环境变量、开机启动、定位脚本、终端同步脚本块全部清除，只保留你选择保留的日志。
- **终端提示符几乎没有延迟**：它只在每次显示提示符之前读取一个本地文件，不启动任何外部进程。

## 8. 文件夹里都有什么

解压之后大体是这样。文件夹名可以改；每个包只有自己平台的目录，Windows 包里没有 `mac\`，反过来也一样。

```
EnvProxy\
  win\                    Windows 版
    打开菜单.cmd         唯一需要双击的文件
    envproxy.ps1         主程序
    lib\                 程序库（不用管）
    monitor\             运行时自动生成，放日志
  mac\                    Mac 版，结构一样
    打开菜单.command     唯一需要双击的文件
    envproxy.sh          主程序
    locator.sh           定位脚本模板
    prompt-sync.sh       终端同步脚本模板
    lib\  monitor\       同上
  README.md               中文说明（本文）
  README.en.md            英文说明
  LICENSE                 MIT 许可证
  VERSION                 版本号
  release-notes\          每版改了什么（选「检查更新」时会显示）
  assets\readme\          README 的配图
```

分三块地，规矩不一样：

- **程序文件**：`win\`、`mac\`、`release-notes\`、`assets\`。更新会覆盖，**别往里放你自己的文件**。
- **运行时目录**：`monitor\`。日志和运行标记，**永不覆盖、永不删除**。
- **最外层**：只覆盖同名文件，**绝不删你的东西**。

日常你只需要打开 `win\`（Mac 上是 `mac\`）。

<img src="./assets/readme/boundary.svg" width="100%" alt="三个区域：程序目录（更新会覆盖，不要放自己的文件）、运行时目录（日志与运行标记永不覆盖、永不删除）、文件夹最外层（只覆盖同名文件，不会删除你的东西）">

## 9. 关于复制备份文件夹

**可以复制、改名、搬走。** 但要知道：**原位置一改名或一搬走，正在跑的监控就找不到自己的程序了**，它会自己退出并清掉代理变量（免得留下过期的设置）。

所以改名或搬家之后，让它回来有两种办法：

- **等下次登录**：定位脚本会找到新位置并接管。
- **立刻回来**：双击一次「安装 / 修复」。想省事就用这条。

搜索范围是**桌面、文档、下载、OneDrive、`.config` 这几个位置向下 6 层**，以及**各磁盘根 4 层**。搬到范围外（比如 `C:\Projects\EnvProxy`）就找不到了，必须双击一次「安装」。

复制出来的备份**不会被误认成正主**（按日志活跃度判断哪份在跑），所以备份可以一直留着。

## 11. 技术边界（5 条）

<img src="./assets/readme/limits.svg" width="100%" alt="五条技术边界：纯 TUN 模式不写入变量、不修改系统代理设置、不改变已经运行的程序、不管需要自己配置代理的工具、不提供界面">

| 边界 | 原因 | 影响 |
|---|---|---|
| **纯 TUN 模式不处理** | 它不监听本地端口，没有端口可以判断 | 这种模式下所有流量本来就经过它，不需要额外设置。它和企业 VPN 无法区分，判断错误会删掉你唯一的代理路径，所以不做处理 |
| **不修改系统代理设置** | 那会影响浏览器和其他程序 | 只写入用户级环境变量，你随时可以在系统设置里确认没有被改动 |
| **不改变已经运行的程序** | 环境变量只在进程启动时读取一次 | 已经打开的窗口需要按一次回车（这是操作系统的机制，见第 0 节） |
| **不管需要自己配置代理的工具** | 它们不读取这几个变量 | Maven、Gradle、Docker 等见第 5 节的折叠表 |
| **不提供界面** | 零依赖是安装前提 | 只有一个菜单，没有托盘图标，没有窗口 |

## 12. macOS 版

### 12.1 与 Windows 版的区别

Windows 写注册表并广播通知，Mac 写 `~/.envproxy/proxy.env` 并调用 `launchctl setenv`。两条路径同时更新，看到的行为一致。

<img src="./assets/readme/mac-paths.svg" width="100%" alt="macOS 双路写入：终端读取 ~/.envproxy/proxy.env，从 Dock 启动的程序读取 launchctl 环境变量，两条路径同时更新">

### 12.2 安装（3 步）

1. 把 Mac 包（`EnvProxy-mac.tar.gz`）放到 Mac 上任意位置（或者把包含 `mac\` 的整个文件夹复制过去：U 盘、隔空投送、压缩包都可以）
2. 进入 `mac` 双击 `打开菜单.command`，选 `1 安装 / 修复`
3. 看到「监控进程：已启动」就装好了

不需要 Homebrew、Python、Node，不需要 `sudo`，macOS 12 及以上自带的 `zsh` 就够。（只要 Mac 版：下载 [`EnvProxy-mac.tar.gz`](https://github.com/FiretrUCK666/envproxy/releases/latest/download/EnvProxy-mac.tar.gz)。）

### 12.3 菜单（与 Windows 一致）

菜单编号、行为、影响范围与 Windows 完全一致（包含 `6 帮助`、`0 退出`）。直接按回车等于查看状态。

### 12.4 `mac` 文件夹里都有什么

见第 8 节的文件夹结构。Mac 多两个模板文件：`locator.sh`（定位脚本）和 `prompt-sync.sh`（终端同步脚本）。

### 12.5 Mac 上首次安装可能遇到的三个问题

<img src="./assets/readme/mac-blockers.svg" width="100%" alt="Mac 首次安装三个问题：下载文件被隔离、脚本没有执行权限、系统设置阻止了后台项目">

| 症状 | 原因 | 怎么办 |
|---|---|---|
| 双击没有反应，或提示「无法打开」 | 下载的文件被系统隔离 | 右键 → 打开；或在终端执行 `xattr -d com.apple.quarantine 打开菜单.command` |
| 提示「权限不够」 | 脚本没有执行权限 | 在终端执行 `chmod +x 打开菜单.command` |
| 安装完成但状态显示未运行 | 系统设置阻止了后台项目 | 系统设置 → 通用 → 登录项与扩展，允许它运行 |

### 12.6 Mac 技术边界

Windows 的前 4 条同样适用（TUN、系统代理、已运行程序、需要自己配置的工具），第 5 条换成 Mac 的说法（Mac 也没有界面）。另外两条：

- **`launchctl` 的环境变量在登录和重启时清空**：所以监控每 30 轮重新写入一次，重启之后会自动补回来。
- **`~/.envproxy/` 是固定位置**：安装完成后里面有这些文件。`locator.sh` 是定位脚本。`prompt-sync.sh` 是终端同步脚本，rc 文件里只写一行引用它。`path.conf` 记录项目路径。`proxy.env` 保存终端这一路的环境变量和当前状态。`owned.env` 记录我们写入过的值，清除时只清除这些。`prev.env` 是安装时保存的原始值，卸载时用来还原。另外还有 launchd 的输出重定向文件。项目文件夹可以移动到其他位置，下次登录会自动重新定位；备份文件夹不会被误选。卸载时这些文件全部清除，只保留你选择保留的 `monitor.log`。

### 12.7 给朋友/新 Mac 部署

把整个文件夹复制过去，进入 `mac` 双击 `打开菜单.command`，选 `1 安装 / 修复`，完成。
