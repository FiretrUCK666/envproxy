## 一句话说明它是干什么的

翻墙软件能让浏览器翻墙，但 `git`、`npm`、`curl` 这类命令行工具不认它——它们只读环境变量。
EnvProxy 补的就是这个空缺：它盯着翻墙软件有没有真的在翻墙，翻着就把代理写进环境变量，不翻了就删掉。

| 你的场景 | 没有 EnvProxy | 装了 EnvProxy |
|---|---|---|
| 打开翻墙软件 | 浏览器通了，终端没通：命令行工具变慢、超时，只认环境变量的工具直接连不上 | 终端跟着翻墙 |
| 关掉翻墙软件 | 代理变量留在那里，终端报"连接被拒绝" | 变量自动删掉，终端恢复直连 |
| 换了端口、换了翻墙软件 | 手动抄端口、手动设变量，还得记得改回来 | 自动发现新端口并更新 |

> 它只管**环境变量**（命令行工具的世界），从不碰**系统代理**（浏览器的世界）。两个世界互不打扰。

### 它注入哪些变量

翻墙时整套写入，断开时整套删除，同进同退：

| 变量 | 写入值 | 作用 |
|---|---|---|
| `HTTP_PROXY` | `http://127.0.0.1:端口` | http:// 请求的代理 |
| `HTTPS_PROXY` | `http://127.0.0.1:端口` | https:// 请求的代理 |
| `ALL_PROXY` | `http://127.0.0.1:端口` | 兜底变量：具体变量没覆盖到的协议用它 |
| `NO_PROXY` | `localhost,127.0.0.1,::1` | 本机地址不走代理 |
| `NODE_USE_ENV_PROXY` | `1` | 让新版 Node 系工具（原生 fetch）也读环境变量代理 |

代理值统一用 `http://` 写法，不用 `socks5://`：本地代理端口两种协议都应答，而部分工具只认 `http://`，统一之后兼容面最大，行为没有损失。

Windows 写 5 个，macOS 写 9 个（同样 5 个，再加一份小写拼写）。这是平台差异，不是漏写：Windows 的变量名大小写不敏感，写小写只会互相覆盖；macOS 的大小写各算一个变量，有的工具只认小写。

<details>
<summary>这几条为什么这么定（不影响使用，点开看）</summary>

- 不用 `socks5://` 的原因：部分工具（例如 dsh）碰到 SOCKS 写法会警告并跳过，而本地混合端口本来就应答 HTTP。
- Windows 不写两种拼写的原因：两种拼写在那里是同一个变量，重复项会让 .NET 系宿主建表时直接报 `An item with the same key has already been added`，同一个终端窗口里跑的东西会一起受影响。
- `NO_PROXY` 里的 IPv6 要裸写 `::1`。写成 `[::1]` 会被 httpx 当成普通域名、生成非法匹配模式，之后每一次请求都报 `InvalidURL`；方括号是 URL 字面量的写法，放错了位置。
- 你自己的 `NO_PROXY` 条目不会被删，只做补齐；卸载时也只回收本工具写下的值。
- 变量被别的东西改坏（覆盖、清空、少一项）不用管：监控每 60–90 秒核对一遍整张表，不齐就补回来。
- 下表里的工具不读上面这 5 个变量，要另行配置（不是本工具的 bug）：

| 工具 | 该去哪里配 |
|---|---|
| Maven | `settings.xml` 的 `<proxies>` |
| Gradle | `gradle.properties` 的 `systemProp.http(s).proxyHost/Port` |
| JDK 原生 HttpClient | JVM 系统属性（或 `java.net.useSystemProxies` 走系统代理） |
| Docker Desktop 的 `docker pull` | Docker Desktop 自己的设置（它忽略 `daemon.json` 里的代理） |

- `NODE_USE_ENV_PROXY` 只对新版 Node 生效：`node:http(s)` 要 22.21 / 24.5 以上，`fetch()` 要 22.21 / 24.0 以上。低版本设了也没用，是预期行为。

</details>

## 1. 安装（3 步，5 分钟）

1. 点 **[这里下载最新版安装包](https://github.com/FiretrUCK666/envproxy/releases/latest/download/EnvProxy.zip)**（一个 zip，Windows 和 Mac 通用）
2. 解压到任意位置，文件夹随便改名。进 `win` 双击 **`1-安装.cmd`**；Mac 进 `mac` 双击 **`1-安装.command`**
3. 看到"监控进程已启动"就装好了

装完它做了四件事：先给已有的同名变量拍快照（卸载时还原用）、注册开机自启动、立刻启动监控、当场校正一次环境变量。

<img src="./assets/readme/first-run.svg" width="100%" alt="安装三步：下载 zip → 双击 1-安装 → 看到「监控进程已启动」；下方并排对比：已经开着的窗口不变，新开的窗口立刻生效">

以后升级：双击 **`5-检查更新.cmd`**，它会先告诉你最新版是什么、这一版改了什么，你同意才装。

出任何毛病：再双击一次 **`1-安装.cmd`**。它是万能修复，不会重复安装、不会断网、不会丢东西。

> 网上下载的包第一次双击若被拦截：右键文件 → 属性 → 解除锁定（或跑一句 `Unblock-File`），不要去改执行策略。

## 2.5 日志（monitor.log）

`win\monitor\monitor.log`（Mac 在 `mac\monitor\`）只记状态变化：什么时候注入、什么时候删除、监控启动与退出、开机自启自愈、出了什么错。稳定运行的时候它一个字都不写，体积上限 200KB，超过就自动截断成最近 200 行，用几年也不会越来越大。

它是排查问题的黑匣子。反馈问题时把最近的相关几行一起带上，大多数情况看一眼就定位了。

## 3. 日常使用（装完后什么都不用做）

| 你做什么 | 它会做什么 | 多久 |
|---|---|---|
| 打开翻墙软件、连上 | 检测到在翻墙 → 写入变量 | 4–10 秒（软件和端口都不在常见表里的，最长约 30 秒） |
| 断开或退出翻墙软件 | 检测到没翻墙 → 删除变量 | 退出约 5 秒；只是断开约 30–45 秒 |
| 改端口后重连 | 发现新端口，更新成新值 | 约 10 秒 |
| 换一个翻墙软件 | 发现新软件的端口 | 几秒 |
| 同时开两个翻墙软件 | 只用验活的那个，前一个断了自动让位 | 不用管 |
| 反复快速连接、断开 | 抖动被吸收，变量纹丝不动 | 不用管 |
| 重启电脑 | 开机立即校正残留变量 | 不用管 |
| 把整个文件夹搬到别处 | 旧监控自己退出，下次启动从新位置拉起（搜索范围见第 11 节第 3 条） | 不用管 |

## 4. 它是怎么判断"在不在翻墙"的

<p align="center">
  <img src="./assets/readme/mechanism.svg" width="100%" alt="三层验证流程图：每 2–3 秒轮询一次，依次检查本机端口是否在监听、该端口是否回答 CONNECT 握手、通过它访问外网是否真的可达。三层都通过就写入整套代理变量；任何一层不通过就删除整套变量、恢复直连。">
</p>

每 2–3 秒检查一次本机有没有端口在监听，有就再往下验两层：它会不会回答代理握手，通过它访问外网是不是真的通。
三层全过才算在翻墙，才写入变量；任何一层不过就当没在翻墙，删掉变量恢复直连——"断开连接但软件内核还活着"就落在这一支。

它不认品牌、不认进程名、不认端口号，只认谁真的在提供代理服务。所以 Clash、v2rayN、Shadowsocks、Hiddify、sing-box、NekoBox、Surge 这些都能用，换软件、改端口都不用动配置。

## 5. 为什么它不容易出错

| 机制 | 作用 |
|---|---|
| 双轮确认 | 状态连续确认两轮才动手——几秒内反复连断，变量不会乱写 |
| 判断"断"很保守 | 连续 3 次探测失败（约 30–45 秒）才认定断开；一次成功立刻认回。判"断"要删变量、通知全系统，代价比多等一会儿大得多 |
| 多端点验证 | 7 个检查端点跨厂商、跨域段。正常只测上次成功的那个，它失败才并行兜底其余——某个域段被干扰不会导致误删 |
| 探测省流量 | 每个端口 15 秒最多真实探测一次，而且只等响应头、不读正文，每次不到 1KB |
| 只有一个监控进程 | 单实例锁，不会越积越多 |
| 本机开发服务器不当代理 | 端口在监听还不够，要过 CONNECT 握手才算候选——8080、8888 上的本机服务不会被误判 |

<details>
<summary>其余保护措施（不影响使用，点开看）</summary>

| 机制 | 作用 |
|---|---|
| 开机对齐 | 开机立即校正变量，关机时残留的死端口瞬间清掉 |
| 安装先快照 | 覆盖同名变量前先记下原值，卸载时按快照还原——只回收自己写下的，不动别人的 |
| 监控自退 | 文件夹被移动或删除，监控 2–3 秒内发现并自动退出，先清掉已注入的变量再清旧位置 |
| 定位器兜底清理 | 移动后立刻关机（监控来不及自退），下次开机由定位器顺手清掉旧位置残留；新位置找不到时也清掉残留变量，新终端不再读到过期代理 |
| 活跃度优先定位 | 先把所有搜索根的结果汇总，再按日志活跃度排序——复制的备份文件夹永远不会被误选 |
| 跨位置优雅停止 | 停旧位置的监控时，把信号写到它自己的目录，优雅退出而不是强杀 |
| 自启动自愈 | 每 30 轮（约 60–90 秒）自查一次，按当前代码重建定位器和自启动项；判据是内容一致，不只是文件还在 |
| 集合试活 | 候选端口排队逐个验活，上次验活的优先认回；双开时前死后活自动让位 |

</details>

## 6. 故障排查

| 现象 | 原因 | 怎么办 |
|---|---|---|
| 装好后终端还是不能翻墙 | 终端是装之前开的 | 彻底关掉，重开一个 |
| 断开后变量迟迟不删 | 软件"断开"没真断（内核还活着），节点也还通 | 正常现象。想立刻停就退出翻墙软件 |
| 变量删了又恢复 | 节点本身在抖，监控如实反映 | 正常现象。持续这样说明节点质量差，换一个 |
| 报 `An item with the same key has already been added`，或变量读不全 | 会话里留着同名两种拼写的变量（`HTTP_PROXY` 和 `http_proxy`） | 把那个终端、以及从它启动的程序全部关掉重开。注册表本身是干净的，不必注销 |
| 明明连着翻墙软件，却显示变量已删除 | 验证端点所在的域段暂时不通 | 7 个端点兜底，单一域段不通不该触发误判。仍然出现就双击一次"安装" |
| 日志里出现"检测异常" | 单轮检测出错，不影响整体 | 不用管，会自己恢复；持续出现就双击一次"安装" |
| 检查更新显示"检查失败" | 本机暂时到不了 GitHub | 稍后重试；翻墙开、关换个状态再试一次也常有效 |
| 更新中途报错 | 下载、解压、校验或写入失败 | 重跑一次 `5-检查更新`（会补齐）；也可以手动下载安装包覆盖后再点一次 `1-安装` |
| 提示"这个版本没有提供安装包" | 那次发布没把安装包挂上去 | 到 Releases 页面手动下载 `EnvProxy.zip`，覆盖解压后再点一次 `1-安装`。不是你机器的问题 |
| 文件夹里有 `AGENTS.md`、`CONTRIBUTING.md`、`.github`、`tests/` 这些看不懂的东西 | 你下的是 GitHub 的 "Source code"，不是安装包 | 纯使用直接点更新，它会先确认用途，选当安装包用就自动清理这些文件；你也可以手动删掉它们，不影响使用 |
| 提示"这是开发副本" | 文件夹里有 `.git`，是 git 工作树 | 预期行为：更新入口不动 git 副本，同步上游用 `git pull` |
| 想彻底回到没装之前 | — | 双击 `3-一键恢复`，日志留不留当场选 |
| TUN / 增强模式下终端本来就通 | 流量被全局接管，检测不到本地端口就不写变量 | 正常现象，不用处理（显示通或不通都对） |
| 安装或自启动被杀软拦 | Run 键与用户目录脚本是启发式引擎的重点观察对象 | 双击 `1-安装` 会读回复检自启动有没有真的写上，装不上会直接告诉你；把安装目录加白名单（火绒先关"HTTPS 加密扫描"一类功能），不要关杀软 |
| 报「安装不完整，缺少程序文件：lib\xxx」 | 文件夹没完整拷过来，或里面的文件被删掉了（程序是「入口 + lib\ 里七个库」的结构，缺一个都起不来） | 到 Releases 页面重新下载安装包覆盖一次；也可以先双击一次 `1-安装` 试试 |

<details>
<summary>不常遇到的情况（点开看）</summary>

| 现象 | 原因 | 怎么办 |
|---|---|---|
| 安装时报一堆"意外的标记 ) / }" | 脚本编码被文本工具改坏了。PowerShell 5.1 在非 UTF-8 代码页的系统上会按 ANSI 读无 BOM 的脚本，中文乱码撑破语法结构 | 官方包里的 ps1 始终是 UTF-8 带 BOM；重新拷贝一份官方文件夹覆盖即可 |
| 把文件夹放到很偏的位置后不生效 | 定位器只在「用户目录 6 层 + 其他磁盘根 4 层」里找（例如 `C:\Tools`、`~/Projects`，或超过 4 层的深目录都在范围外） | 进 `win` 双击一次"安装" |
| 本地代理加了用户名密码 | 无认证的握手会被回 407，判成"不可用"是保守正确 | 关掉本地认证（默认就是关的），或换一个不需要认证的本地端口 |
| WSL2 里的终端不生效 | WSL2 默认不继承 Windows 的用户环境变量 | 预期行为，在 WSL 里另行设置代理变量 |
| 管理员终端（提权运行）不生效 | 提权进程属于另一个管理员身份，不继承你当前用户的变量 | 预期行为，用普通（非提权）终端 |
| 装了之后系统里原有的代理变量没了 | 安装先给同名变量拍快照再覆盖，卸载按快照还原（系统级变量和系统代理从来不碰） | 公司内网机也可放心装；只有安装后新加的值不在快照里 |
| Node 里访问绑在 `[::1]` 的服务没绕过代理 | Node 自带的 undici 解析不了裸 `::1`（会拆成 host `:` + 端口 `1`）；改成 `[::1]` 会让 httpx 全线报错，故保留裸写 | 只有"显式绑 `[::1]` 的服务 + Node 原生 fetch"会踩到，用 `localhost` / `127.0.0.1` 即可 |
| 设了 `NODE_USE_ENV_PROXY`，Node 还是不走代理 | 它只对新版 Node 生效 | `node:http(s)` 要 22.21 / 24.5 以上，`fetch()` 要 22.21 / 24.0 以上；低版本是预期行为 |

</details>

## 7. 性能与流量

| 项目 | 量级 |
|---|---|
| CPU | 平时看不出来。一轮探测只要毫秒级，开销主要是一个 PowerShell 进程本身的底座（Mac 上是 bash，没有这个量级） |
| 内存 | 几十 MB，同样是进程底座占的 |
| 外网流量 | 翻墙挂满 24 小时也就几 MB。真实探测每个端口 15 秒最多一次，只等响应头、不读正文，每次不到 1KB |
| 写文件 | 只在状态变化时写一次，稳定时日志一个字都不写 |

有一个口径要说清楚：**外网流量只在"本机有端口在应答代理握手"时产生**。翻墙软件完全退出（没有端口在听）才是零外网流量；"断开连接但内核还活着"不算零——那时端口还在应答，监控每 15 秒仍会探一次，而这正是它区分"断开"和"翻墙中"的唯一办法。

任务管理器里找命令行带 `envproxy.ps1` 的 powershell 进程，就能看到实际占用。

## 8. 文件夹里都有什么

解压之后就是这样（文件夹名字随便改）：

```
EnvProxy\
  win\                    Windows 版：5 个按钮 + 入口 + 程序库
    envproxy.ps1         入口：解析参数、挂操作锁、加载自检、分派
    lib\                 七个程序库：base / probe / env / runtime / package / update / ops
    monitor\              运行时自建：monitor.log（日志）、monitor.pid、stop.flag
  mac\                    Mac 版：同样 5 个按钮 + 入口 + 程序库
    envproxy.sh          入口（与 win\envproxy.ps1 对等）
    lib\                 七个程序库（与 Windows 同名同职责）
  README.md               中文说明（本文）
  README.en.md            英文说明
  LICENSE                 MIT 许可证
  VERSION                 版本号
  release-notes\          每一版改了什么（点"检查更新"时会直接显示）
  assets\readme\          README 的配图
```

`win\`、`mac\`、`release-notes\`、`assets\` 这四个目录是程序的地盘：更新会按包内清单对齐它们的内容，别放自己的文件。日常只用打开 `win\`（Mac 上是 `mac\`），顶层的文件不用管。

最外层和日志都不用担心：顶层只覆盖同名文件，绝不删你的东西；`monitor\` 里的日志与运行标记永不覆盖、永不删。

## 9. 关于复制备份文件夹

整个 `EnvProxy` 文件夹可以随便复制到别处当备份，无害：

- 自启动项、注册表记录、定位器只引用你装过的那一份，备份不会被引用；定位器按日志活跃度排序，备份永远不会被误选。
- 唯一的注意：**不要在备份文件夹里双击 `win\1-安装.cmd`**——那等于把备份切换成正式安装。
- 一台电脑只留一份安装。搬家先到旧位置点一次 `3-一键恢复`，再到新位置点 `1-安装`。程序本身有单实例锁和迁移保护，不会真的两个监控同时改同一组变量；这条规矩防的是旧位置的自启动项和路径记录被落在系统里，日后卸载容易漏。

## 10. 给朋友/新电脑部署

1. 把安装包弄到新电脑（二选一）：点 **[最新版下载](https://github.com/FiretrUCK666/envproxy/releases/latest/download/EnvProxy.zip)**；或者把已经解压好的整个文件夹拷过去（U 盘、网盘、压缩包都行）
2. 双击 `win\1-安装.cmd`（Mac 双击 `mac\1-安装.command`）
3. 完事

不需要装任何东西（Node、Python 都不需要），不需要管理员权限，Windows 10/11 自带 PowerShell 即可。

<details>
<summary>手动改过文件的话，编码要注意（点开看）</summary>

- `win\` 下的每个 `.ps1`（入口与 `lib\` 里的库）都是 **UTF-8 带 BOM**。这是为了让它在任何中文、英文系统的 Windows 上都能被 PowerShell 5.1 正确读取——没有 BOM 时，中文系统按 GBK 读、英文系统按 Latin1 读，都可能报语法错误。用编辑器改过它，保存时务必选"UTF-8 with BOM"，改完进 `win` 双击一次"安装"让监控加载新代码。
- 日志 `monitor\monitor.log` 相反，是 **UTF-8 无 BOM**，读写两端都显式指定 UTF-8，放哪种代码页的系统上都不会乱码（Windows 侧行尾 CRLF，Mac 侧 LF）。不要把日志也统一成带 BOM——文件开头会多出三个字节，被当成日志内容。
- 拷贝文件夹的时候，别用文本编辑器另存里面的 `.ps1` 文件，那会破坏 BOM。

</details>

## 11. 技术边界（4 条）

1. **纯 TUN 模式不注入**。TUN 已经把流量全局接管，终端本来就通，本工具检测不到本地代理端口，因此不写入变量——这是正确行为，不是 bug。Outline 这类系统级 VPN、纯 SOCKS 端口（没有 HTTP 口）同理。
2. **"断开连接"不等于退出软件**。多数翻墙软件的断开按钮不会停掉内核，端口还活着。本工具以流量真相为准：翻得出去就写入，翻不出去才删除。
3. **搬到搜索范围之外要手动接管一次**。定位器不会全盘乱翻，只在「用户目录（桌面、文稿、下载、OneDrive、.config，向下 6 层）+ 其他磁盘根（向下 4 层）」里按活跃度找新位置。搬到范围之外（例如 `C:\Tools`、`~/Projects`，或任意很深的目录），双击一次 `1-安装` 即可；其余情况全自动。
4. **此前手设过的用户级代理变量会被接管**。安装先给同名的用户级变量拍快照再覆盖，卸载时按快照还原；系统级变量和系统代理从不触碰。个人电脑极少遇到，公司内网机也可放心装。

## 12. macOS 版

> Windows 用户看到这里可以停了。Windows 文件在 `win\`，Mac 文件在 `mac\`，两套并排，整文件夹拷到 Mac 就能用。

### 12.1 与 Windows 版的一句话区别

Windows 把变量写进注册表、广播一次就全局生效；macOS 没有注册表，所以 Mac 版双路同时写：终端走 `~/.envproxy/proxy.env`（新开终端自动加载），Dock 启动的 App 走 `launchctl setenv`。两路同进同退。

Mac 版注入整套 9 个变量，比 Windows 多的是一份小写拼写——macOS 真大小写敏感，大小写各算一个变量，有的工具只认小写（原因见前面变量表下的大小写说明）。其余逻辑与 Windows 一致：2 秒、3 秒轮询，双轮确认，连续 3 次失败才判断，7 端点快路加并行兜底，15 秒节流，日志 200KB 上限，每 30 轮自启动自愈。`2-停止监控` 的语义也一样：停掉就是真的停掉，直到下次登录。

<img src="./assets/readme/mac-paths.svg" width="100%" alt="macOS 双路写入：终端经 shell hook 读 proxy.env，Dock 启动的 App 经 launchctl setenv 读同一批变量；两路同进同退">

### 12.2 安装（3 步）

1. 把整个 `EnvProxy` 文件夹拷到 Mac 上任意位置（U 盘、隔空投送、压缩包都行）
2. 进 `mac` 文件夹，双击 **`1-安装.command`**（首次可能要右键 → 打开放行一次，见 12.5）
3. 看到"监控进程已启动"就装好了。**新开一个终端**验证：`env | grep -i proxy`

装完是五件事：先给已有的同名变量拍快照（卸载时还原用）、注册开机自启（LaunchAgent）、写入终端集成（在 `~/.zshenv`、`~/.zshrc`，以及已存在的 `~/.bash_profile`、`~/.bashrc` 里插一段带标记的 hook，新终端据此加载 `proxy.env`）、立刻启动监控、当场校正一次变量。以后任何不对劲，进 `mac` 双击一次 `1-安装.command` 就是万能修复。

> fish 用户注意：fish 读不懂 `proxy.env` 的 export 写法，需要装 bass，然后在 `config.fish` 加一行 `bass source "$HOME/.envproxy/proxy.env"`。

### 12.3 五个按钮（与 Windows 同语义）

五个按钮都在 `mac` 文件夹里。

| 按钮 | 做了什么 |
|---|---|
| **1-安装.command** | 开机自启 + 启动监控 + 校正变量（万能修复） |
| **2-停止监控.command** | 停监控 + 删变量（保留自启动，下次登录回来） |
| **3-一键恢复.command** | 停监控 + 删变量 + 删自启动、定位器、hook，日志去留当场问 |
| **4-查看状态.command** | 显示监控、自启动、翻墙状态、变量、版本、最近日志 |
| **5-检查更新.command** | 查最新版，问过才装 |

终端用户也可以直接用命令（在项目根目录）：`bash mac/install.sh`、`bash mac/stop.sh`、`bash mac/uninstall.sh`（加 `--purge` 连日志一起删、不询问）、`bash mac/status.sh`、`bash mac/update.sh`（加 `--yes` 跳过确认）。`.command` 只是双击壳，逻辑全在 `.sh` 里。

### 12.4 `mac` 文件夹里都有什么

```
EnvProxy/
  mac/
    envproxy.sh          入口（对标 win\envproxy.ps1，只用系统自带命令）
    lib/                 七个程序库：base / probe / env / runtime / package / update / ops
    locator.sh           定位器模板（安装时复制到 ~/.envproxy/locator.sh）
    install.sh / stop.sh / uninstall.sh / status.sh / update.sh
    1-安装.command … 5-检查更新.command（双击入口）
    monitor/             运行时自建（monitor.log / monitor.pid / stop.flag；日志行格式与 Windows 一致）
```

`~/.envproxy/` 是固定位置，装好后里面有 `locator.sh`（定位器）、`path.conf`（路径记录）、`proxy.env`（终端那一路的变量）、`prev.env`（安装时拍的用户原值快照，卸载还原用）、以及 launchd 的两个输出重定向文件。项目文件夹随便搬家，下次登录自动重新定位；备份文件夹随便复制，不会被误选。卸载时这些一律清掉，只留你选择保留的黑匣子 `monitor.log`。

### 12.5 Mac 上首次安装可能遇到的三个拦路虎

1. **双击没反应，或提示"无法打开"**：Gatekeeper 拦的。按省事程度来：右键 → 打开放行一次；或去系统设置 → 隐私与安全性点"仍要打开"（这个按钮只在你尝试打开后 1 小时内出现）；或在终端里跑 `bash mac/install.sh`（永远有效）；还不行就先执行 `xattr -d com.apple.quarantine mac/1-安装.command` 再双击。不要用 `spctl --master-disable` 关整个 Gatekeeper——`.command` 只是没签名的脚本，签了解决不了问题，关了等于给恶意软件开门。
2. **`chmod` 权限丢了**（从 Windows 拷过来常见）：进 `mac` 目录跑一次 `chmod +x *.command *.sh`。
3. **首次登录弹出"终端想访问文稿、桌面"**：点"好"就行（定位器要搜索新位置）。点了"不允许"也不坏，手动双击一次安装就纠正了。

### 12.6 Mac 技术边界（Windows 的 3 条照搬，再加 2 条）

照搬：纯 TUN 不注入（正确行为）；"断开"不等于退出，以流量真相为准；搬到搜索范围外时双击一次安装兜底。

新增两条：

1. **旧终端要重开**：已经开着的窗口不变，只有新开的终端和 App 才生效（与 Windows 一致）。
2. **核心用 shell 写，不用 python**：Mac 自带的 `/usr/bin/python3` 是 Xcode 附带的旧版本，新系统上缺组件会直接报错。所以 Mac 版只用 `zsh`、`bash` 和系统自带命令（`curl`、`lsof`、`nc`、`netstat`、`ps`、`launchctl`、`awk`、`sed`、`tar`、`cmp` 等），不装任何东西。**改完 `mac` 下任何 `.sh`（入口与 `lib/` 里的库）都要保存为 LF、无 BOM**（与 Windows 的 UTF-8 带 BOM 相反，BOM 会顶掉 shebang 导致无法执行）。

### 12.7 给朋友/新 Mac 部署

整个文件夹拷过去 → 进 `mac` 双击 `1-安装.command` → 完事。不需要 Homebrew、Python、Node，不需要 `sudo`，macOS 12+ 默认的 `zsh` 就够。

想升级：进 `mac` 双击 `5-检查更新.command`，先问后装，日志保留。
