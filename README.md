## 一句话说明它是干什么的

翻墙软件能让浏览器翻墙，但 `git`、`npm`、`curl` 这类命令行工具不认它——它们只读环境变量。
EnvProxy 补的就是这个空缺：它盯着翻墙软件有没有真的在翻墙，翻着就把代理写进环境变量，不翻了就删掉。

| 你的场景 | 没有 EnvProxy | 装了 EnvProxy |
|---|---|---|
| 打开翻墙软件 | 浏览器通了，终端没通：命令行工具变慢、超时，只认环境变量的工具直接连不上 | 终端跟着翻墙 |
| 关掉翻墙软件 | 代理变量留在那里，终端报"连接被拒绝" | 变量自动删掉，终端恢复直连 |
| 换了端口、换了翻墙软件 | 手动抄端口、手动设变量，还得记得改回来 | 自动发现新端口并更新 |

### 它注入哪些变量

翻墙时整套写入，断开时整套删除，同进同退：

| 变量 | 写入值 | 作用 |
|---|---|---|
| `HTTP_PROXY` | `http://127.0.0.1:端口` | http:// 请求的代理 |
| `HTTPS_PROXY` | `http://127.0.0.1:端口` | https:// 请求的代理 |
| `ALL_PROXY` | `http://127.0.0.1:端口` | 兜底变量：具体变量没覆盖到的协议用它 |
| `NO_PROXY` | `localhost,127.0.0.1,::1` | 本机地址不走代理 |
| `NODE_USE_ENV_PROXY` | `1` | 让新版 Node 系工具（原生 fetch）也读环境变量代理 |

代理值统一用 `http://` 写法，不用 `socks5://`：本地代理端口两种协议都应答，而部分工具只认 `http://`，统一之后兼容面最大，行为没有损失。

Windows 写 5 个，macOS 写 9 个（同样 5 个，再加一份小写拼写）。这是平台差异，不是漏写：Windows 的变量名大小写不敏感，写小写只会互相覆盖；macOS 的大小写各算一个变量，有的工具只认小写。

<details>
<summary>这几条为什么这么定（不影响使用，点开看）</summary>

- 不用 `socks5://` 的原因：部分工具（例如 dsh）碰到 SOCKS 写法会警告并跳过，而本地混合端口本来就应答 HTTP。
- Windows 不写两种拼写的原因：两种拼写在那里是同一个变量，重复项会让 .NET 系宿主建表时直接报 `An item with the same key has already been added`，同一个终端窗口里跑的东西会一起受影响。
- `NO_PROXY` 里的 IPv6 要裸写 `::1`。写成 `[::1]` 会被 httpx 当成普通域名、生成非法匹配模式，之后每一次请求都报 `InvalidURL`；方括号是 URL 字面量的写法，放错了位置。
- 你自己的 `NO_PROXY` 条目不会被删，只做补齐；卸载时也只回收本工具写下的值。
- 变量被别的东西改坏（覆盖、清空、少一项）不用管：监控每 60–90 秒核对一遍整张表，不齐就补回来。
- 下表里的工具不读上面这 5 个变量，要另行配置（不是本工具的 bug）：

| 工具 | 该去哪里配 |
|---|---|
| Maven | `settings.xml` 的 `<proxies>` |
| Gradle | `gradle.properties` 的 `systemProp.http(s).proxyHost/Port` |
| JDK 原生 HttpClient | JVM 系统属性（或 `java.net.useSystemProxies` 走系统代理） |
| Docker Desktop 的 `docker pull` | Docker Desktop 自己的设置（它忽略 `daemon.json` 里的代理） |

- `NODE_USE_ENV_PROXY` 只对新版 Node 生效：`node:http(s)` 要 22.21 / 24.5 以上，`fetch()` 要 22.21 / 24.0 以上。低版本设了也没用，是预期行为。

</details>

## 1. 安装（3 步，5 分钟）

1. 点 **[这里下载 Windows 版安装包](https://github.com/FiretrUCK666/envproxy/releases/latest/download/EnvProxy-win.zip)**（Mac 版点 [`EnvProxy-mac.tar.gz`](https://github.com/FiretrUCK666/envproxy/releases/latest/download/EnvProxy-mac.tar.gz)）
2. 解压到任意位置，文件夹随便改名。进 `win` 双击 **`打开菜单.cmd`**（Mac 进 `mac` 双击 **`打开菜单.command`**），再选 **`1 安装 / 修复`**
3. 看到"监控进程：已启动"就装好了

装完它做了四件事：先给已有的同名变量拍快照（卸载时还原用）、注册开机自启动、立刻启动监控、当场校正一次环境变量。

<img src="./assets/readme/first-run.svg" width="100%" alt="安装三步：下载你平台的包 → 双击打开菜单选 1 安装 → 看到「监控进程：已启动」；下方并排对比：已经开着的窗口不变，新开的窗口立刻生效">

出任何毛病：打开菜单选 **`1 安装 / 修复`**。它是万能修复，不会重复安装、不会断网、不会丢东西。

> 网上下载的包第一次双击若被拦截：右键文件 → 属性 → 解除锁定（或跑一句 `Unblock-File`），不要去改执行策略。

## 1.5 更新

打开菜单选 **`5 检查更新`**：先告诉你最新版是什么、这一版改了什么，你同意才装。

- **不用为升级开翻墙软件**：多数网络本来就通。万一提示连不上，把翻墙软件开关一次再试。
- **装之前对校验值**：下载完先对一遍，对不上就不装——装坏了比不装更糟。
- **只动程序文件**：你的文件、日志、`monitor\` 里的运行标记都不碰；装完监控自动用新代码重启。
- **出错时说清原因**：连不上、被限流、对方故障、包有问题，各给各的下一步，不用自己猜。

<details>
<summary>不想用菜单，命令行怎么更新</summary>

Windows：`powershell -ExecutionPolicy Bypass -File win\envproxy.ps1 -Update`（加 `-Yes` 跳过确认）

Mac：`bash mac/envproxy.sh update`（加 `--yes` 跳过确认）

退出码：`0` 成功；`1` 失败（原因在提示里）；`2` 参数写错。

</details>

> 安装包装的就地升级；`git clone` 拿到的开发副本不会被覆盖，同步上游用 `git pull`（见第 13 节）。

选"一键恢复"时会停下来问你一句日志留不留：回车 = 保留，输入 `N` 再回车 = 连日志一起删。

## 2.5 日志（monitor.log）

`win\monitor\monitor.log`（Mac 在 `mac\monitor\`）只记状态变化：什么时候注入、什么时候删除、监控启动与退出、开机自启自愈、出了什么错。稳定运行的时候它一个字都不写，体积上限 200KB，超过就自动截断成最近 200 行，用几年也不会越来越大。

它是排查问题的黑匣子。反馈问题时把最近的相关几行一起带上，大多数情况看一眼就定位了。

## 3. 日常使用（装完后什么都不用做）

| 你做什么 | 它会做什么 | 多久 |
|---|---|---|
| 打开翻墙软件、连上 | 检测到在翻墙 → 写入变量 | 4–10 秒（软件和端口都不在常见表里的，最长约 30 秒） |
| 断开或退出翻墙软件 | 检测到没翻墙 → 删除变量 | 退出约 5 秒；只是断开约 15–50 秒（多数时候二十来秒） |
| 改端口后重连 | 发现新端口，更新成新值 | 约 10 秒 |
| 断开后又连回来 | 发现节点回来了 → 恢复变量 | 约 10–25 秒（要等下一轮探测确认，再两轮去抖） |

<details>
<summary>其他情况（也都不用管，点开看）</summary>

| 你做什么 | 它会做什么 |
|---|---|
| 换一个翻墙软件 | 发现新软件的端口，几秒 |
| 同时开两个翻墙软件 | 只用验活的那个，前一个断了自动让位 |
| 反复快速连接、断开 | 抖动被吸收，变量纹丝不动 |
| 重启电脑 | 开机立即校正残留变量 |
| 把整个文件夹搬到别处 | 旧监控自己退出，下次启动从新位置拉起（搜索范围见第 11 节第 3 条） |

</details>

## 4. 它是怎么判断"在不在翻墙"的

<p align="center">
  <img src="./assets/readme/mechanism.svg" width="100%" alt="三层验证流程图：每 2–3 秒轮询一次，依次检查本机端口是否在监听、该端口是否真的能转发请求、通过它访问外网是否真的可达。三层都通过就写入整套代理变量；任何一层不通过就删除整套变量、恢复直连。">
</p>

每 2–3 秒检查一次本机有没有端口在监听，有就再往下验两层：它像不像一个真能用的代理，通过它访问外网是不是真的通。
三层全过才算在翻墙，才写入变量；任何一层不过就当没在翻墙，删掉变量恢复直连——"断开连接但软件内核还活着"就落在这一支。

它不认品牌、不认进程名、不认端口号，只认谁真的在提供代理服务。所以 Clash、v2rayN、Shadowsocks、Hiddify、sing-box、NekoBox、Surge 这些都能用，换软件、改端口都不用动配置。

## 5. 为什么它不容易出错

| 机制 | 作用 |
|---|---|
| 双轮确认 | 状态连续确认两轮才动手——几秒内反复连断，变量不会乱写 |
| 判断"断"很保守 | 要同时满足两条才算断开：连续失败满 10 秒、且至少 3 次探不到；只要能通一次就立刻不再算断。判"断"要删变量、通知全系统，代价比多等一会儿大得多 |
| 多个外部站点一起判断 | 用 7 个不同的站点一起判断，平时只问上次成功的那个，它不通才换别的——某个站点抽风不会让你被误删变量 |
| 探测省流量 | 一切正常时每个端口 15 秒最多探一次，一次不到 1KB；发现不对劲才缩短到 5 秒一次——查清之后还会多盯 1 分钟，确认不是一时抽风 |
| 只有一个监控进程 | 单实例锁，不会越积越多 |
| 本机开发服务器不当代理 | 端口在监听还不够，得真的能转发请求才算——8080、8888 上的本机服务不会被误判 |

<details>
<summary>其余保护措施（不影响使用，点开看）</summary>

| 机制 | 作用 |
|---|---|
| 开机对齐 | 开机立即校正变量，关机时残留的死端口瞬间清掉 |
| 安装先快照 | 覆盖同名变量前先记下原值，卸载时按快照还原——只回收自己写下的，不动别人的 |
| 监控自退 | 文件夹被移动或删除，监控 2–3 秒内发现并自动退出，先清掉已注入的变量再清旧位置 |
| 定位器兜底清理 | 移动后立刻关机（监控来不及自退），下次开机由定位器顺手清掉旧位置残留；新位置找不到时也清掉残留变量，新终端不再读到过期代理 |
| 活跃度优先定位 | 先把所有搜索根的结果汇总，再按日志活跃度排序——复制的备份文件夹永远不会被误选 |
| 跨位置优雅停止 | 停旧位置的监控时，把信号写到它自己的目录，优雅退出而不是强杀 |
| 自启动自愈 | 每 30 轮（约 60–90 秒）自查一次，开机自启被清掉或过时了会自己装回去 |
| 集合试活 | 候选端口排队逐个验活，上次验活的优先认回；双开时前死后活自动让位 |

</details>

## 6. 故障排查

| 现象 | 原因 | 怎么办 |
|---|---|---|
| 装好后终端还是不能翻墙 | 终端是装之前开的，而且还没敲过命令 | 在旧窗口里**敲一下回车**就会跟上；仍不通就新开一个窗口 |
| 只想让某些窗口翻墙，别的不用 | 默认是"全自动跟随" | 在不想跟随的窗口里执行 `export ENVPROXY_TERM=off`（恢复自动：`unset ENVPROXY_TERM`）。逐窗口生效，不影响别的窗口 |
| 某个窗口想用别的代理 | 你自己设的值我们永远不动 | 直接 `export HTTPS_PROXY=http://你的地址:端口`。判据是"值是否等于我们写下的那个"，你自己写的不算我们的 |
| 断开后变量迟迟不删 | 软件"断开"没真断（内核还活着），节点也还通 | 正常现象。想立刻停就退出翻墙软件 |
| 变量删了又恢复 | 节点本身在抖，监控如实反映 | 正常现象。持续这样说明节点质量差，换一个 |
| 报 `An item with the same key has already been added`，或变量读不全 | 会话里留着同名两种拼写的变量（`HTTP_PROXY` 和 `http_proxy`） | 把那个终端、以及从它启动的程序全部关掉重开。注册表本身是干净的，不必注销 |
| 明明连着翻墙软件，却显示变量已删除 | 用来判断的外网站点暂时连不上 | 它会换别的站点再试，单个站点抽风不该触发。仍然出现就打开菜单选一次"安装 / 修复" |
| 日志里出现"检测异常" | 单轮检测出错，不影响整体 | 不用管，会自己恢复；持续出现就打开菜单选一次"安装 / 修复" |

## 7. 性能与流量

| 项目 | 量级 |
|---|---|
| CPU | 平时看不出来。一轮探测只要毫秒级，开销主要是一个 PowerShell 进程本身的底座（Mac 上是 bash，没有这个量级） |
| 内存 | 几十 MB，同样是进程底座占的 |
| 外网流量 | 翻墙挂满 24 小时也就几 MB。一切正常时每个端口 15 秒最多探一次，一次不到 1KB |
| 写文件 | 只在状态变化时写一次，稳定时日志一个字都不写 |

一句话口径：**外网流量只在"本机还有程序在应答代理请求"时产生**。翻墙软件完全退出才是零流量；"断开连接但内核还活着"不算零——那时端口还在应答，平时每 15 秒探一次，而这正是它区分"断开"和"翻墙中"的唯一办法。发现不对劲时会缩短到 5 秒一次，直到把结论下出来，查清之后再多盯 1 分钟——这段最多几分钟，一次故障多探几次、不到几 KB，不影响上面的总量级。

任务管理器里找命令行带 `envproxy.ps1` 的 powershell 进程，就能看到实际占用。

## 8. 文件夹里都有什么

解压之后大体是这样（文件夹名字随便改；分包里没有另一平台的目录——Windows 包没有 `mac\`，反之亦然）：

```
EnvProxy\
  win\                    Windows 版：打开菜单 + 入口 + 程序库
    打开菜单.cmd         唯一双击入口：菜单（安装/状态/停止/恢复/更新）
    envproxy.ps1         入口：解析参数、挂操作锁、加载自检、分派
    lib\                 七个程序库：base / probe / env / runtime / package / update / ops
    monitor\              运行时自建：monitor.log（日志）、monitor.pid、stop.flag
  mac\                    Mac 版：同样一个菜单 + 入口 + 程序库
    打开菜单.command     唯一双击入口：菜单（同 Windows）
    envproxy.sh          入口（与 win\envproxy.ps1 对等）
    locator.sh           定位器模板（安装时复制到 ~/.envproxy/locator.sh）
    lib\                 七个程序库（与 Windows 同名同职责）
    monitor\             运行时自建（同 Windows，日志行格式一致）
  README.md               中文说明（本文）
  README.en.md            英文说明
  LICENSE                 MIT 许可证
  VERSION                 版本号
  release-notes\          每一版改了什么（点"检查更新"时会直接显示）
  assets\readme\          README 的配图
```

- **两个包各管一半**：`EnvProxy-win.zip` 装 Windows（`win\` + 共享文件），`EnvProxy-mac.tar.gz` 装 Mac（`mac\` + 共享文件）。各下各的，另一平台的目录互不干扰。
- **程序的地盘**：`win\`、`mac\`、`release-notes\`、`assets\` 归更新管，按包内清单对齐。日常只用打开 `win\`（Mac 上是 `mac\`）。
- **你的东西**：顶层只覆盖同名文件，绝不删；`monitor\` 里的日志与运行标记永不覆盖、永不删。

## 9. 关于复制备份文件夹

| 你想做什么 | 结论 |
|---|---|
| 复制整个文件夹当备份 | 随便复制，无害。自启动项、注册表记录、定位器只引用你装过的那一份；定位器按日志活跃度排序，备份永远不会被误选 |
| 在备份里打开菜单选安装 | **别这么做**——那等于把备份切换成正式安装 |
| 删掉整个文件夹 | 先打开菜单选一次"一键恢复"，否则开机自启动项和定位器会留在系统里。它们不占资源、也不留死代理（定位器每次开机还顺手清变量），下次重装即归位 |
| 搬家，或想在一台电脑上放两份 | 一台电脑只留一份。搬家先去旧位置"一键恢复"，再到新位置"安装 / 修复"。程序有单实例锁和迁移保护，不会两个监控同时改同一组变量；这条规矩防的是旧位置的自启动项和路径记录被落下 |

<details>
<summary>手动改过文件的话，编码要注意（点开看）</summary>

- `win\` 下的每个 `.ps1`（入口与 `lib\` 里的库）都是 **UTF-8 带 BOM**。这是为了让它在任何中文、英文系统的 Windows 上都能被 PowerShell 5.1 正确读取——没有 BOM 时，中文系统按 GBK 读、英文系统按 Latin1 读，都可能报语法错误。用编辑器改过它，保存时务必选"UTF-8 with BOM"，改完进 `win` 双击一次"安装"让监控加载新代码。
- 日志 `monitor\monitor.log` 相反，是 **UTF-8 无 BOM**，读写两端都显式指定 UTF-8，放哪种代码页的系统上都不会乱码（Windows 侧行尾 CRLF，Mac 侧 LF）。不要把日志也统一成带 BOM——文件开头会多出三个字节，被当成日志内容。
- 拷贝文件夹的时候，别用文本编辑器另存里面的 `.ps1` 文件，那会破坏 BOM。

</details>

## 11. 技术边界（5 条）

| 边界 | 为什么会这样 | 你需要做什么 |
|---|---|---|
| **纯 TUN 模式不注入** | TUN 已经把流量全局接管，终端本来就通，检测不到本地代理端口 | 不用管，这是正确行为不是 bug。Outline 这类系统级 VPN、纯 SOCKS 端口（没有 HTTP 口）同理 |
| **"断开连接"不等于退出软件** | 多数翻墙软件的断开按钮不会停掉内核，端口还活着 | 不用管。本工具以流量真相为准：翻得出去就写入，翻不出去才删除 |
| **搬到搜索范围之外要手动接管一次** | 定位器不会全盘乱翻，只在「用户目录（桌面、文稿、下载、OneDrive、.config，向下 6 层）+ 其他磁盘根（向下 4 层）」里按活跃度找 | 搬到范围之外（如 `C:\Tools`、`~/Projects`，或任意很深的目录）就打开菜单选一次"安装 / 修复"；其余情况全自动 |
| **此前手设的用户级代理变量会被接管** | 安装先给同名变量拍快照再覆盖，卸载按快照还原；系统级变量和系统代理从不触碰 | 不用管；个人电脑极少遇到，公司内网机也可放心装 |
| **安全软件可能拦脚本**（Windows） | 它的行为看着像"可疑软件"：写用户级环境变量、往注册表加开机启动、在用户目录放脚本 | 遇到拦了就按安全软件的提示允许 / 加白名单，或先把本工具装到它信任的位置。别为它关掉防护 |

<img src="./assets/readme/limits.svg" width="100%" alt="五条技术边界：纯 TUN 不注入、断开不等于退出、范围外手动接管、手设变量快照还原、安全软件可能拦脚本">

## 12. macOS 版

> Windows 用户看到这里可以停了。两边各有各的安装包：Mac 用户直接下载 Mac 包；以前的老文件夹里有 `mac\` 也能照常用。

### 12.1 与 Windows 版的一句话区别

Windows 把变量写进注册表、广播一次就全局生效；macOS 没有注册表，所以 Mac 版双路同时写：终端走 `~/.envproxy/proxy.env`（新开终端自动加载），Dock 启动的 App 走 `launchctl setenv`。两路同进同退。

Mac 版注入整套 9 个变量，比 Windows 多的是一份小写拼写——macOS 真大小写敏感，大小写各算一个变量，有的工具只认小写（原因见前面变量表下的大小写说明）。其余逻辑与 Windows 完全一致：什么时候切换、等多久才下结论、日志上限、自启自愈，都是同一套。"停止监控"的语义也一样：停掉就是真的停掉，直到下次登录。

<img src="./assets/readme/mac-paths.svg" width="100%" alt="macOS 双路写入：终端经 shell hook 读 proxy.env，Dock 启动的 App 经 launchctl setenv 读同一批变量；两路同进同退">

### 12.2 安装（3 步）

1. 把 Mac 包（`EnvProxy-mac.tar.gz`）弄到 Mac 上任意位置（或把含 `mac\` 的整个文件夹拷过去：U 盘、隔空投送、压缩包都行）
2. 进 `mac` 文件夹，双击 **`打开菜单.command`**，再选 **`1 安装 / 修复`**（首次可能要右键 → 打开放行一次，见 12.5）
3. 看到"监控进程：已启动"就装好了。**在任意终端敲一下回车**验证：`env | grep -i proxy`（已经开着的窗口也管用，不必重开）

装完是五件事：先给已有的同名变量拍快照（卸载时还原用）、注册开机自启（LaunchAgent）、写入终端集成（在 `~/.zshenv`、`~/.zshrc`，以及已存在的 `~/.bash_profile`、`~/.bashrc` 里插一段带标记的 hook；`~/.envproxy/prompt-sync.sh` 负责让每次回到提示符都重读一遍，所以已开窗口也能跟上）、立刻启动监控、当场校正一次变量。以后任何不对劲，打开菜单选"安装 / 修复"就是万能修复。

> fish 用户注意：fish 不认 `export` 写法，原生支持还没有。将就的办法是装 bass，然后在 `config.fish` 加一行 `bass source "$HOME/.envproxy/proxy.env"`（每次新开窗口重新读一遍文件，端口变了也跟得上）。

### 12.3 菜单（与 Windows 同语义）

`mac` 文件夹里只有一个双击入口，菜单和 Windows 的一模一样（[见第 2 节](#2-打开菜单)，动作也相同），点开看对照表：

<details>
<summary>菜单对照表（点开看）</summary>

| 菜单编号 | 做了什么 |
|---|---|
| **1 安装 / 修复** | 开机自启 + 启动监控 + 校正变量（万能修复） |
| **2 查看状态** | 显示监控、自启动、翻墙状态、变量、版本、最近日志 |

### 12.4 `mac` 文件夹里都有什么

```

    monitor/             运行时自建（monitor.log / monitor.pid / stop.flag；日志行格式与 Windows 一致）
```

`~/.envproxy/` 是固定位置，装好后里面有 `locator.sh`（定位器）、`path.conf`（路径记录）、`proxy.env`（终端那一路的变量）、`prev.env`（安装时拍的用户原值快照，卸载还原用）、以及 launchd 的两个输出重定向文件。项目文件夹随便搬家，下次登录自动重新定位；备份文件夹随便复制，不会被误选。卸载时这些一律清掉，只留你选择保留的黑匣子 `monitor.log`。

### 12.5 Mac 上首次安装可能遇到的三个拦路虎

1. **双击没反应，或提示"无法打开"**：Gatekeeper 拦的，按省事程度依次试：
   - 先双击一次让它弹警告，再去 系统设置 → 隐私与安全性 点"仍要打开"（按钮要等尝试过才出现；新系统上右键打开已不再给放行选项）
   - 或在项目根目录跑 `bash mac/envproxy.sh install`（永远有效）
   - 还不行就在项目根目录跑 `xattr -d com.apple.quarantine mac/打开菜单.command`，再双击
   - **不要**用 `spctl --master-disable` 关掉整个 Gatekeeper：`.command` 只是没签名的脚本，签了也解决不了，关了等于给恶意软件开门
2. **`chmod` 权限丢了**（从 Windows 拷过来常见）：进 `mac` 目录跑一次 `chmod +x *.command *.sh`。
3. **首次登录弹出"终端想访问文稿、桌面"**：点"好"就行（定位器要搜索新位置）。点了"不允许"也不坏，手动双击一次安装就纠正了。

### 12.6 Mac 技术边界（Windows 的前 4 条照搬，第 5 条换形态，再加 2 条独有）

照搬：纯 TUN 不注入（正确行为）；"断开"不等于退出，以流量真相为准；搬到搜索范围外时双击一次安装兜底；此前手设的变量先快照、卸载按快照还原。

第 5 条换形态：Windows 上会拦的是安全软件（杀毒、EDR），Mac 上对应的是 Gatekeeper——首次运行 `.command` 可能提示"无法验证开发者"，右键"打开"一次即可，详见 12.5。

新增两条独有：

1. **终端提示符钩子**：Mac 用 `precmd`（zsh）/ `PROMPT_COMMAND`（bash），在每次回到提示符前重读一遍 `~/.envproxy/proxy.env`，所以**已经开着的窗口敲一下回车就会跟上代理状态**。这一读只用 shell 内建（不启动任何外部进程、约 0.3 毫秒），因为 `launchctl getenv` 每调用一次要起一个进程、8 个变量加起来够让人感觉到每次回车都卡。
2. **核心用 shell 写，不用 python**：Mac 自带的 `/usr/bin/python3` 是 Xcode 附带的旧版本，新系统上缺组件会直接报错。所以 Mac 版只用 `zsh`、`bash` 和系统自带命令（`curl`、`lsof`、`nc`、`netstat`、`ps`、`launchctl`、`awk`、`sed`、`tar`、`cmp` 等），不装任何东西。**改完 `mac` 下任何 `.sh`（入口与 `lib/` 里的库）都要保存为 LF、无 BOM**（与 Windows 的 UTF-8 带 BOM 相反，BOM 会顶掉 shebang 导致无法执行）。

### 12.7 给朋友/新 Mac 部署

整个文件夹拷过去 → 进 `mac` 双击 `打开菜单.command`，选 `1 安装 / 修复` → 完事。不需要 Homebrew、Python、Node，不需要 `sudo`，macOS 12+ 默认的 `zsh` 就够。（只要 Mac 版：下 [`EnvProxy-mac.tar.gz`](https://github.com/FiretrUCK666/envproxy/releases/latest/download/EnvProxy-mac.tar.gz)。）

想升级：打开菜单选 `5 检查更新`，先问后装，日志保留。
